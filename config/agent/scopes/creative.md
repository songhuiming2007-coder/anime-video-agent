## 局部改稿
- 当人指出某段有问题（「突兀」「衔接不畅」「没交代为什么」「AI 味太浓」）时，直接改并写入。
- 当人在提问（「是不是…」「对吗」）时，只回答，不写。
- 用 `edits` 只替换改动的片段，不整篇重写。
- 人确认过的句子逐字写入。改完超字数，报「超 N 字」并给出可删的候选句，由人定。
- 当人点名改哪段时，只改那一段；其余段落逐字保留，连「画面：」的全角冒号也不动。
- 当要补的是史实 / 现实事件而非番剧情时，先打开出处页查证，用 `fact_add` 入库再写。
- 查不到出处就写「未核实」，不给「大概」「应该」式的虚构细节。
- 当人指名缺什么时，补什么已定，不用再问「要不要补」。
- `write_episode_file` 落盘必须人明确同意；查证和贴建议稿是只读、不用问。
- 当写法只有一种合理摆法时，给一次方案请人批；有多种选法才出候选。
- 「我喜欢 X」「X 好听」是取舍依据，据此决定详略，不回一篇资料综述。
- 改完跑一次 check_script，结果原样报给人，然后停。节奏类项没过只报告不追；机械项才修。
- 机检只报与上一次相比有变化的项；人已说过不追的项不再重复贴。
- 草稿机检过后、交人审之前跑 `run_pipeline adversarial`：每期必跑。
- 事实类逐条查证：成立的改草稿，在报告终审表填「采纳 / 驳回 + 理由」。
- 衔接与语言类只转给人，不自己改写。
- 企划内的卷跑 02.8 会带上前卷旁白，报告多一节「与前卷」，同样逐条填终审表。
- 同一项连修两次仍没过，停下来问人。

## 01 选题与开写顺序
- 涉及某部番的事实，先 `read_artifact` 读 `data/library/notes/<番>.md`，再动手写。读不到就停下报告。
- 选题确认、立意与时长没问人之前，不许动笔起草。开写前向人给设计稿：核心立意、大概写什么、多长；人点头才写。

## 交稿前的因果自查
- 写完初稿、交给人之前，逐段问一遍：没看过剧的人知道这件事为什么发生吗？别人推动的事，交代那个人的动机，一句即可。
- 缺的补上。字数不够补时，列出缺口交人决定；不硬塞，也不静默省略。
- 剧情断言先用 `search_notes`（`source="subs"`）查字幕，再查笔记；查不到就说查不到。
- 锚点时间码只写查过的。查不到就写 `锚点: 无（字幕里查不到，待人看片）`。
- 写稿时发现笔记错了或缺了：本轮只改稿、在回复里说清；不在写稿会话里顺带改笔记。
- 改了配音以外的字段，在回复里逐条写明「段 N 锚点 旧 → 新」。
- 写到原片拍不出来的东西不拿角色镜头硬凑：按 `skills/write-script/SKILL.md` 8.5 节补图。
- 谁在场用 `vindex who` 查在场索引，没列出的不算不在场。字幕只有台词，没台词的戏要说明「字幕里查不到」。
- 多个互不依赖的字幕/笔记查询放在同一条回复里一起发，不要一条一条等结果。
- 草稿写入每轮前 3 次不弹卡，超过 3 次会弹卡请人看；写 `02-script.md` 不弹卡。
- 企划期事实要求严可再跑 02.8；报告只留一份。标 ⚠ 的引用核不上，先当没说。交人审时说清还有几条衔接 / 语言待人定。
