# ADR-0023：跨期记忆层与模型按用途分层

日期：2026-09-22
状态：**已通过**
前置：ADR-0018, ADR-0019, ADR-0020
依据：Hermes MEMORY.md / USER.md 双文件模式调研（2026-09-22）、Hermes `delegation.model` 分层配置模式

## 背景

ava 的经验沉淀目前只有两条通道：AGENTS.md 的手工增补（人写，低频）与 `03-audio/corrections.json`（TTS 专用，ADR-0019）。但 20 期生产积累的跨期模式——「这类查询写法命中率高」「某番检索阈值系统性偏低」「某类题材 BGM 搭配被驳回率高」——散落在各期目录与用户脑中，agent 每期从零开始。人时预算的一部分被反复消耗在「重新教会 agent 已经踩过的坑」上。

同时 `pipeline/agent/llm.py` 是单模型配置：写稿、状态问答、机检辅助全部走同一模型。三者对推理强度的需求差一个量级，统一用强模型是浪费，统一用弱模型是事故。

Hermes 给出现成范式：MEMORY.md / USER.md 平面文件记忆（条目制、字符预算、原子写、注入扫描），与 `delegation.model` 按用途钉模型的分层配置。

## 决策

### 1. 跨期记忆层：`data/library/memory.md`

- **物理形态**：单文件，不进 git（属 `data/` 层资产），条目制（`\n§\n` 分隔），字符预算（暂定 4000 字符，超限必须合并旧条目腾位——防无限膨胀稀释信噪比），写入走 `paths.atomic_write`。
- **写入纪律（沿用判据 7 与 ADR-0019 精神）**：
  - 「可能」不许进记忆；每条必须带证据期号（`证据: 罪恶王冠第3期、春物第2期`）；
  - agent 可提议条目，**首次写入必须经人确认**（与写 01-topic.md 同级）；确认过的条目后续由 agent 自维护（更新、合并、删除过时条目均落盘可审计）；
  - 条目写「模式 + 证据 + 适用边界」，不写流水账——「这个番的检索阈值 0.42 比默认 0.45 命中率高（证据…），仅适用于该番字幕池」是可用的；「第 N 期做得不顺」是垃圾。
- **读取**：经 ADR-0022 的装配器进工序层——进 asset/creative scope 时注入全文（预算 4000 字符就是为此设的顶）。
- **数据源**：ADR-0020 的人审反馈结构化（rejected feedback）是记忆的天然原料；定期（换番或每 10 期）聚合「驳回模式」提议进 memory.md，聚合动作本身也走首次确认。

### 2. 记忆与既有沉淀层的关系（不越位）

| 层 | 记什么 | 谁写 |
|---|---|---|
| AGENTS.md / STANDARD.md | 红线、判据（违反即系统缺陷） | 人，走 ADR |
| `config/` | 机制参数（阈值、曲目、角色） | 人批准的配置变更 |
| `corrections.json` | TTS 读音纠错（ADR-0019 已立） | agent 提议 + 人审 |
| **memory.md** | 跨期**经验模式**（不构成红线，不达到配置强度的观察） | agent 提议 + 首次人确认 |

判据：够得上红线/判据强度的进 AGENTS.md 走 ADR；够得上参数强度的进 config；都不构但有复用价值的才进 memory.md。**memory.md 不是绕过 ADR 的后门**——任何条目升级为规则时必须从 memory.md 删除并走正式通道。

### 3. 模型按用途分层

`config/agent.json` 增加 `models` 段，按用途钉模型，缺省回落到现有单一 `model` 字段（向后兼容，未配置时行为不变）：

| 用途 | 建议档位 | 调用点 |
|---|---|---|
| `reasoning` | 强模型 | 02 写稿、01 选题、对抗审查 |
| `light` | 便宜模型 | 状态解释、REPL 问答、「我卡在哪」 |
| 机检辅助 | 便宜模型 | check_script 语义判断等 |

`llm.py` 的调用点按用途选档，一行配置的事；模型名进 config 不进代码（可复用性总纲）。

## 不做的事

- 不引入向量记忆/embedding 检索（规模不配，4000 字符预算内全文注入足够）；
- 不做自动记忆写入（无首次确认的自动沉淀是污染通道）；
- 不给 memory.md 建工具化 CRUD 面——一个受控写入工具（同 `write_episode_file` 纪律：白名单、双端 resolve、atomic_write）够用；
- 模型分层不做自动路由（LLM 判用途再选模型是套娃，调用点写死用途）。

## 推翻条件

- 若 memory.md 在真实生产中证明信噪比失控（条目陈旧、证据期号无法复核、agent 引用过时经验出错 ≥2 期），则废除 agent 自维护权，改回纯人工维护，只保留注入机制。
- 若模型分层实测收益不可观测（成本/延迟变化在噪声内），允许回退单模型——分层配置保留但不设第二档。

## 补记（2026-09-23，Spec 7 红队裁决 + 人批准）

依据：`docs/dev/plans/2026-09-23-memory-and-model-tiering-spec.md` 两轮红队审查（一轮 🟡-11 程序性登记、二轮第四节倾向），经人批准写入。两条都是对本 ADR §1 的澄清或扩展，不推翻决策本体。

1. **「自维护」的范围**：§1「确认过的条目后续由 agent 自维护（更新、合并、删除）」中的「自维护」，只包括不产生新文本的维护，即追加证据期、刷新引证日期。改写与合并写入的是从未经人确认的新文本，属于「首次写入必须经人确认」的适用范围，一律经人审卡。删除目前也经人审卡，等「过时」有了确定性定义后，再评估是否放宽。
2. **注入范围扩到 idea scope**：§1「读取：进 asset/creative scope 时注入全文」扩为 **asset / creative / idea**。理由有四：
   - idea 会话的历史独立，不与制片会话共用；
   - idea 零写权限（机制保证），写入工具仍只挂在 creative；
   - 注入的是已校验、来源已确认的全文；
   - 选题恰恰是最用得上驳回模式经验的环节（如「这类选题被驳回率高」）。

   pipeline scope 仍不单独注入：自动 REPL 在整期中共用一份历史，01/02 阶段注入的记忆在之后的回合里仍然可见。上位需求文档（direction §2 Spec 7）写的「asset/creative」以本补记为准。
