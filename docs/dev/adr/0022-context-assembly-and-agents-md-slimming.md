# ADR-0022：上下文按需装配，AGENTS.md 瘦身

日期：2026-09-22
状态：**已通过**
前置：ADR-0018, ADR-0021
依据：Hermes skills 渐进披露调研（2026-09-22）、Manus「Manipulate Attention Through Recitation」与 lost-in-the-middle 结论（官方博客，2025-07）

## 背景

AGENTS.md 已膨胀至数百行，每次会话全文载入。其中大部分内容（版权约定、清理约定、BGM 约定、跨番 SP 素材协议、ADR 历史判据）与当期工序无关，却与硬约束（Code Freeze、诚实失败、SSOT、停机点纪律）争夺同一份注意力预算。代价是双向的：

1. **token 成本**：输入输出比 ~100:1 的 agent 场景（Manus 实测），每轮工具循环都在为无关规则付费。
2. **注意力稀释**：Manus 官方结论——长上下文中的模型会 lost-in-the-middle、偏离目标。规则越多，红线的信噪比越低。AGENTS.md 自己也承认「长文件没人读得完，会失权威」——这个判据同样适用于 agent。

Hermes 给出现成范式：系统提示只放工具索引（名字 + 一句话描述），需要时经工具按需加载全文，token 成本与使用频率成正比。ava 的文档地图（AGENTS.md 顶部表格）本来就是索引形态，缺的只是 harness 层的装配机制。

## 决策

### 1. 系统提示三层结构

| 层 | 内容 | 装配时机 |
|---|---|---|
| **常驻层** | 定位一段话、硬约束（Code Freeze、诚实失败、SSOT、停机点纪律、人时预算原则）、文档地图索引 | 每会话必有 |
| **工序层** | 由 scope 与工序路由：`skills/write-script`（02）、runbook 对应篇（各工序）、`config/scenes.json` 阈值（04）、BGM 约定（08）等 | harness 按 `pipeline.status` 推导的当前工序自动注入 |
| **按需层** | 番剧笔记、ADR、postmortems、STANDARD 细则 | 不注入；agent 经 `read_file` 自取，文档地图里有指路 |

### 2. AGENTS.md 瘦身

- AGENTS.md 只保留：定位、硬约束、判据（判据是本项目灵魂，不瘦身）、失败处理原则、工程约定要点、九步表、文档地图。
- 移出的内容（BGM 约定细则、清理约定细则、跨番 SP 协议细则、内容参数表、云端清理表）迁入对应工序文档（`docs/runbook/` 对应篇或 `docs/dev/` 专题），**内容一字不改，只搬家**——判据的执行位置变化不构成判据本身的修改。
- 瘦身后的 AGENTS.md 目标 ≤150 行；超限视为缺陷（与 WORKFLOW.md ≤100 行同一条纪律的逻辑：文档失权威从读不完开始）。

### 3. 装配机制

- `pipeline/agent/` 新增上下文装配器：输入 = scope + `inspect_episode()` 的当前工序，输出 = 工序层文档清单；装配是**纯函数、可测试**（同 scout.py 的依赖纯洁性纪律：顶层零重依赖）。
- 工序层注入在**进入该工序时一次完成**，会话中途工序切换时追加注入新工序文档——**系统提示会话内只增不改**（遵守 ADR-0020 第 5 节的 append-only 与 KV-cache 纪律：不改写已注入内容，只追加）。
- 路由表（工序 → 文档清单）是 `config/agent.json` 附近的配置，不是硬编码——换番、加工序不动代码（可复用性总纲）。

### 4. 不变量

- **判据不进按需层**。判据（AGENTS.md 三节十三条）是每次会话的完整注意力对象，精简判据文本可以，拆散到按需加载不行。
- 文档地图索引必须始终完整——「nothing is ever hidden」（Hermes 原则）：agent 必须随时知道哪份文档存在、在哪，只是不预付内容。
- 本 ADR 只动系统提示装配与文档物理位置，不动任何判据、阈值、流程的语义。

## 不做的事

- 不做 skill 市场/插件化加载——装配清单是仓库内配置，不开放运行时注册。
- 不做文档内容的摘要化/压缩注入（LLM 摘要会失真，判据类文本禁摘要）；要么全文注入，要么指路。
- 不动 `02-script.md` SSOT 与期产物的任何加载逻辑。

## 推翻条件

- 若工序层装配在真实生产中出现「该注入的没注入」导致 agent 违反已移出 AGENTS.md 的规则（如 BGM 纪律），且发生 ≥2 期，则将该规则提回常驻层，并重新评估路由表的完备性——装配错误是 harness 缺陷，不是 agent 缺陷。
