# ADR-0032：工具表取消硬封顶，改为软约束

日期：2026-10-15
状态：**已通过**（2026-10-15 人裁决：「工具表不应该一直设置硬上限，有一个软约束就行」）
取代：ADR-0021「不做的事」中的数量封顶、ADR-0025 决策 1 与「不做的事」第一条、ADR-0029 决策 1、ADR-0031 决策 1 中的封顶数字
前置：ADR-0025「推翻条件」第二条（预见了「每工具一份 ADR 的论证成本高于收益」时改等效门禁）

## 背景

封顶从 ADR-0021 的 ~12 起，先后被 ADR-0025（14）、ADR-0029（15）、ADR-0031（16）三次上调。三次都是为一个具体工具立一份 ADR，正文核心都是「为什么这个能力不能复用现有工具」，「为什么上限是这个数」每次都只是「现役 + 0 或 1」。数字本身没有防住过任何一个工具，起作用的始终是那个论证问题。

2026-10-15 D99 需要第 17 个工具 `fact_add`（结构化事实条目 + 写入时校验摘录），又要为占位再立一份 ADR。人裁决：不再设硬上限。

## 决策

1. **取消数量硬上限**。测试里不再断言 `len(TOOL_SCHEMAS)`。
2. **软约束 = 每个工具都有出处，出处里回答「为什么不复用」**：
   - `TOOL_SCHEMAS` 每一项的 `adr` 字段必须指向一份现存文档：`ADR-NNNN`（`docs/dev/adr/` 里恰好一份），或 `plans/<文件名>.md`（`docs/dev/plans/` 或其 `archive/` 里存在）。由 `tests/test_agent_web.py::test_every_tool_has_existing_adr` 机检。
   - 被指向的文档里要写明：这个能力为什么不能用现有工具（`run_pipeline` 子命令、`bash`、`write_episode_file` 等）完成，以及新工具的读写边界与审批级别。这一条靠评审，不靠机检。
   - 难以回头的工具（新的出网面、新的写域、新的执行能力，如 `bash`）照旧立 ADR；只是加一个边界清楚的专用工具，写在施工图里即可。
3. **观测量**：工具 schema 全量进系统提示，数量多了会增加 token 与模型选择负担。2026-10-15 实测 16 个工具的 name + description + parameters 序列化共 11,245 字符。这个数字只作观测，不设门槛；桌面端上下文读数已能看到每轮总量。真出现「模型选错工具」或 schema 占比明显上升的证据时，再回来讨论合并工具，而不是先设一个数等着撞。

## 不做的事

- 不改任何现有工具的语义、边界与审批级别。
- 不引入插件 / MCP 式的动态注册（ADR-0021 的静态注册不变）。

## 同步动作

- `tests/test_agent_web.py`、`tests/test_candidates_propose.py` 去掉工具数断言；出处校验放宽到施工图。
- ADR-0021 / 0025 / 0029 / 0031 加修订注指向本 ADR；`plans/2026-09-22-harness-evolution-direction.md` §4 红线 6 改写。
