# ADR-0026：LLM 请求出网断言豁免「仓库规程的逐字副本」

日期：2026-10-06
状态：**已通过**（2026-10-06 红队定向复审 D30-R2 🟢；人已于同日选定本方案）。沿革：D30-A 立文；2026-10-06 人已选定本方案（Spec 16 §10 Q1 = ②a）；同日红队一轮 🟡 修订后复审——判定机制成立，可信集的取材口径须按 Spec 16 文首 🟡-1~3 修订；**同日 Spec 16 v0.2 作者修订已按此同步本 ADR**（可信集 = 本进程已提交正文 ∪ 路由表当前正文、白名单根、长度门槛），定向复审 🟢 后改「已通过」）
前置：impl spec §2.5 Y2-r19（出网边界）、Spec 4 §2.4（断言生效点）、ADR-0021（网络工具内化）、ADR-0022（工序层上下文装配）

## 背景

`assert_egress_boundary` 在每次 LLM 请求发出前，对整个请求体做四条受限模式（`cloud.local.json`、`agent.local.json`、`03-audio/manifest.json`、`03-audio/voice.json`）的 casefold 子串匹配。ADR-0022 让装配器按工序把 `docs/runbook/*.md` 注入会话；`03-tts.md` 与 `03.5-voice-check.md` 在说明产物位置时写了字面 `03-audio/manifest.json`，于是期目录处在 03 或 03.5 时，会话第一轮就被自己仓库的规程拦下（D30，2026-10-06 复现）。

Y2-r19 要防的是凭据与 `03-audio/` **内容**出网；内容层面已有结构性防线（读域硬排除、`config/` 不在读根、模型无写规程的工具）。请求体上的子串断言是第二层绊线，它分不清「人写在规程里的路径说明」和「模型或外部内容里出现的路径」。

## 决策

请求体断言可以携带一组**可信文本**（Spec 16 v0.2 §5.2）：(a) 本进程装配器实际拼进消息的规程正文，逐文件取，只增不减（常驻层取三份文件各自的原文，不含 `extra_prompt`）；(b) `assembly.json` 的 resident 三件与全部 routes 所指文档的当前磁盘正文，读法与装配器同层一致，用来认出 `--continue` 历史里未改版的旧注入。每份文档都须过读域过滤：resolve 后在仓库根内、落在白名单根（`docs/`、`skills/`、`config/agent/scopes/`、根 `AGENTS.md`）、不在 `data/` 下、`.md`、路径不命中受限模式。**记忆文档永不可信**，来源与路径两道排除。短于 200 字的可信文本一律忽略。某条模式的一次命中，只有**整体落在某段可信文本的逐字副本区间内**才放过；其他任何命中照旧拦截。判定规则本身（casefold、四条模式、归一与同形上限）不变；web 出方向四个调用点不传可信文本，行为逐字节不变。

## 理由

- 放出去的字节逐字等于 git 里人写的规程，不新增模型或外部内容可利用的口子。
- 保留全部现有层：读域、「读域拒了 + 发送闸再掐」双保险、web 出方向断言、清洗、记忆 R3。
- 区间级而不是整条消息级：注入消息里将来拼进的任何动态内容不会被顺带放过；不用「先删可信文本再匹配」，避免横跨边界的命中被拆碎。

## 放弃的方案

改写 runbook 避开字面量（回避式，下一份文档复发）；按消息来源整条豁免（粒度过粗）；把期内产物路径移出请求体断言或改为密钥值匹配（都会拆掉 03-audio 的双保险）。详见 Spec 16 §4。

## 后果

- 03 / 03.5 期目录的会话恢复可用；任何规程写任何字面量都不再触发。
- 残余：恢复会话后规程已改，旧版正文不在可信集，仍可能被拦（开新会话即可）；人在对话里亲手打出受限路径、作业输出带路径，仍会被拦（Spec 16 §10 Q2/Q3，另立条目）；模型把 ≥ 200 字的规程原文逐字抄进工具参数会被豁免，但放出去的就是仓库文档本身。
- 本断言只比对文件名、不看内容，所以它**不承担**「凭据内容不出网」：`assembly.json` 若误路由到凭据文件，内容会被拼进消息而断言不响。这是装配器读域的既有缺口，登记为 N55，在 `load_injected_doc` 层按同一份白名单拒载，另行修复。
