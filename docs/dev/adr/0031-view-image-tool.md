# ADR-0031：第 16 个工具 `view_image`——让模型看期目录里的图

日期：2026-10-13
状态：**已通过**（2026-10-13 人裁决：「直接给模型读图的能力」，并批准 D90 方案）
前置：ADR-0029（工具表 15 封顶，第 16 个须再立 ADR）、ADR-0026（出网断言只比文件名）、D65（工具结果老化：请求时投影）

## 背景

《束胸力学》09 封面一共来回了 20 来轮（D90）：

- ava 每次渲染完只拿到 `path/width/height/sha256`，看不到图。
- 挡脸、字太小、竖版裁得只剩一张大脸，全是人一轮轮指出来的。
- ava 还会对没看过的图下判断，说「精准横跨在胸口」「彻底避开面部」。

后端模型（gemini-3.8-flash）本身能看图，是宿主没把图交给它。

## 决策

1. 工具表上限从 15 改为 **16**，`view_image` 占第 16 位。第 17 个须再立 ADR。
2. `view_image(path)`：
   - **读域**：只看期目录内的图（`.png/.jpg/.jpeg/.webp`）。resolve 之后再判，软链逃不出期目录。沿用 `read_artifact` 的硬排除（`03-audio/`、`04-patch/`）。
   - **限额**：单文件 ≤ 30 MB，像素数有上限。
   - **审批**：只读，免卡。
   - **会话范围**：没有期目录的会话、企划会话不可用。
   - **返回**：工具结果只回尺寸。
3. **图不放进 `role:"tool"` 消息**。2026-10-13 用合成图对本机代理（CLIProxyAPI → Gemini）做了实测：
   - `image_url` 放进 tool 消息：请求不报错，模型照样「描述」，但描述是编的。红圆 / 绿方块 / ZEBRA 73 被说成蓝圆 / 绿三角 / Shape，prompt token 从 1.1k 涨到 5.6k，看起来 base64 被当成了文本。
   - 同一张图放进 user 消息：认对了。
   - 所以由 `vision.attach_images` 在发请求前，在这批工具结果**之后**插一条宿主 user 消息附图，并注明「不是人发的消息」。
4. 附图是**请求时投影**，和 D65 老化同一纪律：
   - 会话史与 `session.jsonl` 只存路径 + sha（消息内部键 `_ava_image`，进请求体前剥掉），base64 不落盘。
   - **只附本回合的图**，本回合最多附最近 4 张。
   - 文件在看过之后变了，或者已经不在，就不发旧图。

## 后果

- **图片出网**：期目录里的图（番剧截图、封面）会发给配置的 LLM 端点。性质和稿件、字幕片段出网一样，都是本项目内容，不是凭据。
- **token**：一张 1568 长边的图约 1.1–1.8k token。最多 4 张、只在本回合附，所以上界可控。
- **模型看得粗**：实测 flash 能分清「两版哪张更挤」，但对「字压没压到头发 / 脸」这种细粒度的位置判断，两次问答结论不一致。挡脸检查不能只靠模型看图。人裁决不加确定性检查，细粒度挡脸由人看图把关（D90）。

## 推翻条件

出现以下任一情况即复议：

- 代理改为原生支持 tool 消息里的图（届时可以去掉投影，直接回图）；
- 后端换成不支持看图的模型。
