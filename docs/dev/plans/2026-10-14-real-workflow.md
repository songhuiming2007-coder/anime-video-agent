## 一、总览：实际的流程

```
选题会话（人机多轮）──人定方向与期名──→ 人点「新建一期」
  └→ 01 AVA 起草 01-topic.md ─人确认─→ 写盘（普通期不填 BGM）
  └→ 02 人要设计稿（立意 / 大概写什么 / 长度）─人点头─→ AVA 读笔记、写草稿、机检、对抗审查
  └→ 02.5 【最重的一步】逐段挑刺 ⟲ 事实核查 ⟲ 人自己改 ⟲ 结构改动（拆段、补素材、多锚点、试看段）
          ─人批准（封板）─→
  └→ 03 配音（有空闲 GPU 走云端，否则本地）
  └→ 03.5 人顺听 ⟲ 读音纠错 / 文案错 → 改稿 + 只重配点名的段（范围人定）
  └→ 04 排片 → 审看页 ⟲ 画面问题改锚点重排（不动配音）
     + 【普通期的 BGM 在这里定】人点名曲目 → AVA 写 01-topic 与 02-script 音乐段（企划期是文案有了之后先定试听 / 试看段、再铺 BGM，见第三、四节）
  └→ 05 人批准
  └→ 06 渲染 → 07 质检 ⟲ 不过就诊断、修、重渲
  └→ 08 标题候选 → 人定；封面：底图（抽帧池 / 人自备）→ 人定文字与大致位置
          → AVA 渲染并自己先看 ⟲ 人看图迭代 → 横竖两版定稿 → 按惯例归档
  └→ 09 简介（长 / 短 / 标签）写进 07-titles.md → 人批 09 → 人手动上传 B 站 + YouTube
```

`⟲` 是人和 AVA 来回的环。两期所见，耗时与轮次主要花在 02.5、03.5、04/05 的画面、08 封面四个环上；03、06、07 基本是机器一趟过。

补素材（搜图、下载、做 SP 资产、`ingest_patch`）**不固定在哪一步**：缺口可能在写稿、改稿、排片、审片任何时候冒出来，企划期缺口大、隔三差五就要补（人 2026-10-14）。

会话也不固定：一期可以一个会话从头跑到尾，也可以分几个会话（人 2026-10-14）。

## 二、逐步：实际怎么走

### 选题（选题会话，在 01 之前）

**实际**：多轮发散，人一轮轮否掉候选（束胸 6 轮、万里花 5 轮），最后从候选里挑一个方向，再要几个期名、挑一个，在桌面端新建一期，选题讨论整段带进新期。

否决理由每期不同，不归纳成固定条件（人 2026-10-14：「并不固定，你没有我做每一个视频的对话记录」）。

**人拍板**：方向、期名。
**AVA 不该做**：普通期在选题阶段定 BGM（束胸 10-12 14:47「谁让你私自定下bgm的？」「不用敲定，必须到配音结束之后才能敲定」）。

### 01 选题落盘

**实际**：AVA 按讨论结果起草 `01-topic.md`，贴给人看，人说「写吧」才写。普通期 BGM 字段此时不填（束胸这期 AVA 自己编了 `BGM结束: 占位`，属于越权）。企划 / 试听型的 `时长目标` 要把音乐段时长算进去（EGOIST 复盘 §五.1：第二期成片 12.23 分钟，立项就该写 11–13 分钟）。
**与文档的出入**：WORKFLOW 写「01 选题（人）：填 01-topic.md」——实际是选题会话里人机共创，AVA 起草、人确认。

### 02 写稿

**实际**：
1. 人先要**设计稿**：核心立意、大概写什么、多长（万里花 10-10 14:40「写文案之前告诉我这一期视频的核心立意是什么大概写什么」）；人会顺带给约束（「不宜写的太长，不要光说教，要有剧情」）。
2. 人点头后 AVA：**先读笔记** → 写 `02-script.draft.md` → `check_script` 到全绿 → 02.8 `adversarial` → 人在桌面端「从草稿新建」`02-script.md`。
   - **02.8 每期必跑**（人定 2026-10-14）；对事实要求严的企划期可能跑多次，但产物只留一份 `02-adversarial.md`。
   - 查两类：事实（动漫剧情和提到的真实事件，不能捏造）、明显不通顺 / 有语病的句子。
3. 「先读笔记」是硬要求（万里花 10-10 14:53「这 50 次调用在干什么……你真逆天，为什么不查笔记」）。

**与文档的出入**：设计稿这一步文档里只在 `creative.md` 有一句，WORKFLOW / runbook 02 没有。

### 02.5 人审改稿：实际最重、范围最大的一步

文档写的是「人精修事实与张力，批准即封板」。两期所见，实际包含四种活，都在配音之前做：

1. **逐段挑刺环**：人指出段号和问题类型，AVA 改完写入、跑机检，人再看下一处。问题类型很稳定：衔接不畅、措辞怪、术语劝退人、AI 味（「不是……而是」）、写得空、开头不抓人、和上一段重复。束胸约 10 轮，万里花约 8 轮。
2. **事实核查环**：人点名一句「需要核查」，AVA 查字幕、笔记、画面，给出有出处的改法；**查不到就说查不到，不许拿推断顶上**（束胸 10-12 15:13「我靠，到底是在哪？昏暗管道也是你编的」）。
3. **人自己也改稿**：人改过的稿，AVA 动之前要先读当前版本，只做最小替换，不整段重写（束胸 10-12 15:16「不敢直接改，因为我已经做了一些修改」）。
4. **结构改动**（束胸第一次大规模出现）：拆段成 8–12 秒的小单元、补外部真实素材（搜索 → 下载 → 做成 SP 资产）、单段多锚点、插入音乐试看段。
   - 束胸选在配音前做，理由是人说的：「这期现在正好在 02.5 人审，还没配音，拆段落不用重配任何东西，是成本最低的时候」（束胸 10-13 08:17）。这是拆段的成本考虑，**不等于补素材只在 02.5 做**——见第一节。
   - **顺序是先画面后拆段**：「先按文字拆、再给每段找画面，顺序反了：每多拆一段，就多一个必须精确对上的画面位，找不到合适素材时，最后又会退回拿画面硬凑」（束胸 10-13 08:23）。也就是先看有什么画面能用，再决定怎么拆。

最后人批准 02.5（封板）。之后再改稿，封板失效，要重新封。

**与文档的出入**：WORKFLOW 把补料写成「02 写稿期或 04 之后」的旁路通道；实际上补素材随时会发生，拆段、多锚点这类画面规划也是 02.5 的主体工作之一。

### 03 配音

**实际**：有空闲 GPU 走云端，没有就本地（束胸 10-13 09:12「运气不好，没有空闲GPU，本地配音吧」）。AVA 提议，人决定走哪条。本地配音前要关掉占内存的程序。
**与文档的出入**：无大出入。

### 03.5 顺听

**实际**：
1. 人听出的不只是读音，还有**文案本身的错**（束胸：「讲两节代数课」应为「听」、段 7 因果写反），所以会回头改 `02-script.md`。
2. 改完只重配点名的段，**重配范围由人严控**（束胸 10-13 11:46「停！你重配的段落太多了！」「因为我看见你好像也要重配12及以后的段落」）。AVA 应先列出哪些段重配、哪些复用，人点头再发。
3. 读音错走顺听面板录纠错条目 → `--apply-patch`。

**与文档的出入**：文档只讲读音纠错；「顺听发现文案错 → 改稿 → 点名重配」这条环没写。

### 04 排片 + 05 审片

**实际**：
1. `clips` → `review` 出审看页 → 人看画面。
2. 画面问题改锚点、加多锚点，**不动配音**，重跑 `clips`（束胸 10-13 12:06「段7和10这么长，你居然只放一张图片？」）。
3. **普通期的 BGM 在这一步定**（两期所见）：人直接点名曲库里的文件，并说怎么用（循环 / 两首接续）；AVA 写进 `01-topic.md` 的 BGM 字段和 `02-script.md` 的音乐段（铺底块、试看段 BGM 让路）（万里花 10-11 02:08、束胸 10-13 12:16）。企划期不同，见第三、四节。
4. 人知道流水线已有某个能力时会提示，AVA 应先查能力再提方案（束胸 10-13 12:32「我记得egoist那几期遇到试看段的时候，bgm会自动暂停……我们的流水线一定是支持这个功能的」）。
5. 人批准 05。

**与文档的出入**：WORKFLOW 和 runbook 的 01–09 里**没有「定 BGM / 音乐编排」这一步**；runbook 01 的字段表还暗示 BGM 在立项时填。

### 06 渲染 + 07 质检

**实际**：基本一趟过。质检不过时 AVA 诊断、给修法（束胸：补丁图被裁，改成完整放进画面），人点头后修、重渲、重检。
**与文档的出入**：无大出入。

### 08 标题与封面：实际是第二重的环

**标题**：出候选 → 人定或改字（万里花 10-11 15:05 人改了措辞）。

**封面**：
1. **底图**两种来源：`cover` 抽帧池；或人自备图。
   **横竖两版都要**；竖版有时直接从横图裁，有时用 AI 扩图（人 2026-10-14）。万里花这期是人用 Google Flow 把原图扩成横竖两张，AVA 只负责给扩图 prompt，**不加戏**（10-11 02:47「flow只需要做扩图或者裁剪就好了，你一直加戏」）。
2. **叠字**：人定文字内容和大致位置（「完全压平？！放右上侧，大大的」），AVA **直接渲染**出候选，**自己先看图**查挡脸、字号、醒目程度，再给人看；人只看图、不看参数（束胸 10-13 13:11「我看参数这辈子也不知道是什么效果，你不做出来我怎么知道」；13:05「你一直让我看，你自己不read图片」）。
   - 写什么字要先讨论（13:00「不要私自写入字，先讨论」）；字定了以后，渲染候选不需要再问。
3. **比例定死**（人定 2026-10-14）：**横版 16:9、竖版 9:14**。往期竖版 2:3、9:16、9:14 都有，以后统一 9:14。竖版不能裁成大脸、不能有上下模糊垫底（束胸 13:12–13:14）。
4. **系列企划**：版式照抄第一期，只换文字（EGOIST 复盘 §三）。
5. **归档**：定稿复制到期目录顶层 `08-cover.jpg`（横）/ `08-cover-vertical.jpg`（竖），候选都留在 `07-cover/`，顶层不放别的（万里花 10-11 15:15「我说目录怎么这么乱，08怎么那么多封面，看看往期」）。这个命名是 08-18 起往期逐渐形成的惯例，D90 前任何文档都没写。

**与文档的出入**：WORKFLOW 写「叠字排版由 agent 调 cover_edit，每次渲染弹人审卡」——D78 后已免卡；「先讨论文字、再直接渲染、自己先看图」这个分工没写。

### 09 发布

**实际**：
1. `07-titles.md` 里要有：定稿标题、**一份**视频简介、标签。
   - 简介不分平台，统一一份，同时照顾长视频平台和短视频平台；**不能简单照抄文案**（人定 2026-10-14）。束胸、万里花两期写了「长视频版 + 短视频版」两份，以后合成一份。
2. 横竖封面在顶层。
3. 人批 09（填封面路径与标题）→ 人手动上传 B 站、YouTube。
4. 以上不齐，**不能说「闭环」**。两期在这里被人纠正 7 次（万里花 10-11 02:42「封面还得写字呢，你怎么敢说做完了」、14:57「并未闭环，你去看看往期目录」、15:02「还没完，你为什么这么着急，视频简介还没写」；束胸 10-13 13:18「不对！再看往期目录」、13:19「没完！视频简介没写」）。

**与文档的出入**：D90 后 runbook 09 的「输入物」已列横竖封面和简介，但「人工操作」仍写「挑选 1 张封面」，「核心规程」仍写「发布完成即标志本期生产闭环」，两处自相矛盾。

## 三、企划期（EGOIST）：多出来的部分

**背景**：EGOIST 是在 pi 里做的，那时还没有 AVA；做片和流水线开发交织在一起。时间线（产物修改时间 + 同期提交）：
- **V1**（09-06 ～ 09-08）：没有真实素材，只用动漫与 MV / Live。同期仓库在开发跨番混剪、SP 特典、多锚点、试听型音乐（ADR-0010 ～ 0013）。人觉得不能这么做。
- **V1 → V2 之间**（09-08 ～ 09-11）：为了用上真实素材，开发了云端 GPU 部署模型接入流水线（云端配音、视觉语义索引、素材自动搜集，M1b ～ M2.5）。
- **V2**（09-11 ～ 09-14）：真正发布出去的版本，三卷 + 典藏合集。
- 下文只写**做片**的部分，开发的部分不进 AVA 的 context。

**立项**：人给方向（EGOIST 超长篇介绍）→ AI 先搜集一波资料 → AI 建议分几期、每期覆盖什么范围 → 人同意 → 落成总纲 `00-project-plan.md` 与素材蓝图 `01-assets-video.md`。**合集期从一开始就规划了**（人：「可以吃流量红利」），后来做成 `00-全一期-典藏版`。

**每卷写稿前多出来的产物**：事实核查报告 `01-fact-check-report.md`、名场面清单 `01-hero-shots.md`。
- 这些是人在做的过程中想到要加的，**不是固定清单**；原则是：企划对事实真实性的要求非常非常高，事实和名场面要先落成文件，「不然只能靠人的记忆，不靠谱」。
- 长视频要看得下去，不能只讲故事，也要带来一点思考。

**素材搜集是多轮的**：先预收集肯定会用到的 → 文案有了以后再搜一轮 → 改文案过程中顺便核锚点，又搜好几轮。

**对抗审查**：查两类——事实（动漫剧情和提到的真实事件，不能捏造）、明显不通顺 / 有语病的句子。企划期可能跑多次，产物只留一份。

**音乐（V2）**：文案有了之后，先定试听段和试看段，再铺满 BGM；调整非常多。具体曲单与起止点怎么定，每次不一样（见第四节）。

**卷与卷之间**：交叉推进，不是做完一卷再做下一卷。已知要保持一致的：标题命名体系、封面版式照抄第一期（`00-production-lessons.md` §三）；其余人也说不准。

**总装合集**：按 `00-全一期-典藏版/01.5-assembly-spec.md` 拼接（片尾截断、封面过场卡、编码一致性、总装后自证）。

## 四、音乐编排：普通期与企划期是两个复杂度

**每期都不一样，下面不写数量、时长这类固定数字**（人 2026-10-14）：几首曲子、几个音乐段、试听多长、插不插试看段，都看这一期本身。

**普通期**（两期所见）：编排相对简单，以 BGM 铺底为主，可能插试看段；试看期间 BGM 自动让路、放完接着播。曲目在配音之后由人点名，AVA 照写。语法上有一条硬约束：稿件里一旦有任何 `## 音乐段`，BGM 就只认稿件里的块（D89），所以插了试看段的期，BGM 也要写成铺底块（束胸的写法：片头铺底 → 更衣室试看 → 下半场换曲铺底）。

**企划期 / 试听型**（看 EGOIST V2 三期的 `02-script.md`）：音乐本身是叙事证据，音乐段和正文段落交织，**和文案一起设计**，不是事后配。可用的块：

| 块 | 写法 | 作用 |
|---|---|---|
| 前景试听 | `音乐:` 曲名 + 曲内起止 + `状态: 前景试听，旁白停止` + `过渡: 降为 BGM / 淡出` + `画面:` | 原声大音量纯享，旁白停；之后同一首降为弱音托底，或淡出 |
| 背景铺底 | `音乐:` 曲名 + 起点 + `状态: 背景铺底` | 不占时长，铺到下一个音乐块，配侧链闪避托住口播 |
| 现场原声试看 | `源片原声:` + `音画同源: 是` + `画面: 同源` | Live / 名场面原片声画直出，旁白与 BGM 都静音 |
| 自然收尾 | 末段 `继续播放至完整版结束` + `收尾画面:` | 片尾整首播完，画面单独指定长源 |

这几种块怎么组合，三期各不相同。举两个用过的例子（只是例子，不是模板）：前景高潮之后同一首降为 BGM 继续托住口播；或者同一首歌先以前奏铺底的方式垫在口播下面，再接它的前景高潮、然后淡出。

**粗顺序有，细节没有固定流程**：EGOIST V2 是文案有了之后先定试听段和试看段，再铺满 BGM，之后反复调整（人 2026-10-14）。曲单与曲内起止点由谁、在哪一步定，每次不一样——「这就是复杂的地方」。所以这一块不写成细步骤，只写清块的语法与粗顺序，具体每期怎么排由人主导。

## 五、横切：谁拍板、AVA 什么时候不用问

**人定（2026-10-14）**：配音（首配与重配）、排片、渲染、质检、出封面候选、对抗审查、写 01-topic / 07-titles、叠字渲染、往顶层放定稿封面——这些有副作用的操作，**AVA 先在对话里问清楚、人同意了再做，不加审批卡**。

「问清楚」的意思（从两期记录看）：AVA **自己起意**要做的事先问；**人的话已经明确了要做什么**（「放大点」「朝右移一点」「开始渲染吧」），那句话本身就是同意，直接做，不再追问参数——束胸封面连问 6 轮参数就是把这两种情况混了。

下表从两期的纠正里归纳（两期所见，企划期未必相同）。**左列是人一再收回的决定权，右列是 AVA 不用问就该做的事（只读、查证，或人已明确指示）。**

| 人拍板（AVA 只出候选，不许代定） | AVA 不用问（只读、查证，或人已明确指示） |
|---|---|
| 选题方向、期名 | 出候选前先查往期做过什么 |
| 设计稿（立意、长度、大概结构） | 写稿前读笔记；核查事实时查字幕、笔记、画面 |
| 张力字段 | 人指出段落问题、说了怎么改之后，照改写入 |
| 结构改动的方案（拆段、补什么素材） | 定了方案后去搜、下、做 SP 资产 |
| 重配哪几段 | 先列出重配 / 复用清单 |
| **BGM 曲目**（普通期 04/05 时由人点名） | 按人点名写 01-topic 与音乐段；先查流水线已有能力 |
| 封面写什么字、大致放哪 | 字与位置定了之后渲染候选、**自己先看图**；按往期惯例命名归档 |
| 定稿标题 | 写简介（长 / 短）与标签初稿 |
| 四个停机点的批准、上传 | 「做完」之前按交付清单逐项核对 |
| 何时跑配音、排片、渲染、质检、出候选（先问） | 跑之前把要跑什么、影响哪些段说清楚 |

两类错误都出现过：左列 AVA 越权（私定 BGM、私写封面字、编 `BGM结束: 占位`）；右列 AVA 不做、反复请示（人已说了改法，还连问 6 轮参数）。

## 七、已定（人 2026-10-14）

- 选题否决理由不归纳成固定条件。
- 设计稿就是立意、大概写什么、长度，不再加别的。
- 02.8 对抗审查每期必跑；企划期可能跑多次，产物只留一份。

- 音乐编排分普通期与企划期两个复杂度；不写数量、时长等固定数字，每期看本期；企划期没有固定流程，由人主导。
