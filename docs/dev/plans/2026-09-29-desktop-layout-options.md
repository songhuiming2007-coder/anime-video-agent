## 3. 方案（两者共用 C1–C5；颜色、字号、圆角、图标等 Spec 14 视觉 token 一律不动）

**公共修正**：C1 工序卡压成一行（工序 + 「停机」+ 命令单行省略），「详情」展开 next_action、停机原因、advisories、人时；C2 会话头恒为一行，降级长文案挪到对话流首行（Spec 10 §2.3 本就规定「`llm: degraded` 时流内一行降级说明」），头部只留「LLM 未就绪」，文案一字不改；C3 对话流最小 160px，待答区上限 40%，中栏改 `overflow:auto` 兜底（放不下就滚，永不静默裁按钮）；C4 时间线收成 32px 摘要条（作业数 / 失败数 / 事件数，展开上限 40vh），只占预览列底部；C5 人时进 C1 的「详情」。

**原型实测**（8 张图，同一 s3 状态）：文本相交 0、控件被裁 0、hidden 裁切 0；对话流可见高度 **401px（1440×900）/ 301px（1280×800）**，HEAD 为 32px；批准 / 打回 / 发送全部 100% 可见。原型是运行时注入样式与少量 DOM 搬移做的截图，不是实现。

**我的推荐：B。** 这个场景里对话和卡片是持续用的，预览只在停机点审阅和人点开文件时需要；A 在 1280 宽下对话只剩 432px，仍属「挤」的同一类，且 200px 的文件列放不下封面拖放区（`proto-A-1440x900.png` 里「选择文件…」越出虚线框）。B 的代价：05 审阅要多点一下展开预览；展开后在 1280 宽下对话与预览各约 510px。
