# 方案 P4：写稿链重构——从「更长的规则」换成「会复利的资产」（文案四病）

> **后续修订（2026-08-15）**：E3 的「每期 01.5 节拍表」已被推翻。复盘确认 beats
> 不适合杂谈、盘点、共鸣，现行规则改为仅人物志 / 剧情回顾按期启用；本文件保留作
> 方案历史，不再作为当前工作流依据。

对应 issue：**B2**（人时超限，02.5 实为 ~60 分钟）、**D3**（min_chars 逼注水，本方案内拍板）、
**D12**（语气词判据缺口语体样本，风格锚点顺手解锁）、ADR-0005 文案侧补记（prompt 免检 /
机检逼内容 / 注水）。

## 病根与对策总览（为什么不是第 N+1 版 skill）

用户实测：skill 改过多版，文案四病不变——① 机器味浓 ② 段间衔接不自然
③ 机械效仿 skill 弄巧成拙 ④ 剧情错误与含混。判断（第一性分析，2026-08-14 会话）：

- **①②③ 同一病**：374 行规则全程在写稿模型的注意力里，模型无法「忘掉」
  （元规矩一「写的时候忘掉这份文件」对模型物理不可执行）。规则描述什么模型就
  **表演**什么——「要有非承重细节」催生表演性细节；skill 内嵌的示例短语
  （「这里我第一次觉得她好看」等）被逐字模仿成口癖；「上一段留下的问题下一段
  回答」作为规则存在时，衔接是补的胶水不是长出的逻辑。每轮迭代 = 加规则 =
  多一个可表演的表面特征 = 换一种方式烂。
- **④ 是另一病**：事实核查缺失。稿件只有写稿 agent 自检两遍；D13 已实战验证的
  零上下文对抗审查（笔记层 0 编造）从未用于稿件。

对策不是更好的规则，是四样**会复利的资产/机制**：

| # | 机制 | 治什么 | 见效 |
|---|---|---|---|
| A | 02.5 diff 对存档（机器稿基线不再被覆盖） | ①（长期） | 当期起积累 |
| B | 稿件级零上下文对抗审查 | ④ | 第一期 |
| C | 节拍表前置（02 两阶段） | ② + 打通 from-core | 第一期 |
| D | SKILL 减脂 + 范本/过审稿升位 | ①③ | 第一期 |

**本方案分两部分：执行代理做 E1–E6（机械、可测）；会话侧流程 S1–S4（写进 WORKFLOW，
由未来写稿会话执行，执行代理只改文档不跑写稿）。**

## 前置条件

- `uv run pytest` 基线全绿；不需要挂 data 盘（文档与配置改动为主，代码仅 check_script）。
- `skills/write-script/SKILL.md` 有未提交用户改动：**先 `git diff skills/write-script/SKILL.md`
  读懂现状再动**，只做方案列出的修改，不回退用户改动。

## 第一部分：执行代理改动清单（E1–E6）

### E1. D3 拍板落地：check_script 支持「缩段不注水」

决策（用户 2026-08-14 拍板）：**字数下限对人物志/剧情回顾/共鸣放宽**——判据从
「字数 ≥ min_chars」改为「字数 ≥ min_chars × 0.85 且料单承重条数达标」不可行
（料单是给 agent 看的，机检不好验）。**采用最简实现**：

`pipeline/check_script.py` 现状（第 38 行附近）：

```python
MIN_CHARS = paths.conf("script.min_chars", 870)
```

改为支持 per-episode 软下限：`01-topic.md` 写 `缩段不注水: 是` 时，字数下限乘
`script.shrink_factor`（config，默认 0.8，取值理由：楪祈二 2101 字 vs 下界 2362
= 0.89；void 期实际可用料撑不满时 0.8 留出「砍掉整段」的余地，而不是砍到刚过线）。
实现与 `episode_duration_override()` 同款：新正则读字段，缺省行为不变。

```python
# 01-topic.md 的 `缩段不注水: 是`：字数下限 × shrink_factor。
# 依据 ADR-0005 补记三：字数下限逼 agent 注水，被骂的机器味句子相当部分是
# 凑字数补出来的。这是「允许承认这段没料、缩短」，不是放宽默认带。
SHRINK_FIELD = re.compile(r"^\s*缩段不注水\s*[:：]\s*是\s*$", re.M)
```

- `config/project.json` 的 `script` 块加 `"shrink_factor": 0.8` + `_shrink_note`
  （写明 ADR-0005 依据与 0.8 的来路）。
- 测试：无字段行为不变；有字段下限 = round(870×0.8)；上界不动。变异检验：把
  factor 改 1.0 跑测试，下限变化的断言必须红。
- **同步 D3 收尾**：`docs/issues/pending.md` 删 D3，索引同步。

### E3. 节拍表前置：01.5 步与格式定义（文件层，已部分推翻）

原方案曾在 `docs/WORKFLOW.md` 的 01 与 02 之间插入 **01.5 出节拍表（人批，~2 分钟）**。
该方案现在只保留给人物志 / 剧情回顾按期使用，杂谈 / 盘点 / 共鸣直接进入 02。

- 产物 `01.5-beats.md`，格式（示例给出，写稿会话照此填）：

```markdown
# 节拍表：<本期标题>
类型: 人物志 ｜ 时长目标: 7-8分钟 ｜ 段数: 12

| # | 这段讲什么 | 落点（画面/台词/物件） | 料 |
|---|---|---|---|
| 1 | 开场： void/Void 双关，第一句人声 | S01E01 王之刻印诞生 | 台词1 |
| 2 | 祁是谁： 从容器到人 | E02 涯的解释 + E03 「心的形状」 | 台词3,5 |
| ... |
| 12 | 收束： 白空间交接「接着」 | S01E22 19:10 | 台词19 |
```

- **判据（人批时看的就三样）**：弧线完整（开头承诺的，结尾还了）；相邻行说得出
  推进关系；每行的「料」在笔记/料单里真的存在。三样任一不满足打回，**打回的是
  10 行的表，不是 2400 字的稿**——这是本机制省时间的全部原理。
- 写稿阶段只许「填表」不许「改表」：正文与表冲突时停下来报告，不即兴调整结构
  （结构病正是要在 10 行时抓的东西）。
- 与 from-core 的关系写明：同一张表，用户手写 = from-core 模式（跳过 agent 出表，
  直接进扩写），agent 出表用户批 = auto 模式。`config/script-mode` 字段语义不变。

### E4. 稿件对抗审查：07 之前插入 02.8（文件层 + 复用现有机制）

`docs/WORKFLOW.md` 02.5 之后加 **02.8 零上下文对抗审查（agent 劳动，人零耗时）**：

- 复用 D13 三步流水线（写厚门槛 → 零上下文对撞 → 终审裁决回写），对象从番剧
  笔记换成 `02-script.md`。审查 agent **零上下文**（判据 11）：不看料单、不看
  选题、只拿稿件本身 + 字幕索引 + 笔记。
- 逐条核销清单（从 D13 引用级核销平移）：
  1. 每个叙事断言（谁在哪做了什么）→ 追笔记来源行；追不到 = 报告条目
  2. 每句引文 → `subindex search` 逐字比对 + 集号核对
  3. 每处「某某说」→ 时间码定位 + 抽帧确认说话人
  4. 含混表述（「好像」「似乎」承载剧情断言时）→ 列出要求写稿侧消歧或删除
- **报告必须含随机抽样通过清单**（判据 11：只报错不报过的报告是选择偏差）；
  报告落 `data/episodes/<期>/02-adversarial.md`，终审裁决（写稿会话逐条
  采纳/驳回）记进同文件。
- **审查管事实不管审美**：机器味、节奏、好不好听不在对抗范围（那是 02.5 的）。
  与 02.5 的分工：02.8 拦「假」，02.5 拦「坏」。

### E5. SKILL 减脂 + 范本升位（`skills/write-script/SKILL.md`）

**原则：删表演面，升真实例。** 用户未提交改动先行保留，以下在其上做：

**删/降级（模型可表演的规则面）：**

1. 第 5 节「语言：念得出来」整节压缩为 5 行以内：保留「出声念一遍」最终判据 +

2. **杀掉所有内嵌示例短语**：全文搜索引号内的示例句（「这里我第一次觉得她好看」

4. 第 3 节「说话的位置」五问压缩：五问本身是好思考工具，但作为「写前必答」

## 第二部分：会话侧流程（S1–S4，写进 WORKFLOW，由写稿会话执行）

### S1. diff 对存档（每期 02.5 时）

机器初稿落 `02-script.draft.md` → 用户 02.5 改稿直接改 `02-script.md` →
改完当场跑 `git diff --no-index --stat 02-script.draft.md 02-script.md >
02-diff.patch`（落在期目录）。这个 patch 对就是「账号声音」的标注数据。
02.5 结束时 agent 报一句 diff 规模（增/删行数、改动段数），给 B2 计时提供数据。

### S2. 节拍表（每期 01.5）

出表 → 用户批（就看 E3 的三样判据，~2 分钟）→ 批过的表是 02 的宪法，
写稿只许填不许改。

### S3. 对抗审查（每期 02.8）

零上下文 agent 按 E4 清单出报告 → 写稿会话终审裁决（逐条采纳/驳回）→
修正回写 → `02-adversarial.md` 存档。**人不在这一步出现。**

### S4. from-core 试用（P4 落地后第 2–3 期）

用户手写节拍表一期（跳过 agent 出表），实测「审大纲的扩写」vs「审机器全稿」
的 02.5 耗时差。数据回 B2。
