## 改动清单（按序执行）

### 1. D14：tts.py CPM 单源化（代码债，先做）

`pipeline/tts.py` 现状：

```python
CPM = 280           # 中文口播字/分钟，与 check_script 同源
```

改为读 config，与 `check_script.py:30` 完全同款、同 fallback：

```python
CPM = paths.conf("script.cpm", 380)   # 与 check_script 同源同 fallback；真值在
                                      # config/project.json（2026-08-10 校准 315），
                                      # 注释不再声称「同源」却各写各的数
```

`paths` 已在 tts.py 导入（模型钉盘那行）。行为影响：`expected_duration()` 估算
变短 12.5%，`want` 变小 → 实际/估算比值变大；DUR_BAND (0.5, 2.0) 很宽，不改变
判定面，属预期。

测试 `tests/test_tts.py` 的 `TestExpectedDuration` 现有断言全是相对式（
`expected_duration(x) == len/CPM*60`），**测不出分叉**——正是 D14 说的静默错误。
补一条绝对式断言：

```python
def test_CPM_与_config_同源(self):
    from pipeline import paths as pl
    assert t.CPM == pl.conf("script.cpm", 380)
```

（变异检验：把 tts.py 的 CPM 改回字面量 280，这条必须红。）

### 2. N15：tts.py 时长带读 per-episode 覆盖

`pipeline/tts.py` run() 尾部现状：

```python
if not 120 <= total <= 240:
    print(f"WARN 成片时长 {total / 60:.1f} 分钟，超出 2–4 分钟区间", file=sys.stderr)
```

改为复用 qc 的读者（单源，不再抄第三份正则；qc 不 import tts，无环）：

```python
from .qc import episode_duration_band   # 文件顶部 import
band = episode_duration_band(episode) or tuple(paths.conf("video.duration_band", [120.0, 240.0]))
if not band[0] <= total <= band[1]:
    print(f"WARN 成片时长 {total / 60:.1f} 分钟，超出目标区间", file=sys.stderr)
```

模块顶部加常量注释说明默认带与 `config/project.json` 的 `video.duration_band` 同源。
补测试：无 01-topic.md 时走默认带；有时长目标字段时走覆盖带（`episode_duration_band`
在 test_qc.py 若已测过就只测 tts 侧的 fallback 选择逻辑）。

### 4. D17：测试数清算——删数字，不回填数字

实测口径（本仓库当前）：

```bash
uv run pytest --collect-only -q | tail -1
```

原则：**文档里的测试条数没有任何机器强制同步机制，回填一个新数字只是把腐烂周期
重置**。除「数字承担功能」的位置外，一律删数字：

| 位置 | 动作 |
|---|---|
| `README.md` 三处条数 | 删数字，改「跑 `uv run pytest`，见 CI」之类 |
| `CONTRIBUTING.md` 两处 | 同上 |
| `.github/workflows/test.yml` | 先读内容：若是注释/名称里的装饰数字→删；若有实际逻辑依赖→保留并更新 |
| `docs/ROADMAP.md` 对应行 | 先读上下文：若条数是闸门判据→改为「以 `pytest --collect-only` 输出为准」；若是装饰→删 |
| `pyproject.toml` 描述里的条数 | 删数字 |

**顺序注意**：本方案第 1、2 条会新增测试，先做代码改动再清理文档，避免文档先写
又立刻过时。
