# 改稿回合提速 + 修去重回归 + 02.5 一键批准 + 人物志因果（D48）

日期：2026-10-08　状态：**已施工，机检通过，待真实一期手验**
关联：D48；D44（去重回归来源）；D47；ADR-0024 §3 I2；ADR-0025；`skills/write-script/SKILL.md` 4.1

## 起因

人贴来董香二期 02/02.5 的完整会话，要求找出效率、体验、效果上的改进点。人同意了我列的修改，并补充：「你没发现我让改的全部是因果联系不畅吗」——段落 2、4、6、8、17、21 的修改请求全是「观众不知道为什么」。核实到的事实：

- **去重回归（D44 引入）**：`llm.py:812` 只在人批准的执行后清空本轮判重表；D44 让草稿前 3 次写入免卡，写完不清表，于是「写草稿 → 再跑同一条 check_script」被判重复，模型换着写 `data/…`、`./data/…`、`/Volumes/…` 绕过去。
- **字数卡顶 + 偷改人认可的句子**：稿子长期贴着上限（1538–1549 / 上限 1542）。每补一句因果就超字数，模型自己再写一次删字——人说「就这么改」的那句被改成别的、「削弱力量」被删，未告知。所以每次小改 = 写 2 次 + 检查 2 次 + 5 次模型调用、60–150 秒。
- **先建议再问「是否修改」**：段落 4、6、8、17、21 都是两轮（贴建议 → 人回「可以」→ 再写）。D47 后写稿卡自带 diff，卡就是确认。
- **整篇重写**：每次只改一段也传 7.6 KB 全文，上下文从 6.5 万涨到 9.6 万字，越聊越慢，也容易顺手动别段。
- **机检整份重贴**：每次都贴全部 PASS 与早已知道的 CV 未过项。
- **02.5 批准报错**：没封板时点「批准」→ `E_CORE` + 一条终端命令；封板只是确定性的 `git diff`，人点批准就是人审动作。
- **人物志没有因果规则**：`skills/write-script/SKILL.md` 的「人物动机推因果、因果相邻咬合」只在 4.2 剧情回顾 / 4.3 杂谈；4.1 人物志写「按经历顺序讲……段落不追求每段收口」，自检清单人物志一行也没有因果。推动她经历的多是别人的动机（青桐为何来、壁虎为何掳金木、金木为何回 20 区），最先被省掉。

## 施工内容

### A. 去重回归（`pipeline/agent/llm.py`）
`write_episode_file` 执行成功后也清空判重表（与「人批准的执行后清空」并列）。只清写入后：只读的 check_script 免卡执行不清，原地反复跑同一条检查仍会被判重（防打转的本意不变）。

### B. 局部替换写法（`pipeline/agent/tools.py`、`status_card.py`、`session.py`）
- `write_episode_file` 加可选参数 `edits: [{old, new}]`，与 `content` 二选一。每个 `old` 必须在当前文件里**恰好出现一次**，按顺序替换；不唯一 / 找不到 → 报错并指出是第几条。不加新工具（ADR-0025 不变）。
- 新增 `resolve_write_content(ep_dir, args) -> str`，三处共用：落盘（`_tool_write_episode_file`）、写稿卡 diff（`render_approval_card`）、弹卡前校验（`review_tool_call` 里 edits 不成立直接 reject，不弹卡）。
- `tool_summary`：`write_episode_file` 显示「文件名 · 整篇 N KB / 局部 N 处」，`run_pipeline` 显示 command 原文，不再是截断的 JSON。

### C. 02.5 一键批准（`pipeline/agent/cli.py`、`pipeline/status.py`）
- `/approve 02.5`（终端 REPL 与裸形态两处调用点，桌面端走裸形态）在调用 `approvals.approve` 前：若 `_gate_valid(ep, "02.5")` 为假，先跑 `_cmd_seal_script`；封板失败（如零改动）原样报错、不批准。批准仍是人的显式动作，封板随之完成。
- `status.py` 02.5 的 block 文案改为「在桌面端点 02.5「批准」（会自动封板），或终端 `/approve 02.5`」，不再只给 `git diff` 命令。
- ADR-0024 §3 I2 加注：02.5 批准时的封板写入 `02-diff.patch`（与「封板」按钮同一子命令）。

### D. 提示词（`config/agent/scopes/creative.md`）
1. 人指出某段有问题 → **直接改并写入**，审批卡（02-script.md）就是确认；人在提问（「是不是…」「对吗」）→ 只回答，不写。
2. 人确认过的原句逐字写入；改完超字数 → 报「超 N 字」并给出可删的候选，**不自己压缩**，尤其不删人认可的句子与因果交代。
3. 改稿用 `edits` 只替换改动的段落，不整篇重写。
4. 机检只报与上次相比的变化项；已知且人说过不追的项（CV）不再重复。
5. 多个互不依赖的字幕查询放在同一条回复里一起发（底层已支持一条回复多个调用，`llm.py:670`）。

### E. 人物志因果（`skills/write-script/SKILL.md` 及 `.local.md`、`creative.md`）
- 4.1 人物志加一条：**经历之间因果咬合**——每段的事件要么由上一段直接引出，要么开头一句交代起因；别人推动她经历的事，交代那个人的动机（一句即可）。点评贴着当下一幕的规则不变。
- 自检清单人物志一行加「每个转折观众都知道为什么发生」。
- `creative.md` 交稿前加一步因果自查：逐段问「上一段到这一段，没看过剧的人知道为什么吗」，缺的补上；字数不够补时在回复里列出缺口，交人决定（删别处还是放宽本期时长），不硬塞也不静默省略。
- 这是写作规则，不进 check_script（判断因果是语义判断，不包装成机器判据，AGENTS.md 一节）。
