# 上下文压缩（D62）：长会话的 compact 机制

日期：2026-10-09　状态：**草案·待裁决与施工**
关联：D28（取消固定轮数硬上限，2026-09-24 人裁决）、D56（服务商实测 token 读数）、D54（诚实性纪律：事实带出处）、ADR-0018（出网断言）、ADR-0025（工具封顶）、AGENTS.md「产物即状态」「诚实失败」

## 一、问题

D28 取消固定轮数上限后，主会话上下文**只涨不缩**。现有三件相关物都不是管理动作：

- D56 的 token 读数：只是显示，没有后续动作；
- 检查点（50 条/次问人）：防失控，不防溢出；
- session.jsonl：全量落盘可恢复，但恢复是把全文读回来——溢出风险原样带回。

真实结局：长会话跑到服务商报 context-length 错，回合报错交人，会话实质变砖。长会话场景真实存在：人物志多期连做、素材侧大批量期（probe/fetch 几十条）、笔记终审（一次 54 条裁决）。

## 二、成熟方案调研（2026-10-09）

七家 coding agent harness（Codex / Claude Code / Gemini CLI / opencode / OpenHands / Roo Code / pi）的**公约数**：

1. **同模型**单独一次调用做摘要——压缩被视为「需要准确召回」的操作，不是省钱操作；
2. 全文进摘要器；
3. 摘要以 **user-role + 固定前缀**落史（Codex 的 summary prefix：多轮压缩时滤掉旧摘要，防摘要套娃）；
4. **替换而非追加**：摘要 + 近期原文尾部（Gemini 留 30% 逐字尾部；Codex 留 ≤20k token 的近期 user 消息）；
5. 压缩失败不硬来：中止回合交人（多数）；Gemini 另有「压缩后反而变长 → 本会话禁用自动压缩」护栏。

差异化亮点：

| 家 | 值得学的 |
|---|---|
| Claude Code | 压缩后按预算**重注入**最近读过的文件/技能/活动 plan——文件密集任务连续性大增 |
| Codex | **双触发**：回合开始前 + 工具循环中段（中段触发时保住待处理的用户请求）；阈值 90% 偏晚是反例 |
| Gemini CLI | 50% 触发（**标称窗口 ≠ 可靠窗口**）；两段式摘要+自我批评；提示注入硬化写进压缩 prompt；压缩膨胀护栏 |
| opencode | 用**服务商实测 token 数**触发，不用本地估算——ava 的 D56 已有此数据 |
| Codex DSC RFC（未验证） | 事件日志**确定性投影**代替 LL 摘要：无 LLM 调用、可复现、可测；与 ava「产物即状态」气质吻合，留为演进方向 |

## 三、ava 特有约束（设计不能照抄的理由）

1. **产物即状态**：期进度、审批台账、读音表、记忆全在磁盘。压缩后最该重注入的不是「最近读过的文件」（Claude Code 路线是代码 agent 的），而是**从磁盘确定性重建的期状态卡**（`status_card.py` 现有产物）——ava 天然更接近 DSC 路线。
2. **HITL 卡**：压缩时可能正悬着人审卡。挂起的 HumanRequest 不进 messages，但「正在等哪张卡」必须进摘要或重注入，否则压缩后 agent 忘了在等人。
3. **D54 纪律**：摘要是 LLM 转述，转述即编造风险面。摘要 prompt 写死：事实必须带出处锚点（文件名/集数/时间码/URL），无法锚定的标「未证实」。**这是对董香二期 D54 的直接防疫。**
4. **出网断言**：摘要文本进会话历史，过 `_scrub`（RESTRICTED_EGRESS_PATTERNS），与 web 工具回喂同一条纪律——防脏串把会话打成 [BLOCKED]。
5. **审计**：压缩事件（触发时 token 数、摘要 sha、丢弃的消息区间）写 session.jsonl；压缩前历史本来就在日志里，摘要消息后给「完整历史在 session.jsonl，需要细节用工具切片查，别整体读入」的指针。
6. **诚实失败**：压缩 LLM 调用失败 → 本回合中止交人，不静默重试、不降级硬截断。

## 四、设计草案

- **触发**：以 D56 的服务商实测 `prompt_tokens` 为准（opencode 路线）。双触发（Codex 路线）：回合开始前、工具循环中段模型还要继续时。阈值进 config：`agent.compact.trigger_ratio`，**默认 0.6**——对齐 Gemini「标称≠可靠」教训，宁早勿晚；实测后可调（标定值纪律）。
- **摘要器**：主会话同模型（`model_for` 主会话档，不另起便宜档——公约数 1）。prompt = Codex 最小 handoff 骨架（进展/决定/约束/下一步/关键数据）+ ava 专属段：当前期与步骤（从磁盘读入 prompt，摘要器只许引用不许转述）、挂起的人审卡、被驳回的判断及理由、事实-出处对照、下一步。
- **落史形态**：user-role + 固定前缀「压缩摘要 v1」（多轮压缩滤旧摘要）；尾部保留最近 K 条原样消息（K 进 config，**先 20 条**起）。
- **重注入**：摘要消息之后、尾部之前，注入磁盘重建的期状态卡 + session.jsonl 指针。
- **护栏**：摘要长度 ≥ 被压缩区间 × 0.8 → 判压缩失败（Gemini 护栏变体），本回合中止交人、本会话不再自动压缩。
- **手动**：`/compact` 命令，绕过阈值（各家手动入口的公约数）。
- **不做**：DSC 全确定性路线（RFC 未验证）；但摘要器输出 schema 化，留将来换成确定性投影的接口。

## 五、待人定

1. 默认触发比例（草案 0.6）与尾部保留 K（草案 20 条）；
2. 压缩对人的可见形态：状态卡一角 / 一张 notice / 仅事后可查；
3. idea 会话（无期目录、无状态卡可重注入）是否同一套。

## 六、验收判据（每条配「它会失败」的变异）

1. 触发：mock usage 超阈值 → 压缩发生；未到 → 不发生（变异：比较方向反转）。
2. 落史形态：user-role + 前缀；二次压缩滤掉旧摘要（变异：不滤 → 套娃）。
3. 尾部 K 条逐字不变（变异：K-1）。
4. 重注入的期状态卡来自磁盘而非摘要器输出（变异：摘要器输出原样进史 → 红）。
5. 压缩失败/膨胀 → 回合中止 + 本会话禁用自动压缩（变异：失败照压 → 红）。
6. 摘要过 `_scrub`：脏串 → [已脱敏]，会话不炸。
7. session.jsonl 有压缩事件（token 数、摘要 sha、丢弃区间）。
8. 挂起人审卡的标识进摘要/重注入（变异：丢了 → 红）。
