> 对应 issue：**D71**（`docs/dev/issues/README.md`）。人选方案 **A**（2026-10-11，看过 [`2026-10-11-job-status-shots/`](2026-10-11-job-status-shots/shots.spec.ts) 四张真实窗口截图：现状 / A 全局作业条 / B 时间线醒目态 / C 面板自管）。

## 一、用户场景与目标

**场景**（2026-10-10 伪恋期实录）：人在 1280×800 或 1440×900 窗口里做一期，侧栏时开时收，预览区常收起（做视频时的常态，D39/D49）。在顺听面板点了重配、或让 agent 跑配音 / 排片 / 渲染之后，人接着在对话区和 agent 说话、或者去看别的产物。**每一步人都要一眼看到**：现在有没有作业在跑、跑的是什么、跑了多久；想看细节时一点就到时间线。

现状：唯一线索是预览区底部时间线一行里的「作业 N」计数（预览收起时根本看不见），以及顺听面板里的一行「增量重配进行中（pid …）」。人原话：「做任务的时候缺乏状态提示、UI不告诉用户在干什么，这是非常大的问题」。

**目标**：活跃期有作业在跑（或排队）时，顶栏下方出现一条全宽常驻作业条：转圈 + 「正在运行」+ 命令 + 已运行时长（每秒走）+「看进度」；作业结束即消失。

## 四、明确不做

- **跨期作业**：作业数据只来自活跃期的 `events.jsonl`（宿主只订阅活跃期）。切到别的期时，前一期在跑的作业不在条上。要做须让宿主轮询所有期的事件文件或扩期摘要，代价另算。**重启条件**：真实使用中出现「切了期就不知道上一期还在跑」一次。
- 进度百分比 / 逐段进度：作业事件里没有进度（`job_heartbeat` 是预留枚举、从未发出），不编造。
- 终止作业按钮：不在本条范围（终止是写操作，另议）。
- 对话侧运行指示：D46 已有，不重复。

## 五、测试

- vitest：`fold` 的 `startedAt`；`jobBar` 的排序、时长格式（含 >1 h、时钟回拨返回 null）、`check_script` rc=1 判「未通过」而 rc=2 / 其他命令 rc=1 照旧 failed。
- e2e（`desktop/e2e/stopPoint.spec.ts`）：夹具期写一条 running 作业（pid = 活进程）+ 一条 check_script rc=1：作业条可见、文案含命令与 `m:ss`；点「看进度」后预览区展开、时间线展开；时间线显示「未通过」且「失败」计数不含它；作业写入 `job_finished` 后作业条消失。底线断言（UI 规则 5）：1280×800 与 1440×900 下作业条与顶栏、侧栏、对话区 boundingBox 不相交，`scrollWidth <= clientWidth`。
- 变异：作业条不渲染 running / 不渲染 pending / 「未通过」判据放宽到所有 rc=1，各自应被抓。
