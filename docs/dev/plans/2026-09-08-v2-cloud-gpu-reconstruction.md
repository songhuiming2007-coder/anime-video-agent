## 一、 为什么必须推翻妥协？（重构核心动因）

### 1. 荒谬的资源错配：高维 Token 在给低维算力擦屁股
截至 2026-09-08，本项目已累计消耗 **15 亿 Token、8,192 次 LLM 请求**。分析证明，超过 **80% 的 Token** 并非用于文案创作，而是消耗在**为 16GB Mac 本地算力缺陷擦屁股**上：
- 陪 1.7B 自回归小模型反复排查“全部→权部”、“世界→逝戒”等 CJK 同形字音读泄漏，反复修改错别字和重试随机种子；
- 因本地缺乏视觉大模型（VLM 失明），Agent 被迫将几万行的 `04-shots.json` 裸吞入 Context 人肉计算镜头起止时间，排查 `anchor_overlap` 冲突。

### 2. 题材跃迁的业务断层：杂谈 80 分 vs 纪录片 50 分
现有流水线在制作《春物》《天气之子》等动漫杂谈时可达 **75~85 分**(我自己粗略评价)，因为原番自带“台词即画面”的强绑定红利；但在制作《EGOIST 编年史》等深度音乐史与文学纪录片时，评分暴跌至 **50~60 分**(我自己粗略评价)：
- **台词脱节**：纪录片讲客观史实与命运张力（“合同只有六个月”、“女孩窒息在黑幕”），原片根本没有对应台词，字幕检索覆盖率为 0%；
- **异构素材**：从单番 MKV 扩张为跨番混剪、Live 现场、实体扫图微动、音画同源原声，机械时间轴碰撞频发；
- **意象通感**：纪录片需要“窒息落寞”、“万人狂热”的电影级意象蒙太奇，基于字符串字面相似度的算法根本无法理解。

### 3. 经济学账本彻底打破心智门槛
- AutoDL 租用 24GB 显存的 RTX 4090 仅需 **1.98 ~ 2.2 元 / 小时（约 0.036 元/分钟）**；
- 包机连续实验 1 小时也不过两块钱；
- 相比于购买万元物理工作站或消耗数以亿计的高价值 LLM Token，云端弹性 GPU 是绝对的压倒性选择。

## 四、 施工改动清单与技术选型

### 1. 配音模块重构 (`pipeline/tts.py`)
- **废弃**：`mlx-audio` 纯苹果后端绑定、`readings` 错别字字典、`segment_seeds` 探针；
- **引入**：**IndexTTS2**（B 站 2025-09 开源，Apache 2.0）为主选——音色与情感解耦（情感可用参考音频/向量/文本描述独立控制）、时长可控（配音对齐时间轴）、零样本克隆；**CosyVoice 2.0** 备选；
- **音色资产**：优先零样本克隆 `seg6.wav` 及干净原声；LoRA 微调仅作音色不达标时的兜底；
- **注音**：挂载标准 `pypinyin` 规则库，输入端全部转为标准音素拼音嵌入；
- **韵律验收（2026-09-10 基线反馈新增）**：首期试看反馈证实「无起伏、无情感」是独立于音色与错字的第三硬伤，选型验收必须包含情感/韵律测试用例，否则 v2 配音依然不及格。

### 2. 视觉多模态索引引擎 (`pipeline/vindex.py`)
- **废弃**：已证伪的 Chinese-CLIP 余弦搜索、死板的单帧二次元 tagger；
- **引入**：**`Qwen3-VL-8B-Instruct`**（FP16 约 19GB，4090 24GB 可跑；预算紧退回 Qwen2.5-VL-7B AWQ）；
- **逻辑**：在 `shots.build` 之后，将每个镜头代表帧送入 Qwen2-VL，生成 30 字以内的紧凑画面特征（时间、地点、人物动作、光影色调、情绪张力），存入 `shots.captions.json`，并由 `bge-m3` 建库。

### 3. 视频修复扩展 (`pipeline/enhance.py` 新建)
- 封装 `real-esrgan`，针对低于 1080p 的素材提供可选的 4K 超分通道（老番/扫图画质是已验证痛点，保留）；
- 【降级为可选增强 2026-09-10】`demucs` 分轨暂不进核心路径：试看/BGM/试听三大场景均不需要，仅当 Live 人声提纯或「伴奏垫解说→原版进试听」需求出现时再启用。

### 4. 数据存储与传输方案（2026-09-10 新增）
- 云端 GPU 硬盘空间相对有限，必须为素材数据、模型参数、返回结果分别制定存储与传输方案，在速度与容量之间取得平衡；
- 当前可用存储：2 个 Google 账号的 Google Drive（各 5TB）、1 块 1TB 本地硬盘、云端 GPU 赠送的免费空间。

### 5. 素材搜集与评估自动化（2026-09-10 新增）
- 纯动漫素材时代，搜索下载是人工时间活（Telegram 群组找种子 + 长时间等待下载）；
- 随着素材多样性与复杂性上升，应建立 **Agent 自动化搜索下载素材的机制**，并配套素材质量的评估机制。

## 五、 实施计划与推进步骤

> **核心决策：宁缺毋滥，停止 v1 妥协交付，直接启动 v2。**  
> 前两期成片受限于本地算力与检索机制，未达预期标准。纪录片作品不容马虎，坚决不把不好的视频做出来；第三期《终局葬礼》不再用旧流水线妥协硬凑，直接基于 v2 云端架构打造高质量成片。

- **实施步骤**：
  1. **第 0 步（先于一切重构）：建立系统的评估（Evaluation）机制。** 没有评估，就无法判断一次改动的提升源于设计本身还是随机波动；评估把 Agent 迭代从经验判断转化为可比较、可复现的工程过程，是以科学方法做系统开发的基础。急着重构只会浪费 GPU 资源——动工前必须先讨论并定义评估标准：怎样的素材搜集丰富程度算丰富、怎样的排片算切中要害。**评估依托 v1 现有成片建立基线**：第一交付物极小且可验证——前两期成片的人工评分表 + 一页可执行判据清单（首批基线数据见第六章）；
  2. 以 git worktree 开出独立工作区并新建分支（`git worktree add ../anime-video-agent-v2 -b v2-cloud-gpu`），隔离开发并共享完整 git 历史；
  3. 在 AutoDL 开设 RTX 4090 镜像容器，搭建 PyTorch 2.x + CUDA 12.x 环境；
  4. 依次移植并验证：IndexTTS2 配音通道、Qwen3-VL 镜头打标通道；
  5. 跑通全自动端到端 11/11 验证，直接承接《EGOIST 编年史》第三期的高质量制作。

## 六、 v1 基线评估（2026-09-10：首期人类反馈）

前两期《EGOIST 编年史》成片的好友试看反馈 + 作者复看自评，是评估机制的第一批基线数据：

| 反馈 | 根因分析 | 对应工单 / v2 解法 |
|---|---|---|
| 配音音色尚可，但无起伏、无情感，没有听下去的欲望 | TTS 韵律（prosody）缺失——与音色、错字是三个独立维度 | D23；四.1 已补韵律验收要求 |
| 文案涉及现实生活/实际场景时，动漫画面过多 | ① 现实素材太少；② 无视觉能力，排片只能按台词字面碰撞；①间接加剧② | D2/D4/D5/D22；四.5 素材自动化搜集 + Qwen3-VL 视觉索引 |
| 配音费时费力，同时消耗本地硬件生命与人类生命 | 16GB Mac 本地算力天花板 | 一.3 经济账本；云端 4090 算力池 |
| 作为纪录片，现实素材少、翔实程度不够 | 素材搜集目前是纯人工时间活 | 四.5 素材搜集与评估自动化 |

**结论**：三条反馈命中 v2 已有解法（方向被现实数据确认）；一条暴露盲区（配音韵律），已回补进四.1 选型验收。
