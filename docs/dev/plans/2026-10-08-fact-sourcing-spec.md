## 这次做了什么（不加工具、不改机检）

人不在场时自主裁决（2026-10-08 夜，人授权「能修的自己决断，要人定的搁置」）。只动提示词，因为两条事故的直接成因都是「规则没写到」，而补规则不改任何行为边界：

1. `director.md` §5「剧情事实注明出处」扩成：谁说的、谁在场、在哪、做了什么、什么神态都算剧情事实；字幕不带说话人，所以说话人与在场人物没有笔记或人给的材料就是「未核实」；被人指出事实错时**先查再改**（整集台词 → 笔记 → web 分集剧情），查不到就说查不到、请人看片，不换一个猜测再交（D54 成因 ①，及四轮「认错 + 新版本」）。
2. `creative.md`「交稿前的因果自查」加两条：锚点时间码只写查过的（字幕查到的那句、或笔记写明的时间码），查不到写 `锚点: 无（字幕里查不到，待人看片）` 走检索，不凭记忆估（D55 方向 ③）；改了配音以外的字段（锚点、查询、备选）在回复里写明「段 N 锚点 旧 → 新」（D55 方向 ②，覆盖旧进程只能写草稿、人手工同步时丢改动的情形）。

## 实测：锚点机械核对会误伤（D55 方向 ①，未施工）

设想：锚点段的「查询 / 备选」凡是字幕原句（归一化后整句相等，或 ≥5 字的包含关系），其时间码应落在 `[锚点 − 15 s, 锚点终点或锚点 + 配音字数 / 7.2 + 15 s]` 内，不在就报。

对 `data/episodes/` 全部现存稿件只读实跑（脚本在会话 scratchpad，不进仓库）：**可核对 73 条，窗口外 12 条（16%）**。抽看窗口外的样本，多数是有意为之，不是错：

- 画面取开场、台词引片尾重复的同一句独白（《你的名字》段 1：锚点 00:57，台词在 93:20 再现）；
- 台词比锚点晚 20–30 s，画面要的是说这句之前的镜头（《罪恶王冠》段 2：18:02 / 18:31）；
- 画面与台词刻意取自同集两处（《伪恋》段 4：15:25 / 06:08）。

董香二期段 3 的事故（锚点 06:12、便当戏在 04:31）本身**抓不到**：它的「查询」「备选」都是描述句，不是字幕原句。

结论：做成机检失败项会让一批过审稿件变红，且抓不到这次的事故；做成「只提示」也有 16% 噪声。**交人定**：不做 / 只提示 / 失败项（推荐不做，靠上面第 2 条规程 + 05 审时间码兜底）。
