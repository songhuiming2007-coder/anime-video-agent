## 起因（人原话，2026-10-08）

1. 「很显然没有渲染，让人看着很费劲」——助手回复里的 `**粗体**`、`- 列表`、`---` 原样显示成符号。
2. 「工具调用结果不要自动展开，占空间太大了，看着难受」——check_script 退出码 1 时，整段 JSON 原文默认铺开在对话流里。
3. 「现在模型思考、调用工具的时候 UI 没有动感，让人不知道到底动没动」——唯一的运行指示是会话头角落的小转圈，对话流末尾没有任何变化；回复是整段到达的，模型生成期间对话区完全静止。

## 修订的旧规则

| 旧规则 | 修订 | 理由 |
|---|---|---|
| Spec 10 §2.3 / Spec 9 H-3：助手回复纯文本，不渲染 Markdown | 助手回复（`answer`、`wrapup`）渲染 Markdown；**卡片字段、本地说明、工具原文仍是纯文本** | RF-13 留的口子：「若要 Markdown，须另提修订并证明渲染器不能产出可点击控件」。证明见下节 |
| Spec 10 §2.3：非成功调用默认展开 observation（当时的用户裁决） | 默认收起，点开仍逐字、不截断 | 人新裁决。失败仍由行首红色图标标出，原文一处不删，只是不再默认占版面 |

## H-3 的前提为什么仍成立

H-3 防的是模型文本变成可点的东西（假批准按钮、外链、表单），或者让渲染器去加载外部资源。聊天渲染器 `ChatMarkdown` 比文件预览的 `MarkdownBody` 再收一档：

- `html: false`：原始 HTML 一律转义成文字（`<button>` 显示为字面量）；
- 关掉 `link`、`autolink`、`reference`、`image` 四条规则：`[文字](url)`、`<https://…>`、引用式链接定义、`![](…)` 全部按字面文字显示，**输出里不可能出现 `<a>` 和 `<img>`**；
- `linkify: false`：裸网址不变链接；
- 仍是 `markdown-it` 的输出，只在 `PreviewPane.tsx` 里持有（TG-13 不放宽）。

剩下能出现的元素只有标题、段落、强调、列表、引用、代码、表格、分隔线，都不可点击、不加载资源。测试逐条喂恶意输入（HTML 按钮、各种链接写法、图片、`javascript:`），断言输出里没有 `<a`、`<img`、`<button`、`<input`、`<form`、`<iframe`、`<script`。

## 施工内容

| 项 | 落点 | 内容 |
|---|---|---|
| A 回复 Markdown | `PreviewPane.tsx::ChatMarkdown`；`ConversationPane.tsx`；`style.css` | `answer`、`wrapup` 用 `ChatMarkdown`；`local_note`、卡片、用户消息不变。补列表、引用、表格、分隔线的样式，只用 token |
| B 原文收起 | `ConversationPane.tsx` | `<details open>` 去掉 `open` |
| C 运行中有动静 | `ConversationPane.tsx`；`App.tsx` 传入 `running`、有无待答卡 | ① 执行中的工具行图标换成转圈（只在回合运行时转，回合已结束还没收到结束帧的行不转）；② 回合运行、没有待答卡时，对话流末尾一行「模型思考中 · N 秒」或「工具运行中 · N 秒」，N 从最后一行到达起每秒走一次。系统开了「减少动态效果」时转圈停，秒数照走 |

秒数起点：最后一行到达的时刻；最后一行是已结束的工具行时取它的结束时刻（`at + durationMs`），否则工具耗时会被算进「模型思考中」（首版截图里 4 秒工具 + 2 秒生成显示成「6 秒」，已修）。
