# ADR-0002：配音走本地 MLX + IndexTTS-1.5，解码循环自己写

日期：2026-07-29
状态：已采纳（决定二/三已被 ADR-0006 取代，2026-08-15 换引擎 Qwen3-TTS；本文件保留作 IndexTTS 时代的历史证据）

## 背景

配音要把稿件变成逐段音频，并交出**每段真实时长**——它是排画面轨的唯一依据。
（本文写于旧编号，当时 配音=第 05 步、排画面=第 06 步；现行编号 配音=03、排片=04，见 `docs/STANDARD.md` 十。）
候选是本地模型与云 API 两条路。

## 决定一：本地，不用云 API

- 云端按字计费虽便宜（一期约几毛），但它把一条**必须联网、有账号、有配额**的依赖
  放进了每期主循环。本项目的交付物是流水线本身，多一个外部依赖就多一处会在半夜挂掉的地方。
- 声音克隆要把参考干声传给第三方，这件事本身也不该常态化。
- M4 / 16G 跑得动 1.4G 的模型，实测 0.3–0.8× 实时，机器时间不占人类预算。

代价：模型 1.4G 落 SSD，首次下载慢（实测约 850 KB/s，25 分钟）。一次性成本，接受。

## 决定二：引擎 = IndexTTS-1.5（mlx-community 转换版）

同期看过的三个：

| 候选 | 结论 |
|---|---|
| IndexTTS-2 | mlx-audio 0.4.6 **不支持**，装不上。已下的 4.4G 是废的（见下） |
| VoxCPM 1.5 | mlx-audio 支持，但要 ref_text，且中文表现未实测 |
| IndexTTS-1.5 | mlx-audio 支持，中文口播自然度够用，1.4G，**采纳** |

引擎是接缝：`config/voice.json` 改一行即可换，不动流水线。

## 音色：audio_03（2026-07-29 选定）

八条参考干声各生成同一句话，听选。**判据按语速优先、音色最后**——语速决定成片长度，
而时长与播放量负相关，是三项里唯一有数据支撑的。

一个反直觉的实测结果：**单句试音不能预测整篇语速。** audio_03 在试音句上比 audio_01
慢（6.52s vs 6.22s），跑完整篇却快 12%（122.5s vs 139.5s）。选音色可以听单句，
但要估成片长度**必须看 `manifest.json` 的总时长**。

## 决定三：IndexTTS 的解码循环写在我们自己的仓库里

**这是本 ADR 最重要的一条，改动前必须读完。**

mlx-audio 0.4.6 的 `indextts.Model.generate()` 有两处错：

1. `start_mel_token`（8192）被塞进 `text_embedding` 查表——它属于 mel 码本，
   应走 `mel_embedding`。因为 8192 落在文本词表 12001 的范围内，**不会报错**。
2. mel 位置编码从「前缀长度」起算，应当从 0 起算。

失败是静默的：模型照样出声，只是念漏字、提前收口。2026-07-29 实测：

```
model.generate()      「这不叫牺牲，这叫止损。」→ 念成「这不叫止损」  1.3s  CER 44%
自己解码（本仓库）     同一句                    → 完整               2.65s CER  0%
```

温度、种子、参考干声都换过，全都无效——这不是采样问题，是输入拼错了。

修正版在 `pipeline/tts.py:_indextts_audio`。**不要"简化"回 `model.generate()`。**
上游修好之后可以删掉它，但删之前先跑 `python -m pipeline.tts probe` 对比 CER。

## 质检：每段回读

自回归 TTS 的典型失败不是抛异常，是把一句念成两遍、或者跳掉半句。所以每段生成后
用 Whisper 回读，与原文比编辑距离；不过就换种子降温重生成，三次仍不过**整体失败退出**，
不把坏音频留在盘上（CLAUDE.md「诚实失败优于凑合交付」）。

判据是**错数 ≥ 3 且 CER > 20%** 两条同时越线。只看比率会冤枉短段落——十个音节的段落
被 ASR 听岔一处就是 10%。实测 ASR 自身在干净 TTS 音频上的同音字错误约 5–8%
（「八幡」→「八番」「自爆」→「自报」），这不是 TTS 的问题。

### 比对在拼音上做，不在字形上做（2026-08-03 修订）

原先比的是字。**那样量到的是「ASR 认不认识这个词」，不是「TTS 念没念对」**，
而春物通篇是日文专名，Whisper 逐个听成同音字：户冢彩加→户种采家、川崎沙希→穿其沙西、
比企谷小町→比奇古小丁。长段落靠字数把错误率稀释掉，短段落直接顶穿——
2026-08-03 一句 14 个字的短句 3 处错、CER 21%，重试三次全一样，整期退出，
**而音频完全正确**。

修法不是扩充同音字表（这次是「户种」下次是「户中」，穷举不完），
是换维度：`cer()` 比对前两边都过 `tts.syllables()` 转**带声调**拼音。
声调必须留——去掉能多消几处误报，但会把「得 dé」和「地 dì」折成一个。
漏读、重复、跑飞改变的是音节数量与顺序，拼音照样抓得住。

单位因此从「字」变成「音节」，两个阈值的量级不变（中文一字一音节）。
新增依赖 `pypinyin`。

## 决定四：按句合成 + 裁掉句尾的机械声（2026-07-29 增补）

第一版整段合成，交片后人耳听出两个问题，都不是回读质检能发现的。

### 语速与文本长度正相关

实测 21 段，语速与字数相关系数 **r = +0.613**——文本越长念得越快，因为模型对整句时长
有先验，长文本就压着念。段 17 单独验证：

    整段 82 字一次合成   14.46s = 5.67 字/秒
    拆 4 句分别合成      20.22s = 4.05 字/秒

改成**按句合成**（句号断句，单句超 30 字再按逗号断），裁掉每句自带的首尾静音，
用固定 `SENT_GAP` 拼起来。改后 r 降到 +0.310，标准差 0.57→0.46。
**改善是有限的**：极差从 1.55× 只降到 1.52×，句子内部仍有各自的时长先验。
再往下按字数硬拆会伤韵律，到此为止。

### 句尾的机械声（低频闷响）

**IndexTTS 在停止符附近会吐出一段条件不良的帧，BigVGAN 把它渲成约 100ms 的低频闷响。**
58 句里 55 句都有。频谱是它的指纹——话音结束、安静约 100ms 之后，最后 100ms 又冒出能量：

    区间             0-200Hz  200-500  500-1.5k  1.5-4k   4-8k   8-12k
    句中（正常语音）     109      109       92      99     101     95
    句尾前 200-100ms    82       84       63      50      43      37
    句尾最后 100ms     106      108       96      96      87      77

低频回到接近正常语音，高频比正常语音低 15–20dB。**低频足、高频缺**，听感就是「登」。

按响度裁不掉（它够响，不算静音），得按形状认：**主体语音 → 一段明显的谷 → 又冒起来 → 结束**。
`_tail_artifact` 找最后一段 ≥40ms 且低于峰值 12% 的谷，谷之后若还有东西就从谷处切。
判据是**谷之后那一截有多长**（≤250ms 才算机械声），不是它有多响——初版用响度卡
（要求冒过峰值 50%），漏掉了只冒到 29–45% 的那些，而人耳照样听得见。

裁剪必须排在回读质检**之前**。判据是启发式的，万一切进句尾真实的字，只有回读能发现。

## 这个 bug 花了六轮才定位，方法上的教训

前五轮改的全是拼接层：段落边界淡出、句子边界淡出、线性改余弦、消除补丁的 2ms 漂移、
排查 AAC 预回声。这些改动本身没错（包络阶跃确实存在，最响处从 27542 降到 247），
**但都不是人耳听到的那个声音**。

走弯路的根因是：**判据在人的耳朵里，而我只有测量。** 于是反复出现「测了个数值变好了，
人听着没变化」。中间还拿错过尺子——用逐样本跳变去测低频闷响，得出「边界比正常语音
还平滑」的结论，与事实相反。

转折点是两条来自人的信息：

1. **「短句几乎念完就有」** —— 把范围从「拼接处」挪到「每次合成结束时」
2. **一组 A/B 试听**（TTS 直出 vs 成片）—— 人回答「四个文件全都有」，
   一句话排除了整条渲染链，锁死在 TTS 内部

**结论：判据在人的感官里时，第一步就该做 A/B 让人听，不要先自己测量猜。**
测量只能验证已经定位的假设，不能替人定位。这条同样适用于画面贴合度、节奏、观感。

## 顺带修掉的事：模型往内置盘漏

HuggingFace 默认把权重下到 `~/.cache/huggingface`，即内置盘，违反 CLAUDE.md
「模型一律不落内置盘」。发现时那里已经积了 1.0G。

`pipeline/paths.py` 在 import 时把 `HF_HOME` 钉到 SSD——但**光这样不够**。
`huggingface_hub.constants` 一旦被 import，缓存路径就算死成常量，之后改环境变量无效。
`mlx_audio` / `sentence_transformers` 这类库 import 时就会触发它。于是「先 import 第三方库、
再 import paths」的文件里，钉盘完全失效且没有任何报错。当天就这么又漏了 2.6G。

所以 paths.py 还会检查 `sys.modules` 里 constants 是否已被别人定死，是就当场退出。
**`from . import paths` 必须排在所有第三方 import 前面**，顺序错了会立刻报错，不会再静默漏盘。

## 遗留

- `data/models/hub/models--mlx-community--IndexTTS-2-fp16` 4.4G 当前无法使用，
  等 mlx-audio 支持 IndexTTS-2 再说；要腾空间就先删它。
- 下载走 `huggingface_hub` 会卡住（xet 通道），改用 `curl -C -` 直连 CDN 才稳。
  模型目录因此是 `data/models/local/<名字>/` 的平铺结构，不是 HF 缓存布局。
