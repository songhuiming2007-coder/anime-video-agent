# ADR-0005：排片错配的核心缺陷是「文本表面相似度」代替不了「语义理解」

日期：2026-08-10
状态：**诊断已确认（有代码证据），修复方案未选定**——本文只记诊断过程与结论，
不含已实现的改动。LLM 候选复核是目前唯一在讨论的方向，接口怎么接、
接在哪一步，都还没定，见文末「候选方向」。

> 本 ADR 的起因：本期（罪恶王冠·楪祈人物志·一）`04-clips.json` 自动检索出的结果里，
> 5 个 clip 经人工核对判定画面对不上台词（`_manual_fix` 注记见该文件），逐一靠
> ffmpeg 抽帧手动改了 `start`。用户随后问：分集信息（`集:` 字段/ADR-0004）和
> 人脸检测（presence/ADR-0004）都已经在跑了，为什么还会错得离谱。
> 下面是这次追问推出的四轮判断，逐条记录，不做事后包装。

## 人类视角：人是怎么给文案配画面的（作者补记，2026-08-12，非本 ADR 结论）

我作为一个人类，从人类的角度来审视排片这一工作，大概顺序是：
1. 看一段文案，理解它
2. 寻找与文案最匹配的情节
3. 匹配画面

那么，现在 agent 排片做不到精确度，我觉得问题可能出在：
1. 不理解文案对应的最适配的剧情
2. 对剧情的笔记不够详细，没有到达分钟级的精细程度
3. 无法理解画面意义
4. 经常被台词和流水线误导，去选择差强人意的画面

> 这条是作者的观察视角，供后续方案评估参考，不替代下面的正式判断。

## 实测印象：错配分布（作者 05 审核观察，2026-08-12，待量化）

每期排片约 20 个片段：约 **6-7 个是检索台词这步就没适配的**——流程是先检索台词、再按台词切画面，
而检索经常找不到真正适配的台词，只能在结果里矬子里拔将军（屎上雕花），找一些很模糊的台词凑合，
画面随之随缘；3-4 个勉强相关，余下才真正切中剧情。这是 05 人工审核的累积印象，**不是测量值**。
精确错配率可从历史 `04-clips.json`（机器出）vs `04-clips.approved.json`（05 人改过）
的 diff 量化，并按「错配主因」（查询写错 / 语义撞车 / 候选池无正确答案）分桶；外置盘可用时回填本段。

对「候选方向」的约束：约三成候选是检索层产出的垃圾，复核只能把它们的 status
判成 `no_match` 交人，**不能凭空生成正确画面**——它降低「错配混进成片」的概率，
不降低 05 的人工负担。

## 判断 1：先定位问题范围

当前几期做下来，最大的两处问题是**文案**和**排片**。本文只处理排片这一半。

## 判断 2：追问「notes 和人脸检测都有了，为什么还会错」

带着这个问题去读 `pipeline/clips.py` 实际代码（`_ladder` L299、`scene_no_match` L341、
`_ladder_scene` L367、`_by_character` L395），结论是两者都没有在做直觉上以为它们在做的事：

- **分集剧情笔记（`data/library/*/笔记`）在 `clips.py` 里被引用次数为 0**
  （`grep -n "note\|笔记\|library" pipeline/clips.py` 无匹配）。笔记是 02 写稿阶段
  人/agent 用来核实剧情、找台词出处的参考文档，检索代码对它一无所知，
  排片时唯一看到的输入是字幕文本本身。
- **人脸检测（`_by_character`，L395）不是过滤器，是候选池内一个很窄的 tie-break。**
  它只把候选列表里文本分差 ≤ `PRESENCE_BAND`（L60，实测标定 0.06，见 ADR-0004）
  的相邻候选按在场分重新排序，够不着排在更后面的候选，也没法把 Top-K
  （`_ladder` 的候选池）里根本不存在的正确镜头凭空拉进来。
- **`_ladder` 的排序阶梯是「只救不比」（L299 起，判据 10）：** 查询→备选→配音原文
  逐级试，第一级 top-1 只要过 `NO_MATCH = 0.45`（L40）就立刻锁定，
  **不会因为换一层能拿到更高分而继续找**。一个「勉强及格、语义沾边」的候选
  会在真正匹配被发现之前就被锁死。
- **`集:` 字段/ADR-0004 只缩小检索范围**（集→季→全空间降级链），不保证范围内选对——
  同一集里可能有好几场戏用词口吻相近。

## 判断 3：提三条最小成本改法，逐条评估（结论：都不成立或收益有限）

| 提案 | 评估 | 结论 |
|---|---|---|
| 优先去剧情相关的那一集找 | 已经存在（ADR-0004 的集→季→全空间降级链），真正的缺口是**集号从哪来**——它是 02 写稿时人工填的，不是 notes 自动喂给 clips.py 的 | 纪律问题，不是功能缺失 |
| 人脸检测权重调大 | presence 回答的是「谁在画面里」不是「在演什么」；调大权重最可能把错误从「文不对题」换成「人对但事不对」（这个人确实在画面里，但演的是完全不相关的另一场戏）——是把同一个病换个样子，不是治好 | **不采纳**，违反判据 10（分数只在自己通道内排序，presence 是唯一例外且被写死为窄带 tie-break） |
| 番剧笔记做到分钟级 | 真正的逐句时间戳数据（`.ass` 字幕）早就存在，`subindex.py` 建索引就建在这上面；02 写稿的「引用核对」已经在逐句核对字幕原文。notes 是摘要，从来不是检索的直接输入，做细能减少「凭印象编错剧情/说话人」这类低级错误，但救不了本身没有台词的镜头（检索入口从头到尾只有台词文本） | 收益有限，优先级低 |
| 放弃视觉模型，视觉太吃硬件 | 结论方向对，但记错了理由：ADR-0003 拒绝全自动视觉通道的记录理由是**阈值不稳定**（探针测不出可靠的 `no_match` 门槛），不是硬件不够；这个区分决定了还有没有「按需轻量复核」式的中间方案可走 | 结论采纳，理由修正 |

## 判断 4：推翻前三条，抓到真正病根

> 这是本 ADR 的核心结论，前三条判断都是围着它打转的找补。

`subindex.search` 用的是 **bge-base-zh-v1.5，一个双塔（bi-encoder）嵌入模型**：
查询文本和每条候选字幕窗口是**各自独立编码成向量**，再算余弦距离。它结构上没有
「读上下文」这回事——候选窗口前后发生了什么、这句话是回应谁的、代词指的是哪场戏
里的哪件事，这些跨句/跨场景信息双塔模型根本看不到。余弦分数高，至多证明
「用词/语气/主题相近」，从未证明「这就是那一刻」。

**前三条提案都是在这个核心缺陷的外围打补丁：**

- 集号锁定：缩小了「表面语义相近的候选」要在哪个范围里挑，没让「挑得对不对」变得可靠
- presence 加权：换一个独立于文本的信号帮着挑，但这个信号答的是另一个问题，跟
  「这段词是不是在讲这件事」无关，纯属旁路
- notes 加细：给人更多参考，不会让 clips.py 这台机器多理解一个字

## 唯一没解的死角

如果被叙述的那一刻本身没有台词（例如本期抽帧确认的翻花绳镜头），候选池里
**从一开始就不存在正确答案**——不管排序机制换成嵌入相似度、presence tie-break，
还是候选复核，都是在一堆错误候选里矬子里拔将军。这种情况唯一的解是写稿阶段
（02）先用 `subindex.search` 确认有没有台词，没有就显式标注、人工指定
`start`/`source`，而不是指望检索环节凭空生成语义。这条建议来自判断 3
里被认可的部分，不属于本次否掉的三条提案。

## 候选方向（未决定，不是本 ADR 的决定）

真正对症的改法方向是**把「比相似度」换成「判断力」**：在 `_ladder()` 已经吐出的
候选列表（每条候选自带时间戳、前后字幕上下文）之后，加一次真正会读的模型
复核——把口播原文 + 每个候选连同前后几句字幕上下文一起交给它判断
「哪个候选实际讲的是这件事，还是都不是」，而不是继续让余弦分数做这个判断。

这个方向比视觉模型（ADR-0003 已否）便宜：纯文本、候选数量有限（TOPK 量级）、
不需要给全语料库建索引，只对检索之后已经收窄的候选做一次性判断，量级上属于
「屎上雕花」而非「力大砖飞」，硬件上站得住。

**尚未决定、需要单独立项判断的问题**（比照 ADR-0003/0004 的先例，动手前应先写方案）：

1. 接在哪：`clips.py` 内部自动改写结果，还是作为 05 审图页的辅助提示、不碰自动结果——
   这两种接法对「人是唯一关卡」（CLAUDE.md 六、每期九步）这条原则的影响不同
2. 复核不通过（模型说「都不是」）算什么状态——是回退现有排序结果，还是提升为
   `no_match` 交人处理
3. 判据 10「分数只在自己通道内排序」是否适用于「复核结果」这个新产物——
   它不是分数，是布尔/离散判断，理论上不受这条判据约束，但要不要引入新的
   「复核意见 vs 检索分数冲突时听谁的」规则，需要显式写清楚，不能悬着
4. 成本与效果的实测——按 ADR-0003/0004 的纪律，动手前列好探针（一批已知正确/
   错误的历史 clip，跑复核看能不能分辨），不能「先上了再看效果」

## 文案侧通病：不核剧情 + 机检越权（2026-08-12 楪祈人物志·二复盘补记）

> **本次复盘暴露的主要是文案问题，与排片无关**——排片病根在判断 4，这里不重复。
> 补记想表达的和判断 4 同源：**机检和余弦一样，只能证伪它自己那一个通道，管不了内容**。
> 但具体病状全部发生在写稿/改稿/机检边界上，单独记，别混进排片。

### 当天实录（五处，均已处理，全部属文案环节）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 段落 1 剧情写错：稿子写「祈在学校拦住供奉院动手打了她」，subagent 核查实为广播室 + 真名人格 + 虚空结晶 | agent 凭印象/二手转述写剧情，没先核「这一集到底演了什么」 |
| 2 | 段落 2 漏掉黑化导火索（校条祭之死），而画面备选台词「祭的死 全是你的错」明明挂着答案 | agent 不读自己素材表里的线索，凭想当然补因果 |
| 3 | 段落 7 前情缺失：直接从「我就是我」跳到「她去找集告别」，读者不知道涯斩臂、集失力 | 同上，没做「这集前情是什么」的确认 |
| 4 | `anchor_words` 机检逼正文写「第X集」凑锚点数，删集数后掉到 2 处判失败 | 机器判据反过来决定内容，方向反了（已整个删掉，见 commit 56361a1） |
| 5 | 强制保存后只跑一遍 `check_script` 就以为完事，被指出「你居然不检查」 | 把「机检全过」当成「内容对」 |

### 归纳

- **文案内容没有任何自动兜底，全压给 02.5 人抓**：agent 生成的每个叙事性断言（谁在哪
  做了什么）都是凭印象写的，没有一步核对字幕/说话人，机检也管不了。
- **机检在反过来逼内容**：锚点检查逼正文写集数、具名场合词，等于让机器决定内容——
  与「剧情和文字由人审」的定位相反。已删（56361a1）。
- **「机检全过」≠「能交」**：改稿后跑绿不读内容。

### 对流程的约束（本补记的结论）

1. **机检只做机器能证伪的**：格式、字数、查询命中、检索门槛。剧情、说话人、文字像不像人，
   一律归 02.5 人审；机检不再用任何判据去逼正文内容。
2. **agent 写稿时对每个叙事性断言先核字幕索引**：查得到台词/说话人就写，查不到就显式标
   「待 02.5 确认」，不许凭印象落笔。素材表（备选台词）是线索，不是装饰。
3. **改稿后读一遍成品内容再走**：至少读开头和最长段落（对齐 CLAUDE.md「成片交人前至少
   听一遍」那条，落到写稿改稿层面），跑完机检不算数。

### 什么情况下推翻本补记

- 若 agent 写稿的事实核查能自动化到可证伪（如逐句对照字幕索引 + 说话人索引自动拦错），
  第 2 条可升级为机检项。在做到之前，内容只能靠 02.5，不接受机检代替。
