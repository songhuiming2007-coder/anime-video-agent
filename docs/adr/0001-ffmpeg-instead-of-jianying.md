# ADR-0001：放弃剪映草稿生成，直接用 ffmpeg 渲染成片

日期：2026-07-28
状态：已采纳

## 背景

原方案的合成阶段计划走"程序生成剪映工程文件 → 人在剪映里做最后 10-15 分钟微调"。
2026-07-28 对该链路做验证，结论是不可行且不必要。

## 不可行的证据

1. 本机装的是 **CapCut 国际版**（`com.lemon.lvoverseas` 7.9.0），非剪映专业版。容器为空，
   从未运行过，本地无任何草稿可供逆向。
2. `pyJianYingDraft` 只支持剪映中国版；CapCut 支持在另一个未完成的仓库。
3. 关键：新版本的 `draft_content.json` **常为加密而非明文**，"生成 JSON 工程文件"
   这一前提在新版上不成立。
4. 该格式属字节闭源资产，且厂商有持续加密的商业动机。依赖它等于把流水线终端
   建在会主动破坏兼容性的目标上。

## 不必要的理由

人类时间预算是 ≤15 分钟/期，而剪映微调本身就要 10-15 分钟——**单这一步吃掉全部预算**。
项目已决定牺牲文案质量上限换时间（见 CLAUDE.md），同一取舍贯彻到底，剪辑同样不应
消耗人类时间。保留剪映在逻辑上不自洽。

## 决定

合成阶段全程无 NLE，由 ffmpeg 一趟渲染出可直接上传的成片。

## 验证结果（2026-07-28）

ffmpeg 8.0.1，带 libass / libfreetype / libfontconfig。端到端探针实测：

```
seg1: 请求 3.2s 实得 3.200s 偏差 0.000s
seg2: 请求 4.5s 实得 4.500s 偏差 0.000s
seg3: 请求 2.8s 实得 2.800s 偏差 0.000s
音画偏差 0.000s      PASS
总时长偏差 0.000s    PASS
响度 -15.8 LUFS（目标 -16）
渲染 1s / 10.5s 成片（1080p30 crf20 preset medium）
```

抽帧复核截取精度：成片 5.0s 处显示源时间码 `SRC2 00:00:05.800`，
= seg2 起点 4.0s + 段内偏移 1.8s，帧级吻合。中文字幕烧录、BGM 混音、
响度归一在同一条 filter_complex 内完成。

## 探针发现的产线杀手

请求时长超过源片剩余长度时，**ffmpeg 静默截断且不报错**。检索命中集尾时必然踩到，
一旦踩到整条音画全线错位而无任何提示。

因此渲染阶段强制两道守卫，缺一不可：

1. **切之前**校验 `seek + duration <= 源时长`，不足立即失败
2. **切之后**复核实际时长与请求值之差 <= 1 帧（0.034s @30fps）

## 代价

放弃人工节奏微调，成片观感上限下降。与文案自动化的取舍一致，接受。

## 逃生舱

若某期确需精修，用原始素材手动重剪。**不为此保留自动化链路**——
按需手工处理的成本远低于长期维护一个会被厂商主动打破的格式依赖。
