# ADR-0004：排片先锁定集号再打分，presence 只做带内次级排序

日期：2026-08-09
状态：已采纳，已实现并验收（2026-08-09，本期「东京喰种-雾岛董香人物志-一」端到端跑通）

> 本 ADR 是**动手前**写的，和 0003 一样。文中凡是没有数的地方显式标了「待实测」，
> 实测后回填。最大的一处回填：计划时的 `PRESENCE_BAND=0.03` 是拍脑袋初值，
> **实测推翻**（噪声中位数是它两倍），回填为 `0.06`，证据见「实现与本文的出入」第 2 条。

## 背景

排片（`clips.py`）的查询在整个番所有季集的字幕索引上做 bge 语义打分，
**没有任何集维度的约束**。跨季/跨集的高分可以顶掉正确画面。

2026-08-09 实证（本期人物志，段落 19，讲雏实阻止董香复仇）：
正确的 S01E08 画面（0.653）输给了跨季的 S04E05（0.506）——错的画面分数更低，
但正确画面被挤掉了。

这次事故是三个因素叠加，缺一不可：

1. **检索无集约束**：查询可以在全番 40+ 集里找命中
2. **漏检被布尔过滤误杀**：段落曾写 `人物: 雏实`，正确画面 S01E08 因 presence
   漏检被硬性过滤掉（ADR-0003 的「漏检不剔除」原则在排片侧没落实到位，
   实现成了硬过滤）
3. **过滤池恰好非空**：跨季 S04E05 里雏实被检出、过了 0.45 门槛，
   于是「候补」成了「唯一」——**漏检误杀 + 过滤池非空**的组合，
   比「过滤池为空 → 退回」更隐蔽，因为它不退回、不报错，直接上错误的画面。

## 决定

四条，缺一不可：

1. **段落写 `集:` 字段，排片先按集过滤再打分。** 稿件分镜标注加
   `集: S01E07`（全库唯一规范形，`S1E7` 自动归一化）；`subindex.search`
   接受 `season/episode` 掩码，只在指定集内打分。集号是内容：
   从引用核对里查到的真实集号，不是 agent 猜测。
2. **降级链：集 → 季 → 全空间。** 集级检索不及格才放宽到整季，再不行才全空间。
   **末端 = 全空间 = 今天的行为**，所以 `no_match` 结构性不会变多。
   每一级降级都记录（`ep_scope` / `ep_fell_back`）并显示给第 05 步人审——
   降级是「回去改稿」的信号，不许静默。与「检索落空自动降级」红线的辨析见下。
3. **presence 从布尔过滤改为带内次级排序。** 不再硬性剔除漏检镜头；
   漏检镜头（在场分 0）照常进入候选，只是**垫底**。候选先按台词分排，
   台词分差 ≤ `PRESENCE_BAND` 的同一档内才用在场分决胜负。
   **结构上不可能顶掉清晰的台词命中。**
4. **check_script 校验集号。** 两道：格式（`S\d{1,2}E\d{1,2}`，永远可跑）
   和集号在素材库（延迟 import `ingest`，不在 → FAIL 并区分「集号写错」vs
   「整季没入库」）。**无 `集:` 字段不判失败**——人物志有已知落空的段落，
   强制每段写 = 逼人编集号；覆盖率只作信息报告。

## 为什么降级链末端是全空间，不是「就让它 no_match」

集号写错或检索不稳时，集级可能全部不及格。两条路：

- **末端硬失败**：集号锁死，集内检索不到就 `no_match`。好处是逼人回去改集号，
  坏处是**集号只是检索的加速约束，不是正确性的仲裁**——同一段台词在相邻几集
  都可能出现，集内检索不到不代表「这段没画面」，只代表「这句台词没在这集出现」。
- **末端全空间**（本决定）：相当于「集号是一层优先约束，锁不死就退到今天的行为」。
  `no_match` 不会变多（今天就是全空间），而集号写对时跨季错误被结构性消灭。

与 CLAUDE.md 红线「检索落空不自动降级」的辨析：红线禁的是**自动塞差素材 /
放低标准**——NO_MATCH 门槛 0.45 全程不动、三级阶梯不及格照样硬失败交人。
本设计的降级是**放宽检索范围**，不是放低分数标准；而且降级显式记录、显式显示，
不是静默。检索范围是「去哪找」的启发式，分数门槛是「找到的东西能不能用」的
判据，两者是正交的。

## 为什么 presence 是带内次级排序，不是加权

ADR-0003 写死了「一个量能用来卡门槛，不代表它能用来排序」——
跨通道分数融合是第五次坑。全量加权的错误是它造出一个**不存在于任何真实东西
里的复合分**：台词的 0.7 和画面的 0.7 长得像纯属巧合，融出来的排名照样存在、
照样单调、照样能取 Top-K，只是不对应任何真实的东西。

带内次级排序不造新分：**排序轴还是台词分，presence 只在「台词分无法区分」
的同一档内调整顺序**。它没有融合分数，只是把同一个轴的细粒度化——
同一个候选，台词分差 0.02 时谁上谁下本来就是噪声级的决定，presence 提供
一个比抛硬币好的次序。

边界（写死，不许踩）：

- **只在同一段落内、同一 producer 内比较**。presence 分数随 producer 量纲不同
  （ccip 的 1−距离 0.95–0.99 vs tagger 的概率 0.5–1.0），跨 producer 比绝对值无意义
- **绝不跨通道**：画面通道的候选不用 presence 排序
- **绝不跨段落**：全局贪心 pool 的排序键仍是台词分，presence 只影响段落内部顺序

**全量加权唯一的入口是离线评测**：拿一批人工标注的正确答案，证明融合排名
优于单通道排名。没有这个证据不许上——与 ADR-0003 的推翻条件同一句。

## 实测回填：PRESENCE_BAND

计划初值 `0.03` 是拍脑袋的（计划原文就标了「待实测回填，别拍脑袋」）。

**实测（2026-08-09，本期 20 段查询）**：每段查询写 2 个同义改写变体
（v1 词序/同义微调、v2 换说法但语义不变），对**同一 top-1 候选**打分——
量的是「同一命中点、近似措辞」下 bge 余弦的分数波动，不是改写后换了个命中点
的分差（后者量的是不同命中点，天然大差，没有意义）。

40 对分差分布：min 0.000 / P25 0.007 / **median 0.060** / P75 0.109 / max 0.243。

**取值逻辑**：PRESENCE_BAND 的语义是「台词分差小到不可信的量级」——
差不超过它，排序本来就是噪声级的，presence 才发言；超过它，台词分是可靠信号，
presence 无权翻盘。取**中位数 0.060**：约一半的近似改写会翻转排序，presence
的发言空间正好覆盖噪声空间。不取 P75（0.109）：那意味着 presence 能翻
「台词分差 0.1」的排序，而 75% 的改写里 0.1 的分差是稳定的——0.1 是可靠信号，
presence 不该碰。

换番、换 embedding 模型后这个数要重测（它是 bge-base-zh-v1.5 在这个语料上的
噪声性质，不是模型常数之外的通用常数）。

## 实现与本文的出入

| 项 | 本文原写 | 实现 | 为什么 |
|---|---|---|---|
| PRESENCE_BAND | `0.03`（标了待回填） | **`0.06`** | 实测：40 对近似查询分差 median 0.060。0.03 只有 38% 的改写波动被覆盖，presence 大半该发言的时刻不发言 |
| 段落 5 集号 | （未提） | 无 `集:`，已知落空段落 | 人物志里是「董香身份疑云」的过渡段，没有可锚定的台词事件，按模板规则不写集号 |
| 降级显示 | 「打印 + review 显示」 | clips 打印 `·S01E08` + `(→季内)/(→全空间)`，04-review.html 同步显示 | 与计划一致，无偏离 |

## 验收证据（2026-08-09，本期）

- **段落 19 锁 S01E08**（0.793），不再出现跨季 S04E05；段 16/17 锁 S01E07；
  本期零降级，所有片段在锁定集内
- **回归**：删掉全部 `集:` 重跑，输出与基线逐段一致（向后兼容证明）
- **check_script**：19/20 段带集号机检全过；故意改错（段 20 → S05E99）
  → 正确 FAIL 且 hint 可操作（「多半是集号写错」vs「整季没入库」两条分开）
- 363 个单测全绿；变异检验：忽略集号的作用域链、删掉 search 掩码、
  按块切分改全文抓取、带内排序方向反转、删掉 BAND——全部变红

## 什么情况下推翻本决定

- **集号约束让 no_match 明显变多**（不该发生：末端=全空间=今天）→
  优先怀疑集号写错，check_script/05 的降级标记会暴露；若确实暴露了
  「同一段台词在相邻多集出现」的系统性现象，考虑把集级放宽为
  「该集 ± 相邻集」
- **全量加权有了离线评测证据**（人工标注的正确答案证明融合排名优于单通道）
  → 那时 ADR-0003 的推翻条件也已兑现，两个 ADR 一起改
- **换番重测 PRESENCE_BAND 差一个量级** → 这个数不是拍脑袋就是错的，重定
- **presence 带内排序在 05 人审中反复确认排错**（在场分高的候选画面里
  没有那个人，ccip 误检率高）→ 把 BAND 收窄回中位数以下，或回到布尔过滤 +
  漏检垫底
