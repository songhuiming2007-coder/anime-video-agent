# anime-video-agent 项目标准

本文件是这个项目的**规范定义**：哪些是硬标准、每一条为什么存在、违反时按什么程序处理。
它是 CLAUDE.md、WORKFLOW.md、ADR 的骨架——它们解释细节，这里给出标准本身。

**四条使用规则：**

1. **标准先于实践。** 新建任何东西之前，先在这里找到对应的标准；没有就先补标准，再动手。
2. **改标准先改文档。** 实践与标准冲突时，先改这里，再改实现，顺序不能反。
3. **每条标准都能回答「为什么」。** 写不出理由的标准不算标准——删掉它。
4. **标准要么被执行，要么被删除。** 留着不执行的条款会让整份文档失去权威。

---

## 一、定位标准

| 标准 | 内容 |
|---|---|
| 交付物 | **流水线本身**，不是内容表现。可复用的 agent 工程系统（本地索引 + 语义检索 + 多阶段流水线 + 自动质检） |
| 内容数据 | 副产品与验证信号，不是目标 |
| 取舍判据 | 做任何选择都问：这件事让**流水线**更好，还是只让**这一期视频** / **这一部番**更好？后者一律降优先级 |
| 可复用性 | 项目不是为一部动漫写的，是为 1 亿部写的。任何硬编码都是缺陷，见第二节 |
| 项目性质 | 实验项目，优先级低于主线，成功标准是流水线跑通而不是播放量 |

**明确不做的事（已付过代价的决定，改动先看对应理由）：**

- 纯搬运（无口播的内容）
- 自动上传（发布永远手动）
- 画质 / 转场 / 文案的无限打磨
- 政治议题进自动管道
- 引入 MoviePy、Remotion、任何 NLE 或视频框架
- 引入数据库、编排框架、web 界面
- 为提覆盖率去 mock 掉 ffmpeg 或模型
- 检索落空时自动降级
- 把审美判断包装成机器判据（给封面候选打分排名）
- 放宽阈值让检查通过，而不查它为什么不通过

## 二、可复用性标准（为 1 亿部动漫，不是为一部）

**这是项目的本质，不是加分项。** 这个项目不是为春物写的，是为任何一部能被检索、能配音、
能渲染的动漫写的。**一切硬编码 = 把项目钉死在某一部番上**，等于只做了一期的工具。

**R1. 机制与内容分离。** 机制进代码，内容进配置。判断一件事是机制还是内容，
问一句话：**换一部番它变不变？** 变，就是内容，内容不许写死。
- 实例：锚点词曾写死在 `check_script.py` 的正则里，全是春物专有名词，换番一个都命中不了，
  锚点检查永远判 0 处——挪进 `config/project.json` 的 `anime.anchor_words`
- 实例：画面语义的查询表是内容——「空无一人的教室」是校园番的问法，科幻番该问别的；
  反例「太空中的宇宙飞船」在春物里是噪声地板，在科幻番里是**正片**
- 实例：`config/*.json` 里下划线开头的 `_note` 键就是内容说明，机制与内容的分界写在注释里

**R2. 阈值必须逐番标定，不许抄默认值。** 镜头切分阈值（`visual.scene_threshold`）、
画面通道门槛（`scenes.json` 的 `no_match`）、CCIP 同人距离（`faces.CCIP_SAME`）——
这些数是拿一部番的量产出来的，只对这部番成立。抄来的阈值不会报错，
只会静默地切出过碎或过粗的镜头、把噪声地板测成一个真命中的高分。

**R3. 索引、目录、配置按番隔离。** 检索按番过滤（`subindex.load_all` 只在加载层收该番、
`clips.candidate` 再校验一次），索引目录按番分组。**绝不允许跨番命中**——
命中别的番的台词会被解析成本番的同季同集文件，切出完全不相干的画面且不报错。

**R4. 换番只动 config 与 Phase 0 资产，不动 `pipeline/`。**
角色名表、BGM 曲目表、锚点词、视觉配置都是 Phase 0 资产；换番 = 重跑 Phase 0 + 改配置，
代码一行不动。能插拔的部分必须做成**可插拔通道**：booru tagger 是动漫专用的，
换真人影视必须能整块摘掉而不影响其余部分（ADR-0003「不许让它成为架构里拔不掉的一环」）。

**R5. 每个数离开当前这部番还成立吗？** 成立 → 进全局配置或代码；不成立 → 按番存或留待实测。
判断不了就先不写，不许带「可能」蒙混。这条与判据标准 S7 同源。

**R6. 任何「换一部番就要改代码」的地方都是缺陷，不是惯例。**
发现一个修一个：把该数挪进配置、该表挪进 config、该层做成通道。改完跑一遍换番动作验证
（见第十五节验证标准），不只是跑当前番。

**R7. 每期的验证不止于「这一期能不能出片」，还要问「换一部番这套还成立吗」。**
这是 HELP.md 的核心假设：把「动漫」从流水线里拆出去，变成可插拔的垂类 profile。
不要写「只对春物成立」的代码然后告诉自己以后再说——以后永远不会来。

## 三、硬约束标准

| 约束 | 值 | 违反即 |
|---|---|---|
| 每期人类投入 | **≤ 10 分钟** | 系统缺陷 |
| 人类出现的位置 | 只有 **05 审时间码** 和 **09 发布** | 系统缺陷 |
| 超预算处理 | 改流水线或砍掉该环节，**不是加时间** | 加时间是违约 |
| 连续超预算 | 3 期 → **停止产出，回头修流水线** | 继续产出是违约 |
| 无限打磨 | 禁止。时间只花在更自动、更可靠上 | 违约 |

超预算不是「这期多花点时间」，是流水线有 bug。每期必须在 `meta.md` 记录实际人类耗时；
3 期超预算就停产，这是止损线，不是加班理由。

## 四、判据标准（本项目的灵魂）

这是踩出来次数最多的纪律，全部是硬标准：

**S1. 每加一道检查，先问它测的是不是真实产物。**
测的不是真实产物的检查，通过毫无意义。实例：质检字幕项初版算「原文长度 ÷ 每行容量」，
而 libass 对无空格的中文根本不折行，91 字的段落渲成一整行照样判 PASS。

**S2. 每引入一个分数，先问它能不能用来排序。**
一个量能用来**卡门槛**，不代表它能用来**排序**。同一条教训在这个项目里出现过四次：
拉普拉斯方差给封面打分、回读 CER 判轴、查询阶梯取三级最高分、跨通道分数融合。
卡门槛的量一旦被拿来排序，答案就会被压掉且不报错。

**S3. 门禁的失败必须指向真实缺陷。**
一道门禁只有两种坏法：该拦的没拦、拦了不该拦的。修法一律**回到成因，不调阈值**：
复读幻觉是 ASR 的错不是轴错、同音字是比对维度错不是 TTS 错、论文连接词是正则不看位置。
调阈值是拿一个真问题换一堆假问题。

**S4. 门禁拿不到能证伪的信息时，跳过样本，不定罪。**
把「我不知道」记成「不合格」，是让人干脆关掉门禁的最快方式。实例：Whisper 复读循环时
输出长超字幕 2 倍，判该采样窗不可用，跳过而非记为反证。

**S5. 先归一化再比对的检查，问被归一化掉的部分是不是缺陷所在。**
引号既是噪声（ASR 不还原标点）又是信号（TTS 不该念出标点）。同一个符号两个方向意义不同，
一刀切必然漏一边。实例：「谁更该"赢"」念成「谁更该非赢匪」，回读判 PASS。

**S6. 判据要么反映实际做法，要么删掉。**
实例：降级方案文档承诺过、代码从未实现，按代码的实际行为改文档，而不是补一个凑合的降级。

**S7. 凡是要写进配置 / 代码的判断，不许带「可能」。**
验不了就先不写。实例：`requires-python` 里「部分 ML 包可能无 wheel」那句话没验且是错的，
把真正约束（`numpy<2.5`）顶掉了，照 README 在 3.12 上全新装也装不上。

**S8. 素材边界的判据是「集数对得上」，不是「检索得到东西」。**
后者永远为真：池子只有七分之一时，检索照常返回 Top-K、分数照常在阈值以上、成片照常渲染。
判据必须是六条数字相等：片源 / 字幕索引 / 笔记 / 镜头表 / 角色在场 / 画面语义。

**S9. 跳过不是通过。**
缺前置文件跑不了的检查项必须显式列出，退出码也算不合格。实例：字幕四项缺文件时曾显示
「6/6 通过」，实际跳了三分之一。

**S10. 分数只在它自己的通道内排序，绝不跨通道比较。**
台词的 0.7 和画面的 0.7 不是同一个量，长得像纯属巧合。跨通道融合的排名照样存在、
照样单调、照样能取 Top-K，**只是它不对应任何真实的东西**。要融合必须先用人工标注的
正确答案做离线评测。

## 五、失败处理标准

- **诚实失败优于凑合交付。** 拿不到关键素材、配音反复不自然、检索无匹配——立即停下报告，
  不许降低标准硬交。这是本项目最重要的一条。
- **不许硬塞不匹配的画面。** 留白远优于画文不符。
- **检索落空走查询阶梯，只救不比。** `查询` → `备选` → `配音` 原文，逐级重试，
  门槛 `0.45` 全程不动。上一级够格就到此为止，绝不因为下一级分数更高而换掉。
  加大的是找的力度，不是放低的标准。
- **三级都不及格 → 硬失败交人处理，不自动降级。** 自动塞空镜看着省事，实际是把
  「画文不符」藏起来。留白合不合适只有人能判。
- **硬失败把判断交回给人，比自动兜底诚实。** 机器判不了的判断不许由代码替人拍板。
- **成片交人之前，至少听一遍开头和最长的那一段。** 十一项质检全绿不代表能听——
  归一化会抹掉证据，有些缺陷只有耳朵抓得住。

## 六、工程与代码标准

**E1. 每阶段产物落盘，产物即状态。** 看目录里有哪些文件就知道进行到哪一步，
没有数据库、状态文件、任务队列。任何一步失败都能从中间接上重跑。

**E2. 人机交接一律走文件，不走对话上下文。**

**E3. 每个常量后面写「为什么是这个数」。** 每个 workaround 后面写「不这么做会怎样」。
实例：`clips.NO_MATCH = 0.45` 是拿零假设组量出来的；`render.BGM_RATIO = 2.5` 是拿
闪避后 BGM 单独输出的响度表量出来的。**拍脑袋的数不许进代码。**

**E4. 所有路径相对仓库根写 `./data/...`，不硬编码卷路径。** 卷路径通常含空格、卷名会变。

**E5. 任何会下载 HF 模型的模块，`from . import paths` 必须排在所有第三方 import 前面。**
`paths.py` 把 `HF_HOME` 钉到 `data/models/`，并检测 `huggingface_hub.constants` 是否
已被别的库定死——是就当场报错。顺序错了会静默往内置盘写几个 G。

**E6. 依赖一律装在项目目录内（uv 虚拟环境），不污染全局。**

**E7. 媒体正确性靠截取守卫与质检门禁在真跑时兜，代码里不 mock。**
纯函数与媒体正确性分离：`tests/` 只测纯函数；守卫检查真实产物，mock 检查的是 mock。

**E8. 新增能力一律开新文件。** 实例：视觉索引写 `pipeline/vindex.py`，不改 `subindex.py`。

**E9. 命令行入口统一为 `python -m pipeline.<模块>` + `ava-*` 脚本，每个阶段能独立跑。**

**E10. 错误处理标准：**
- 缺前置产物 / 缺配置 / 数据对不上 → `SystemExit`，带**可执行的修复命令**
- 三种失败分开报，修法不同就不混成一句（实例：`require_data` 区分 没建 / 盘没挂 / 骨架不全）
- 门禁报错要带明细，逼人重跑去猜等于逼人关掉门禁
- 批量处理里一个文件出错不打断整批，报 FAIL 让其余跑完

**E11. 截取守卫是渲染阶段的强制标准，缺一不可：**
1. 切之前校验 `seek + duration <= 源时长`，不足立即失败
2. 切之后复核实际时长与请求值之差 ≤ 1 帧
`ffmpeg` 在片段超出源片末尾时静默截断且不报错，踩到就整条音画错位而无提示。
**「1 帧」按源片 `r_frame_rate` 现算，不许写死**（23.976fps 的一帧是 0.0417s，不是 0.034s）。

**E12. 字幕折行必须自己算，不指望 libass。** ASS 的 WrapStyle 依赖空格找断点，
中文整句没有空格就不折。断点取标点，贪心取最远的那个；中文破折号是两字符，必须等一对补全。

## 七、数据与存储标准

| 标准 | 内容 |
|---|---|
| 仓库 | 只有纯文本（代码、skills、配置、文档），全部进 git |
| `data/` | 所有大件（片源、字幕、索引、模型、每期产物），**不进 git**，可作符号链接指向外置盘 |
| 自动创建 | **脚本绝不自动创建 `data/`，不可达立刻报错退出。** 符号链接指向未挂载的卷时，
`mkdir -p` 会在 `/Volumes/` 里建出实体目录，几十 G 静默写进系统盘且盘插上后看不见 |
| 建骨架 | 显式动作 `./pipeline/preflight.sh --init [目标目录]`，打印落在哪块盘 |
| 模型缓存 | `HF_HOME` 指向 `data/models/`，任何模型不落内置盘 |
| 清理时机 | **人拍板最终版之后才能清理，且每次要主动问过。** 脚本只报体积和路径，不替人判断
「什么时候算定稿」。判据是「重生成要多久」：几十秒能重来的一律可清；
不可重生成的（片源、参考干声、番剧笔记、BGM 分轨）一律不清 |

**字幕来源硬规则（违反会静默毁掉整条流水线）：**
字幕的时间轴必须照手上这个视频文件打的。只允许三种来源：
1. ffmpeg 从该文件提取的内封
2. WhisperX / mlx-whisper 对该文件转录
3. 与该文件同属一个发布、文件名逐一对应，**且通过 `ingest verify` 对轴校验**的外挂字幕

**永不用第三方字幕配第三方视频。** 跨版本配对是中间插入与删除，不是恒定偏移，加 offset
修不好；帧级精确截取是渲染链路的前提，前提一塌，视频照常渲染，只是全程画面对不上话。

**片源完整性判据：** `ffmpeg -c copy -f null -` 全片解复用，任何报错即判残缺。
不要用「实占块 ÷ 逻辑大小」（实测漏放 14/72 个残缺文件，最大高估 83pp）——
它只当**前置快筛**：说「没下完」可信，说「下完了」不可信。

**索引自描述标准（ADR-0003）：** 索引元信息必须带 `model_id` + `revision` + `dim` +
预处理参数 + 贴名映射；加载时硬校验，不一致直接失败。同维度换模型不会崩——
余弦照样算、分数照样正常、照样出片，所以只能靠元信息硬失败来挡。

## 八、测试标准

- **`tests/` 只测纯函数**，不 mock ffmpeg 和模型。涉及媒体的正确性交给截取守卫和
  质检门禁在真跑时兜。
- **测的是踩过的坑，不是 API 形状。** 每条断言对应一个具体错误，注释里写它当初怎么错的。
- **期望值先在实现上跑一遍，再写进断言。** 这不等同于「跑出什么就断言什么」——
  跑出来的值先要看懂**为什么是这个值**，说不通就是找到 bug 了。
- **写完做变异检验：把被测行为故意改坏，看测试红不红。**
  一条永远绿的断言和没有断言效果完全一样，但它会让人以为这块被覆盖了。
- `pytest` 必须不碰片源 / 模型 / 外置盘，clone 下来装完就能跑（约 3 秒）。

## 九、文档标准

| 文件 | 记什么 | 进 git |
|---|---|---|
| `CLAUDE.md` | 工程约定，任何人拿这个仓库都适用 | 是 |
| `CLAUDE.local.md` | 只对本机 / 本账号成立的事实（盘符、播放数据、优先级） | 否 |
| `docs/Standard.md` | **规范定义（本文件）**：标准、理由、违反程序 | 是 |
| `docs/WORKFLOW.md` | 每期九步与 Phase 0 的操作细节 | 是 |
| `docs/ROADMAP.md` | 顺序与闸门：先做什么、什么条件下才允许做下一件 | 是 |
| `docs/adr/` | 难以回头的单个决策及其证据、推翻条件 | 是 |

**ADR 标准：**
- 只记难以回头的决策；可逆的决策（谁写谁定）不用 ADR
- 每个决策带证据与验证结果；验不了就显式标「待实测」，不许带「可能」蒙混
- 每个决策写「什么情况下推翻本决定」
- 实测数据回填后要回来改 ADR，不要只改代码

**文档纪律：**
- 注释写「为什么」，不写「是什么」——代码本身已经说明它做什么
- 实现与文档分叉时，按代码的实际行为改文档，不补一个凑合的承诺
- 修改规范：先改文档、再改实践

## 十、每期流程标准

九步顺序**不可交换**，产物文件即状态：

```
01 选题 → 02 写稿 → 03 配音 → 04 排片 → [05 人审时间码]
        → 06 渲染 → 07 质检 → 08 封面标题 → [09 人选并发布]
```

**N1. 顺序不可交换的根本理由：必须先配音拿到每段真实时长，再排画面轨。**
字数估算与实际语速的偏差每段几百毫秒，二十段攒下来是几秒的渐进错位，
越到后面画面与口播差得越远，**全程不报错**。配音时长以 `ffprobe` 复核的
`manifest.json` 为准，不采信模型自报。

**N2. `01-topic.md` 必须带 `模式` 与 `张力`。** 张力是整条流水线里唯一真正的编辑判断，
必须在这一步定死并经人批准，不能留到写稿阶段由 agent 自行发明。写稿只校验、不更换。

**N3. `02-script.md` 的 `查询` 是机器接口，不是备注。** 它被原样送进字幕索引检索，
必须写成台词语义；写成画面构图必然落空。落空的绝大多数原因是查询写错了，不是素材不够。

**N4. 写稿自检两遍，顺序不能反：先保真（台词原文、说话人、季集号、数字），再去味。**
机检全过不代表能交。

**N5. 第 05 步是整条流水线唯一的人工关卡。** `--approve` 必须是显式动作——
自动写 approved 是最省事的做法，也正是这一关曾经形同虚设的原因（两文件字节完全相同）。

**N6. 第 08 步分工是三层，不是两层，且候选之间没有排名：**
| 层 | 谁 | 做什么 |
|---|---|---|
| 1 | 机器 | 剔黑场/过曝/糊帧、去重、编号 |
| 2 | agent | 看联系表，挑出符合本期主题的（谁在画面上、占不占主位） |
| 3 | 人 | 从 9 张里定一张（审美） |

机器筛掉不能当封面的帧，**不假装能判「哪张有张力」**。清晰度是准入门槛不是排序依据，
试过两版打分，两版都把正确答案压掉了。

**N7. 排片软过滤，封面硬过滤（检测的不对称）。**
「检测到 X」可信、「没检测到 X」不等于 X 不在场：
- 封面：按「含主角」过滤，为空则失败（几千帧挑 9 张，高精度低召回正合适）
- 排片：过滤为空则**退回不过滤的结果**，不硬失败（一段只有几个候选，误杀就没片可用）

## 十一、内容参数标准

以下每一条来自本账号的实测复盘，改动任何一条前先看新数据是否推翻它：
推翻了就**先改标准、再改实践**。

| 参数 | 标准 | 依据 |
|---|---|---|
| 平台 | 抖音优先，B 站同步分发 | 同内容抖音播放高一个量级 |
| 画幅 | **16:9 横屏，已决策** | 番剧构图为 16:9 设计，裁竖屏破坏画面 |
| 时长 | 2–4 分钟 | 两平台一致地时长与播放负相关 |
| 选题 | 情感共鸣密度 × 番剧认知度，不是热度榜 | 认知度最高的热血番垫底 |
| 垂直度 | 硬约束，技术/体育类播放接近零 | 稀释账号标签，一律不发 |
| 素材配比 | 动画 ≥80%，漫画 ≤20% 作补充 | 受众预期动态画面 |
| 标题 | 金句式，不论文式 | 判据：能否脱离视频单独发出去 |
| 政治议题 | 不进自动管道 | 审核边界 agent 不掌握 |

**文案由 Agent 全权生成**是知情的取舍：人工写稿约 30 分钟/期，会吃掉学习时间，
这个代价高于文案质量下降的损失。但文案生成必须是可替换模块（seam），
切换只改配置、不改流水线（`config/script-mode = auto | from-core`）。

## 十二、质量门禁标准

渲染后自动跑，机器可判定，**不达标直接打回，不进人工环节**。主观项（节奏、观感）
不进门禁——它们的根在稿子和排片上，回第 02 / 05 步改，不在成片上补救。

- 成片时长落在 2–4 分钟
- 音画时长误差 < 0.5 秒；成片与排片一致
- 响度 EBU R128 目标 −16 LUFS；无 true peak > −1 dBTP
- 无 > 0.5 秒纯黑；无 > 2 秒静音段
- 字幕：无空段、不超宽、每卡一行、不超高

**TTS 回读质检**是配音阶段的门禁：每段生成后用 Whisper 回读，不过就换种子降温重生成，
三次仍不过**整体失败退出**，不留坏音频。判据两条同时越线（错数 ≥3 且 CER >20%），
比对在**带声调拼音**上做（`tts.syllables()`），不在字形上做——
按字形比量到的是「ASR 认不认识这个人名」，不是「TTS 念没念对」。

## 十三、版权与发布标准

- 二创混剪 + 原创口播属灰区，口播是加分项；**纯搬运不做**
- **BGM 用该番自己的音乐**（OST / OP / ED / 插曲 / 角色歌），每首必须带实测响度
  （`config/bgm.json` 里没有 `lufs` 的曲子不许用，`bgm.py` 直接报错退出）
- **上传手动做，不自动化**——省下的几分钟不值得拿账号冒险
- 片源不进 git、不外传

BGM 音量控制量是**归一到目标响度**，不是乘一个固定系数：劇伴 −14.4…−18.1 LUFS、
OP/ED 单曲伴奏 −7.1…−13.2 LUFS，极差 11 dB，固定系数换一首就失准而且不报错。

## 十四、协作标准（两人项目）

**C1. 决策权跟着验证能力走。** 谁能验证一件事，谁就对那件事有决定权；
拍板的一方有义务把理由写下来，**写不出理由的拍板不算数**。
- 判据、阈值、门禁 → 能真跑的一方（macOS 侧）
- 内容方向、选题、发布 → 账号所有者
- 平台无关的代码结构 → 谁写谁定（可逆）
- 数据格式、模块边界、重依赖 → **两人一致**，谈不拢时各写一份 ADR 草案，隔一天再看

**C2. 先开 issue 再写代码。** 不是请示，是防撞车。issue 写三件事：
要解决什么问题、**判据是什么**、打算怎么验。判据写不出来说明这事还没想清楚。

**C3. 合并判据：** `pytest` 全绿（三平台 CI）；新行为带纯函数测试且做过变异检验；
没有 mock 掉 ffmpeg 或模型；涉及媒体产物的改动由能真跑的一方跑过真实数据才合。

**C4. 分支：** `feat/` `fix/` `docs/`，从 `main` 开，不直接推 `main`；
一个 PR 只做一件事，正文超 400 行就拆；squash merge，commit message 中文。

**C5. 红线（双方都不做）：**
- 提交 `*.local.md`、任何媒体文件、片源、字幕
- `git push --force`，或任何改写已推送历史的操作
- 在 issue / PR / commit / 注释里贴账号数据、播放数、密钥

## 十五、验证标准（改完必跑）

| 场景 | 命令 | 判据 |
|---|---|---|
| 改完代码 | `pytest` | 全绿（约 3 秒，不碰片源/模型/外置盘） |
| 环境自检 | `./pipeline/preflight.sh` | data 可达 + ffmpeg 带 libass |
| 稿件机检 | `python -m pipeline.check_script <02-script.md>` | 全过，主观项留给 / 交给人看 |
| 六条数字 | `python -m pipeline.vindex status --anime <番>` | 六条相等 |
| 真跑验证 | 阶段跑真实数据 | 涉媒体改动必须真跑，靠 CI 兜 A 层 |

**「我这儿能跑」不构成证据。** 某些 bug 只咬新环境（`numpy<2.5`、未挂载的盘），
已有的环境一切正常正好掩盖它。验证必须在全新环境上做一次。
**「当前番能跑」同样不构成证据。** 可复用性（第二节 R6）要求：凡动了配置边界、
阈值、通道结构的改动，都要按「换一部番」的动作验证一遍——不是只在春物上过一遍就合。

## 违反标准的处理程序

| 违规类型 | 处理 |
|---|---|
| 硬约束超预算 | 记录到 `meta.md`，连续 3 期 → 停止产出修流水线 |
| 门禁误报 / 漏报 | 回到成因修判据，**不许调阈值绕过** |
| 静默失败（不报错的错误行为） | 加一道守卫把静默失败变成当场失败，再谈修不修 |
| 实现与文档分叉 | 先确认哪个对，改标准文档或改实现，二选一，不留分叉 |
| 删文件 / 改配置 / push | 命中红线，先问人，得到确认再动 |

> **判断任何决策是否合格，最后一句话问自己：**
> **「这件事我能不能说出它为什么是对的？」** 说不出来，就是还没想清楚——
> 这个项目拒绝过好几个「能跑但判据是假的」方案。
>
> **可复用性那件事再单独问一次：**
> **「换一部番它还成立吗？」** 答案是否，而你没有把它变成配置或通道——这个决策不合格。
