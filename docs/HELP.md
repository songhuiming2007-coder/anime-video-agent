# 招募：一起把 anime-video-agent 做成通用的视频解说 Agent 的伙伴

我在做一个视频解说自动化流水线，已经跑出两条成片，现在想找人一起把它做成通用的 Agent。

- **仓库**：https://github.com/songhuiming2007-coder/anime-video-agent
- **成片**：[第一期《大老师自爆，真的是一种牺牲吗？》](https://v.douyin.com/aUBsk_DryFk/) · [第二期《为什么雪之下雪乃是最适合大老师的》](https://v.douyin.com/_2WfJS5FgP8/)

---

## 现在有什么

`anime-video-agent` 是一条命令行 pipeline：输入一句选题，输出可以直接上传的 mp4、封面和标题候选。中间九步——写稿、稿件机检、本地 TTS 配音、语义检索排画面、人审时间码、渲染烧字幕混 BGM、11 项自动质检、封面与标题——由脚本和 coding agent 跑完，人类只在两处介入。

已经端到端跑完两期：

- 《大老师自爆，真的是一种牺牲吗？》3:09，41 个片段跨 4 集，质检 11/11，2026-07-29 已发布
- 《为什么雪之下雪乃是最适合大老师的》3:14，质检 11/11

质检是硬门禁，11 项全过才允许发：时长 2–4 分钟、音画对齐差 ≤ 50ms、响度 -16±1.5 LUFS、真峰值 ≤ -1 dBTP、无 >0.5s 纯黑、无 >2s 静音、字幕不超宽不超高每卡一行。两期的实测是 -16.07 / -16.04 LUFS，音画差 11ms / 28ms。

全部本地跑，没有云 API、没有数据库、没有编排框架、没有 web 界面：

| 环节 | 用什么 |
|---|---|
| 素材检索 | bge-base-zh-v1.5 对 ASS 字幕做 2 行滑窗语义索引，6 集片源建出 2337 个检索单元，向量存 npy |
| 配音 | IndexTTS-1.5 跑在 mlx-audio 上，自回归解码循环是自己写的（上游 `generate()` 有两处 bug） |
| 质检 | mlx-whisper 回读配音算 CER、字幕对轴校验、无字幕时兜底转录 |
| 视频 | 全程 ffmpeg，不用 NLE、不用 MoviePy |
| 状态管理 | 文件系统。产物即状态，看目录里有哪些文件就知道跑到哪一步 |
| 测试 | 165 条 pytest，只测纯函数，不 mock ffmpeg 和模型 |

项目的重点其实不在功能，在**判据**。这条流水线上难修的 bug 都有同一个特征：**它不会主动报错。**

- ffmpeg 截取超出片尾会静默截断并返回 0
- 语义检索找不到合适画面照样返回 Top-K、分数照样在阈值以上
- 索引只建了 6 集而片源有 41 集，检索照常工作、成片照常渲染
- TTS 把引号念成字，回读质检判 PASS
- 字幕长到出画，「原文长度 ÷ 每行容量」这个检查也判 PASS

所以每加一道检查，先问它测的是不是真实产物；每引入一个分数，先问它能不能用来排序。

## 现在的边界

设计预算是人类每期 ≤10 分钟，**这个数还没验证。** 第一期是边搭边做的，时间基本花在报 bug 上（语速不统一、句尾杂音、给雪之下配了叶山的画面、BGM 听不见）；第二期在选题上反复返工。但这都是建设成本不是每期成本，每期时间确实还没确定。硬约束是在 pipeline 完工后连续 3 期超 10 分钟就停产、回头修流水线。

它也只会做动漫，而且是硬编码进去的：

- 素材检索完全依赖内封 ASS 字幕，没字幕的片源直接不工作
- 稿件机检的「剧情锚点」靠一张逐番手写的具名词表
- 写稿风格、张力模式、质检阈值都是在动漫素材上调出来的

换一部番要重跑 Phase 0，换一个品类基本要重写一半。

---

## 想做成什么

把「动漫」从流水线里拆出去，变成一个可插拔的垂类 profile。同一套骨架，换个 profile 就能做影视解说、游戏实况精剪、纪录片拆解、科普、新闻解读。

核心假设是：解说类视频的骨架是通用的——选题 → 稿 → 声音 → 画面对齐 → 成片 → 质检——真正因垂类而异的只有三件事：素材怎么被检索、稿子怎么算合格、成片怎么算能发。**这三样能不能被抽成配置和插件，是这个项目值不值得做下去的真问题。** 我不确定答案。

---

## 通用化真正难的部分

### 1. 素材索引现在只懂「说了什么」，不懂「画面里有谁、有什么」

举个刚发生的例子。第二期整期在讲雪之下雪乃，封面模块自动筛出 9 张候选，其中 5 张里根本没有她——烘焙材料静物、天台空镜、结衣和三浦。最后是人指定「去最后一季告白那回找」才拿到能用的一帧。根因很直接：整条素材链建在字幕语义索引上，索引里没有「画面里有谁」这一维。

这在动漫里只是封面偶尔翻车，换成影视、游戏、纪录片就是整条链断掉——那些片源大量没有可用字幕。要靠 ASR + 视觉理解（抽帧 embedding？VLM 打标？人物识别？）重做一层，而且要能和现有字幕索引共存、按素材可用性降级。**这是最大最难的一部分。**

### 2. 判据的可移植性

11 项质检、稿件机检、封面筛选的阈值全是在动漫素材上实测出来的。换品类后这些数还成不成立、是不是每个 profile 都要重测一遍，我没有答案。

### 3. profile 的抽象边界画在哪

画太浅，换品类还是等于重写；画太深，会变成一个谁也读不懂的通用框架。

## 在找什么人

会一块就行，不要求全会：

- **熟练使用 coding agent** —— 这是最重要的一点，你不可能手写所有代码。有这一条下面都不用看，你就是我要找的人，兄弟。
- **检索与多模态** —— embedding / 向量检索，或者用抽帧、VLM、人物识别做视觉素材理解。**这是最缺的**
- **音视频工程** —— ffmpeg 熟，踩过 libass 折行、响度归一、时间轴对齐的坑
- **内容侧** —— 会写解说稿，有自己的垂类（影视、游戏、科普都行），愿意当第一个非动漫 profile 的作者兼真实用户
- **本地推理** —— Apple Silicon / MLX / 模型量化部署

比技能更重要的两件事：能接受「先定判据、再写功能」这个顺序；提 issue 时说得清「我预期什么、实际什么、怎么复现」。
