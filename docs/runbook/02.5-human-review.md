# Runbook: 02.5 人审改稿（停机点 1）

【🛑 强制人工停机点】：机检只能证伪格式，无法证明观点立得住。必须人类通读并确认。

## 输入物
- `data/episodes/<期号>/02-script.md`
- `data/episodes/<期号>/02-adversarial.md`（02.8 对抗审查报告：事实类 agent 已裁决，衔接 / 语言类标「人定」等你判；⚠ 是审查者自己引用核不上的条目）

## 这一步实际要做的
人主导，AVA 配合，都在配音之前做：
- **逐段挑刺**：人指出段号和问题（衔接不畅、措辞怪、术语劝退、AI 味、写得空、开头不抓人、和上一段重复），AVA 直接改、写入、跑机检、报改了什么。
- **事实核查**：人点名一句要核查，AVA 查字幕、笔记、画面，给出有出处的改法；查不到就说查不到，不拿推断顶上。
- **人自己也改稿**：AVA 动手前先读当前版本，只做最小替换。
- **结构改动**：拆段、补外部素材、单段多锚点、插试看段。配音前改成本最低；先看有什么画面能用，再决定怎么拆，避免拆出对不上画面的段。方案由人定。

## 审查重点
1. **编辑判断立不立得住**：反方立场像不像真人在说话，张力是否虚构；
2. **事实核验**：台词出处、说话人、关键集号与数字是否真实，拦截 AI 幻觉；
3. **去模型味**：删去油腻拔高、翻案腔与套路排比；
4. **`人物:` 该写没写**：对照机检 INFO 行逐段扫一眼。该写没写不可证伪，这一条是提醒不是判据；
5. **说话人断言抽帧核对**：「某某说」类断言抽帧确认说话人（`skills/write-script/SKILL.md`）——字幕 `Name` 字段基本不填，机器判不了。

## 封板操作
人类总监直接在 `02-script.md` 上修改，也可以让 agent 改（2026-10-08 D47；ADR-0030 起写入不弹卡，agent 写前的旧版留底在 `_agent/script-history/`，人要回退从那里拿，标注数据也据此区分人改与 agent 代笔）。`02-script.md` 只能由人从草稿新建；它存在后草稿冻结，保持为 patch 的基线。改完后直接批准 02.5（桌面端待答区「批准」或终端 `/approve 02.5`）：封板缺失或过期时会先自动封板（D48），不用另敲命令。想先封板再批，点 app 内 02.5 编辑器的「封板」（产物 `02-diff.patch` = 草稿与定稿的 diff；底层等价 `git diff --no-index 02-script.draft.md 02-script.md > 02-diff.patch`，只作排查参考）。

## 规则
- **未见人审封板严禁配音**：`02-diff.patch` 是账号声音的重要标注数据。未获得人类明确确认（或封板 patch）前，Agent **严禁擅自启动后续配音**。
