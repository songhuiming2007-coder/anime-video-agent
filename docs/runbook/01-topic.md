# Runbook: 01 选题与张力

每期立项的唯一起点。由人类（或人机共创）产出。

## 产物与位置
`data/episodes/<期号>/01-topic.md`

## 必须字段
```markdown
---
番: 春物
类型: 杂谈              # 人物志 / 剧情回顾 / 杂谈 / 盘点 / 共鸣
模式: 驳论              # 驳论 / 立论 / 吐槽（杂谈必填）
张力: 伪恶者的自我救赎 vs 逃避现实的平庸之恶  # 杂谈必填，正反交锋冲突点
锚点: S01E01 12:30      # 核心物证镜头时间码
封面集: S01E05          # 可选：指定封面抽样集
时长目标: 2.5-3.5分钟    # 可选：目标分钟带
---
```

## 核心规程与铁律
1. **张力是流水线唯一的编辑判断**：必须在立项时定死。写稿阶段 Agent **严禁擅自更换或发明张力**。
2. **题材决定骨架**：人物志/剧情回顾以人物动作因果为核心，不强设张力；杂谈必须具备明确对立面与公道话。
3. **完成标志**：文件落盘且字段完整，准备进入 `02-script.md`。
4. **一部番榨干再换**：选题池枯竭前不开新番；番剧笔记写厚 + **零上下文对抗审查** + **终审裁决回写**（全部期共用的资产，全程 agent 劳动、人类零耗时，细节在 `docs/dev/postmortems/workflow-history.md`「番剧笔记」节）；换番要显式决定并在会话里跟 agent 记一句为什么。

## 01.2 平台与内容规格基准表

来自自己账号的实测复盘，不是拍脑袋。**具体播放数字不进 git**（账号数据，本机自维护且会过时），这里只留规则与方向性依据。改动任何一条前先看新数据是否推翻它；推翻了**先改规则、再改实践**。

| 参数 | 标准 | 依据 |
|---|---|---|
| 平台 | 抖音优先，B 站同步 | 同内容抖音播放高一个量级 |
| 画幅 | **16:9 横屏，已决策** | 番剧构图按 16:9 设计，裁竖屏破坏画面 |
| 时长 | 2–4 分钟（默认，可按期覆盖） | 两平台一致：时长与播放量负相关——这条数据来自短打杂谈类内容，不假定对所有体裁都成立。选题天然需要更多篇幅时（人物志/剧情回顾/共鸣等），在该期 `01-topic.md` 写 `时长目标: X-Y分钟`，`check_script.py`/`qc.py` 会跟着改判据；不写就还是这两平台数据撑着的 2–4 分钟。**这是一次性的选题决定，不是把默认值改宽**，理由在会话里跟 agent 说清楚即可 |
| 选题 | 情感共鸣密度 × 番剧认知度，不是热度榜 | 认知度最高的热血番反而垫底 |
| 垂直度 | 硬约束，技术/体育类一律不发 | 播放近零，稀释账号标签 |
| 素材配比 | 动画 ≥ 80%，漫画 ≤ 20% 补位 | 受众预期动态画面 |
| 标题 | 金句式，不论文式 | 判据：能否脱离视频单独发出去 |
| 政治 | 不进自动管道 | 实测被退回/限流，agent 不掌握审核边界 |

**文案由 Agent 全权生成**是知情的取舍（人工写稿约 30 分钟/期，会吃掉学习时间），但必须是可替换模块：`config/script-mode = auto | from-core`，切换只改配置、不改流水线。

## 01.3 BGM 选曲填入与响度约束

- **选曲每期人耳现选**（2026-08-08 改，此前是「一部番一套固定曲目，Phase 0 定死」）：AI 的音乐审美、对经典歌曲的判断不如人，把选择权锁死在机器手里是本末倒置。Phase 0 扫库/分轨/量响度（`pipeline.bgm` 的 `scan`/`extract`/`register`）攒成可选曲库；具体选哪首等这期配音出来、人听过之后再定，填进这期 `01-topic.md`（允许后补——选题阶段写不了，配音出来才听得出该配什么）。**支持任意首数拼接**（2026-08-10 改，此前「一期最多两首」）：`01-topic.md` 写 `BGM:` 列表，每行一首、`@N秒` 定起点（不写自动接上一首结尾）；老格式 `BGM正文`/`BGM中段`/`BGM结尾` + 切入点字段仍可用。每首放一遍、后一首接棒；后一首起点晚于前一首自然结尾 → 留停顿。最后一首铺到片尾。
- **每首必须记实测响度**：曲目表里没有 `lufs` 的曲子不许用（`bgm.py` 报错退出）。音量控制量是「归一到目标响度」（-26 LUFS），不是乘固定系数——劇伴与 OP/ED 伴奏极差 11 dB，固定系数换一首就失准且不报错。
- **扫曲库必须解 cue**：OP/ED 单曲碟是整轨镜像 + cue，按 flac 文件数扫会漏掉整档（而它恰恰最强）。
- 曲库两份，改一份同步另一份：`config/bgm.json`（给机器，攒的是候选池，不是定死的选择——`use` 字段现在只是没人现选时的退路）+ 番剧笔记（给人，和分集笔记同文件）。
- **该番所有下载到的音乐一律放 `bgm/<番>/`**（2026-08-09 定）：顶层是已测量、进 `bgm.json` 候选池的曲子（flat 文件，路径被直接引用，不能动）；`raw/` 子目录放完整原始下载——不管是独立下载的 OST 压缩包，还是随 BD 一起下的附赠 CD（Drama CD / 角色歌 / 单曲），只要是音乐就不留在 `raw/<番>/`（那里只放视频+字幕）。理由：音乐找起来独立于「按哪个 BD 组下的」，混在片源目录里下次想扩曲库还得先想起某季附了什么 CD。
