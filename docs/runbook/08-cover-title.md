# Runbook: 08 封面与标题候选生成

全自动提取高质量封面帧候选池并生成标题候选，严禁机器代人定稿。

## 执行
agent 先问人，再跑 `cover`（期目录自动补上）。底层排查参考：`python -m pipeline.cover data/episodes/<期号>`。

## 产物与位置
- `data/episodes/<期号>/07-cover/`（候选帧与 6×5 联系表）
- `data/episodes/<期号>/07-titles.md`（5 条类型化标题候选）

## 规则
1. **机器只做剔除，不做排名**：
   - 拉普拉斯方差 < 60 剔糊帧，平均亮度剔过曝/死黑，dHash 剔同镜头重复。清晰度是准入门槛，非审美排序依据。
2. **三层分工，Agent 读联系表**：
   - 机器负责无死角去重抽样 → Agent 看联系表挑选符合主题的 9 张候选（`--pick`）→ 人类最终定稿 1 张。
3. **标题与封面定稿权在人**：
   - 产出的 5 条标题涵盖不同受众心理（反问/下判断/剧情钩子等）。
   - **Agent 严禁擅自拍板标题或修改封面文案**，必须如实呈现候选，交由人类决策。
4. **人自备图导入与 `cover_edit`（Spec 12）**：
   - 人自己找的图（含在 Google Flow 扩好的横/竖版）：在 app 里拖入或选文件导入，落 `07-cover/import/`（不重编码、不覆盖同名）；终端等价路径 `cat <图> | ava <期> /import-cover --name=<原始文件名>`。
   - 叠字排版：**先和人商量写什么字**（字是人定的）；字定了以后，agent 调 `cover_edit` 直接出图（文字/九宫锚点/字号/颜色/描边为参数，Pillow 确定性渲染，同参数同字节），不把位置、字号拿出来问；人说「放大点」「朝右移」就照改重出。输出 `07-cover/edit-*.png` 候选（不覆盖、不排名）。
   - 字体文件由人一次性放置到 `config/project.json` 的 `cover.font_file`（不在时渲染如实报错，不 fallback）。`cover_edit` 不做缩放/裁剪/滤镜/生图/扩图。
5. **出图先自己看（D90）**：`cover_edit` 渲染完、bash 裁完图，先用 `view_image` 看一眼，确认不挡脸（含头发、背景人物的脸）、字在手机上看得清、取景不只剩一张大脸，再交给人。交给人的是图，不是参数表。模型看图判断位置偏粗：靠近脸的字，宁可再挪开一点。
6. **竖版底图**：竖版有时从横图裁，有时由人用 AI 扩图（如 Google Flow）做好再导入；扩图时 agent 只给扩图 prompt，不加戏。`cover_edit` 不裁图，要裁就用 bash（ffmpeg / sips）裁到 `07-cover/import/`，看过再叠字。原图是胸口以上的特写时，硬裁成竖版只剩一张大脸——换一个半身 / 中景镜头的帧，不要用上下模糊垫底（2026-10-13 人明确不要）。

## 交付物（09 前必须齐，`read_status` 逐项核对）
- `08-cover.jpg`（横版 16:9）与 `08-cover-vertical.jpg`（竖版 9:14，人定 2026-10-14）：放期目录**顶层**，候选都留在 `07-cover/`，顶层不放别的。人点名用哪一版后，agent 才可用 bash 把那一版转成 jpg 放过去；人没点名不许写。`.jpeg` / `.png` 也认。
- `07-titles.md` 里要有 `## 简介` 与 `## 标签` 两节。简介**统一一份**，不分平台，同时照顾长视频与短视频平台，不简单照抄文案（人定 2026-10-14）；人选定标题后记在 `## 定稿标题`。
- 缺任何一项，`read_status` 的 09 会列出缺项；没齐不许说「可以批准 09」「闭环」。
