# Runbook: 03.5 配音顺听（停机点 2）

【🛑 建议人工停机点】：防范多语种自回归 TTS 静默发飘、吞字与音色断层。

## 输入物
- `data/episodes/<期号>/03-audio/`
- `data/episodes/<期号>/03-audio/manifest.json`

## 人工操作规程与预算

人类时间预算按成片时长核算（预算 = `k × 片长`，以 03.5 顺听+改+复听 ≈ 1.5×片长 为锚点）：
- **默认定位是「三项抽检」**（非全量）：
  1. 开头段（`seg-00.wav` / `seg-01.wav`）：确认起调、情绪与音色基调；
  2. 最长段落：确认语速是否均匀，有无尾音发飘或严重电音；
  3. 夹杂英文/日文专有名词或生僻多音字的重点段落：确认发音是否可懂。
- 全量顺听是怀疑系统性发飘时的深挖动作（执行前留意总音频时长）。

## 顺听工具与流程

1. **单段或抽检播放**：
   ```bash
   open -a "QuickTime Player" data/episodes/<期号>/03-audio/seg-05.wav
   # 或使用 afplay
   afplay data/episodes/<期号>/03-audio/seg-05.wav
   ```
2. **在 ava REPL 中顺听**：
   - `听 5`：自动调用 QuickTime Player 打开第 5 段对应的音频文件；
   - `听`：后台启动 afplay 顺序播放整期音频；
   - `停`：终止整期后台播放序列（kill afplay 并重置停止标志）。

## 随手纠错指令与语法（ava <期> /voice）

在 `ava <期号>` 会话中输入 `/voice` 进入纠错模式：
- **分支 A：字词级错读（多音字 / 错读）**
  - 语法：`<段号> <错词> 改成 <拼音>`（如 `05 重 改成 zhòng` 或 `段5 重叠 改成 zhòng dié`）；
  - 亦支持 `应读`、`读作`、`听成` / `念成`（如 `05 重叠 听成 chóng dié 改成 zhòng dié`）；
  - 拼音音节建议用空格分隔或标调号数字（如 `zhong4 die2`）；
  - 解析成功后回显结构化卡片，按 `y` 确认追加到 `corrections.json`；
  - 作用：写入当期读音覆盖（期级 overlay），仅靶向重配该段。
- **分支 B：整句级听感异常（语气发飘 / 断层 / 吞字）**
  - 语法：`<段号> 换种子` 或 `<段号> 语气发飘`（命中受控听感词：发飘、断层、不稳、闷、机械、吞字、杂音、赶、变了）；
  - 作用：严格按公式重掷并钉住新种子（`pin_seed`），重配该段。
  - **注意**：语速调整暂不进入合成链（issue D26），输入「太快/太慢」会明确报错提示不支持。
- **管理指令**：
  - `回滚 <段号>`：从 `03-audio/attic/` 包含该段的最近快照中恢复旧音频与 manifest 段条目，条目回到 pending；
  - `撤回 <条目ID>`：按 corrections 条目 id 撤回该条纠错；
  - `/done` 或 `done`：退出纠错并执行应用流程。

## 核心纪律与资产生命周期

1. **`03-audio/corrections.json` 是 append-only 永久资产**：
   - 严禁随意删除！删除了它，下次普通重跑时期级 overlay 丢失，音频会被静默重配回错读音；
   - 它是制片资产与审计轨迹的一部分，随期目录持久留存。
2. **两层读音表关系**：
   - `config/voice_readings.json`（g2p 全局表）是**长期沉淀层**；
   - `03-audio/corrections.json`（期级 overlay）对同名键**严格优先**；
   - 更改全局表不会自动改动已有期级 overlay 的段。
3. **云端配音与本地配音的侧别纪律**：
   - **同一期音频的 apply 与产出该期的引擎必须同侧**（本地 apply 会触发引擎变更拦截退出）；
   - **云端配音期**（`engine=qwen3_tts_cuda`）：
     1. 本地编辑/追加 `corrections.json`；
     2. 上行同步：`python -m pipeline.cloud push`；
     3. 云端应用补丁：`python -m pipeline.cloud run <期号> tts -- --apply-patch`；
     4. 下行拉回产物：`python -m pipeline.cloud pull`；
   - **本地配音期**（`engine=mlx`）：
     - 本地执行：`python -m pipeline.tts data/episodes/<期号> --apply-patch`。
4. **快照备份与 `03-audio/attic/` 保留策略**：
   - 每次 `--apply-patch` 在覆盖前会自动将受影响段音频及 `manifest.json` 备份至 `03-audio/attic/<YYYYMMDD-HHMMSS>/`；
   - 系统自动保留最近 10 份快照，并在修剪时明确报账所删快照及其包含的段号；
   - 清理前置条件：必须确认当前没有 pending 条目；成片交付归档后，可整目录清理 `attic/`。
