# Runbook: 03.5 配音顺听（停机点 2）

【🛑 人工停机点】：防范多语种自回归 TTS 静默发飘、吞字、音读泄漏与音色断层。听觉结论只能来自人耳。

## 输入物
- `data/episodes/<期号>/03-audio/`（`seg-XX.wav`）
- `data/episodes/<期号>/03-audio/manifest.json`（每段时长与合成记录）

## 抽检规程

人类耗时是观测量（2026-09-23 起不设硬预算；经验参考：顺听 + 改 + 复听约 1.5×片长）。默认是**三项抽检**，不是全量：
1. 开头段：起调、情绪与音色基调；
2. 最长段：语速是否均匀，有无尾音发飘或电音；
3. 含外文专名、生僻字或多音字的段：发音是否可懂。

怀疑系统性发飘时再全量顺听。

## 在桌面端顺听与纠错（主路径）

**打开**：03.5 停机点就绪时，预览区会自动打开本期的 `03-audio`（人正在操作或有音频在播时不抢，改为预览区顶部出一条「停机点 03.5 已就绪 · 查看」，点它打开）；也可以在产物树里点本期的 `03-audio`。预览区上方出现顺听面板。

**面板上有的东西**（只有这些）：
- 工具栏：「顺序播放」「停」「刷新」，本期配音引擎名，「完成并应用补丁」；
- 段落列表：每段一行，▶ 播放该段；该段在 `03-audio/attic/` 有快照时多一个「回滚」；
- 纠错输入框：文法与终端 `/voice` 相同（见下文「纠错文法」）。填好点「解析」→ 出确认卡（段落、目标词、听成、目标读音、动作、范围）→ 点「确认落盘」，条目以待应用状态写进 `03-audio/corrections.json`；
- 待应用纠错条目列表：每条可「撤回」；
- 多音字预检：只读，列出稿件里的多音字及候选读音，仅供关注。

**应用**：全部纠错录完后点「完成并应用补丁」，按 `corrections.json` 只重配受影响的段（本地 `tts --apply-patch`）。
- 本期是**云端引擎**时这个按钮不可用，面板会提示去云端执行（步骤见「核心纪律」第 3 条）；
- 正在重配时面板显示进行中的 pid；锁残留时让 agent 跑 `tts --clear-stale-lock`（弹卡；锁里的 pid 已不存在才清，还活着就拒）。app 不加清锁按钮。

**已知不便**（D50，待改）：面板下方还有一份旧的音频列表，播的是同一批文件；纠错输入框在面板底部，段多时要往下翻；结构化打点（manifest 的 human_review）面板上没有入口——跟 agent 说分数，由它跑 `tts --review voice=4,prosody=3,misread=4`（弹卡，只写打点不重合成）。

## 读音错了改哪里：三层表

**改稿不是纠读音。** 字幕用 `02-script.md` 原文，合成用的是经读音表处理后的文本。读错的字不要改稿件，改读音表。

| 层 | 文件 | 能做什么 | 生效范围 |
|---|---|---|---|
| 全局·拼音直注 | `config/voice.json` 的 `pinyin_injections` | 词 → TONE3 拼音（如 `"喰种": "can1zhong3"`）。治**音读泄漏**（汉字被念成日语）先用它：拼音没有日语映射，模型无从借调 | 所有番、所有期 |
| 全局·同音字 | `config/voice.json` 的 `readings` | 词 → 同音字（如 `"乐迷": "月迷"`）。治**多音字与普通读错**先用它，选读音唯一的字；音读泄漏用拼音实测不灵时也退到这里 | 所有番、所有期 |
| 期级 overlay | `03-audio/corrections.json` | 只有两种动作：拼音注入、换种子；**没有期级同音字替换** | 默认只管点名的那一段；写「全局」或「所有段」= **本期**所有段（不是跨期） |

- **先试哪种看错误类型**（2026-10-08 人裁决）：汉字被念成日语 → 拼音直注；多音字读错、普通读错 → 同音字。依据：voice.json 里已有 3 条拼音直注实测失效退回同音字（全部、二次元、二次审查），董香二期「绚都」也是；多音字类错误不是音读泄漏，拼音「物理阻断」的理由对它不成立。
- 同一个词在两张全局表里都有时，拼音优先，`readings` 那条被跳过（所以换路线要 `--supersede` 删掉另一条）。
- 期级对同名词严格优先于全局表。
- **放哪一层**：跨期反复出现的专名（贯穿一个系列的人名、地名）放全局层，一次生效，不要每期各录一遍；只在这一期、这一段出问题的放期级。
- 全局表可以人手改，也可以由 agent 经人审卡写（AGENTS.md「Code Freeze」唯一例外，只限这两张表）。改完后普通重跑 `tts`（不带 `--force`）只会重配念法变了的段。
- 经 `corrections global` 写入的条目会在 `readings_provenance` 里记下来历（哪一期、哪部番、哪个引擎和音色上实测的、哪天）。换音色或换引擎时按它挑出要重测的条目；旧条目没有来历，不回填（凭 `_note` 推断会编出假来历）。
- 期级纠错走面板、`/voice` 或 agent 经人审卡录入，再 `--apply-patch`，只重配受影响的段。

### 命令（agent 经 `run_pipeline` 调用，期目录自动补上）

| 命令 | 作用 | 卡 |
|---|---|---|
| `corrections check --word 肉体 --homophone ròu体 --expect rou4ti3` | 只核对读音，不写 | 免卡 |
| `corrections add --text "5段 重叠 改成 zhong4die2"` | 期级：追加一条到本期 `corrections.json`（文法同 `/voice`） | 弹卡 |
| `corrections global --word 绚都 --pinyin xuan4du1` | 全局拼音直注 | 弹卡，标 [全局] |
| `corrections global --word 绚都 --homophone 炫嘟 --expect xuan4du1` | 全局同音字 | 弹卡，标 [全局] |
| 上一条加 `--supersede` | 另一张表有同键时一并删掉（否则拒：同键时拼音优先，同音字会成死条目） | 弹卡，卡上写明删了什么 |

读音不成立（音节数不对、同音字读音与 `--expect` 不同）在弹卡前就被拒，并打印两边的拼音。

## 核对替换读音

写进任何一张表之前，先查替换词的拼音，确认与**应读的音**逐字同音同调：agent 跑 `corrections check --word 绚都 --homophone 炫嘟 --expect xuan4du1`（免卡，只核对不写），对不上会打印两边的拼音。

比对的对象是「这个词应该怎么读」，不是 pypinyin 对原词的结果：pypinyin 自己也会读错多音字（例如它把「绚都」给成 `xuan4dou1`，而应读 `xuan4du1`）。同音字只看音不看义，替换成同义词不算同音字替换。

## 终端备用：`ava <期号>` → `/voice`

- **顺听**：`听 5` 用 QuickTime 打开第 5 段；`听` 用 afplay 顺序播放整期；`停` 终止。
- **纠错文法**（面板输入框同一套）：
  - 字词错读：`<段号> <错词> 改成 <拼音>`，也认 `应读`、`读作`、`听成` / `念成`（如 `5段 重叠 听成 chóng dié 改成 zhòng dié`）；拼音用空格分隔或数字调（`zhong4 die2`）；加「全局」或「所有段」= 本期所有段；
  - 整句听感：`<段号> 换种子` 或 `<段号> 语气发飘`（受控词：发飘、断层、不稳、闷、机械、吞字、杂音、赶）；语速不进合成链（D26），「太快 / 太慢」会报错；
  - 管理：`回滚 <段号>`（从最近快照恢复该段音频与 manifest 条目）、`撤回 <条目ID>`、`/done` 退出并应用。
- **结构化打点**：跟 agent 说分数，它跑 `tts --review voice=4,prosody=3,misread=4`（弹卡；只写打点，不重合成）。

## 核心纪律

1. **`03-audio/corrections.json` 是 append-only 永久资产**：不许手删。删了它，下次普通重跑时期级 overlay 丢失，音频会被静默重配回错读音。
2. **期级与全局的关系**：期级对同名词严格优先；改全局表不会改动已有期级 overlay 管着的段。
3. **云端 / 本地同侧**：apply 必须在产出本期音频的那一侧做（本地 apply 云端产物会被引擎变更拦截退出）。
   - 本地配音期（`engine=mlx`）：面板「完成并应用补丁」，或让 agent 跑 `tts --apply-patch`（弹卡）；
   - 云端配音期（`engine=qwen3_tts_cuda`）：本地录好 `corrections.json` → agent 依次提议 `cloud push <期目录>` → `cloud run <期目录> tts -- --apply-patch` → `cloud pull <期目录>`（三张计费卡）。
4. **快照**：每次 `--apply-patch` 覆盖前把受影响段的音频与 `manifest.json` 备份到 `03-audio/attic/<YYYYMMDD-HHMMSS>/`，保留最近 10 份并报账删了哪些。没有 pending 条目、成片交付归档后，可整目录清理 `attic/`。
5. **锁残留**：上一次 apply-patch 进程被杀或断电，`03-audio/.apply_patch.lock` 会让后续纠错落盘与 apply-patch 都中止。让 agent 跑 `tts --clear-stale-lock`（弹卡）：锁里记着持锁进程的 pid，进程已不存在才清；还活着（真在跑，或 pid 被复用）就拒，等它结束或交人看。不要手工 `rm`。

## 给 agent 的边界

- 顺听结论只来自人耳，不替人说「这版没问题」。
- 描述桌面端时只说本篇写到的按钮与流程；没写到的，说不知道、请人看界面。
- 人报了读错的字，按这个顺序做：
  1. 给方案，先看错误类型：多音字或普通读错用同音字（读音唯一的字）；被念成日语用拼音直注；第一种人听过仍错再换另一种；
  2. 问放本期还是全局：跨期反复出现的专名（系列人名、地名）建议全局，只在这一期出问题的放本期；
  3. 用 `corrections check` 自查读音，通过了再提议 `corrections add` 或 `corrections global`（弹卡由人批）；
  4. 批了之后提议只重配：期级 `tts --apply-patch`，全局 `tts`（不带 `--force`），云端期走 cloud 三步；
  5. 配完请人听，听感结论由人下。
- 读错的字不改稿件；同音字只看音不看义，不用同义词。
