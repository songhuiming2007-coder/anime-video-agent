### [B4] 人审改画面后段级时长不再对齐，渲染漂移无门禁拦截
- 状态：阻塞
- 位置：pipeline/clips.py:178-242（size 精确填满的机制）；pipeline/review.py:182,199（只展示
  不比对）；pipeline/qc.py:188-196（只查总量）；pipeline/render.py:691（-shortest 截差额）；
  docs/adr/0005:9-11（手工改 start 的先例）
- 描述：机器排片时每段画面总长 == 该段配音时长（`size()` 保证）。05 人审发现画文不符、
  要求 agent 改画面后，改的只是 `04-clips.json` 里的 start/dur，没有任何环节把
  「每段画面总长 == 该段配音时长（manifest）」重新校验或重排。渲染后口播与画面
  按段漂移、越到后面越歪；段级漂移而总量凑巧相等时全程静默，`-shortest` 还会把
  差额截掉一部分进一步掩盖。与 B1 是两类病：B1 是画面内容不对（语义），这条是
  时间轴漂移（时长）。
- 线索：审查页每段并排展示配音时长与各片段 dur，但人不做求和比对；qc 的
  「音画时长对齐」「与排片一致」都是总量级，抓不住段级漂移。方向候选：
  ① 审查页/独立校验逐段 `sum(clip.dur)` vs manifest 段时长，不等标红或报错；
  ② 收口编辑——改画面只许改 start/source，dur 一律重跑 `size()` 重填；
  ③ 二者结合。
- 推进：选定方向（决策点）后按项目纪律出方案再动手；人审后改过 clips.json 的每一期
  都会踩，量化触发条件与 D6 同源。
