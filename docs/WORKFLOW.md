# 每期作业流程

> **本文档只记操作步骤：命令、产物、要盯什么。**
> 所有 `S*` / `R*` / `E*` / `N*` 判据的权威定义见 [`docs/STANDARD.md`](STANDARD.md)。

从选题到成片的九步，每步的命令、产物、以及**要盯什么**。

设计目标是人类投入 ≤ 10 分钟/期，只出现在四处：**02.5（人审改稿）、03.5（配音顺听）、
05（审时间码）、09（发布）**。其余全是机器时间，可以后台跑。

每步的产物落盘且带序号，**产物文件即状态**——看目录里有哪些文件就知道进行到哪，
不需要额外的状态记录，任何一步失败都能从中间接上重跑。

```
data/episodes/YYYY-MM-DD-<番>-<主题>/
├── 01-topic.md              选题（类型、锚点；杂谈含模式、张力）
├── 01.5-beats.md            可选节拍表（仅人物志 / 剧情回顾按期启用）
├── 02-script.draft.md       机器初稿（中间缓存，定稿后可删）
├── 02-script.md             全稿 + 分镜，终稿（02.5 人改的是这份）
├── 02-diff.patch            初稿→终稿 diff（账号声音标注数据）
├── 02-adversarial.md        02.8 零上下文对抗审查报告 + 终审裁决
├── 03-audio/                逐段配音 + manifest.json（真实时长）
├── 04-clips.json            排片
├── 04-clips.approved.json   ← 人在这里批准
├── 05-final.mp4             成片
├── 06-check.log             质检报告
├── 07-titles.md             标题候选与定稿
└── 07-cover/                封面候选池 + 一页 HTML（人在 09 选定一张，最终封面不自动落盘）
```

## Phase 0 · 每部番做一次

| 事项 | 状态 | 命令 |
|---|---|---|
| 片源完整性 | ✅ | `ingest intact` —— 全片解复用，约 0.9s/文件 |
| 字幕对轴 | ✅ | `ingest verify` —— ASR 回读比对 |
| 整季入库 | ✅ | `ingest phase0` —— 对轴 + 建索引 + 登记片源，三步合一 |
| 语义索引 | ✅ | `subindex build` —— bge-base-zh，滑窗 2 行 |
| ASR 兜底 | ✅ | 无外挂字幕时用 `mlx-whisper` 转录该文件本身 |
| 镜头切分 | ✅ | `shots calibrate` 定阈值 → `shots build` → `shots frames`，约 2.2 分钟/集 |
| 角色在场 | ✅ | `faces detect` → `cluster` → **人贴名** → `presence`，约 1.3 分钟/集。**已贴名的 clusters.json 不许重跑 `cluster` 覆盖**（会无声抹掉人工贴名，命令会拒绝并给指引）；要重建：`mv <番>.clusters.json <番>.clusters.json.bak` 保住贴名 → 重跑 `cluster` → `sheet` 对照新旧簇的代表脸把名字补回去。只补几集 detect 不必重跑 cluster |
| 画面语义 | ✗ 探针没过，不建 | `vprobe scene` 跑完的结论：门槛立不住（ADR-0003 待实测 #4）。氛围段落留给人在第 05 步 |
| 音色 | ✅ | 试音选定后写进 `config/voice.json` |
| BGM 曲库 | ✅（只攒库，不定选曲） | `bgm scan` / `bgm extract` / `bgm measure`——攒的是候选池，具体哪期用哪首见每期 01（CLAUDE.md「十、BGM 约定」，2026-08-08 起改成每期人耳现选） |
| 番剧笔记 | **三步流水线**：①主 agent 研究写厚 → ②对抗 agent 审查（零上下文子代理）→ ③主 agent 终审裁决回写 | 产物 `data/library/notes/<番>.md` + `<番>-对抗审查报告.md`。**三步产物齐 + 裁决已回写才算完成，缺一步不许出片。** 全程 agent 劳动，人类零耗时 |

### 一次做完全集，做不完不许出片

**这条是踩出来的，代价是好几期视频在一个假的素材边界里做完了。** 判据见 [S8](STANDARD.md#S8)；
事故复盘见 [`docs/notes/workflow-notes.md`](notes/workflow-notes.md#1-一次做完全集做不完不许出片)。

判据是**六条数字必须相等**。加了视觉索引之后从三条扩到六条——
多一份索引就多一处会悄悄缩水的地方。一条命令全查：

```bash
python -m pipeline.vindex status --anime <番>
#   片源 / 字幕索引 / 笔记 / 镜头表 / 角色在场 / 画面语义
```

> **原则**：集数对得上才是真边界；「检索得到东西」永远为真，不是判据。

### 番剧笔记：三步流水线（每部番做一次，全程 agent 劳动，人类零耗时）

```
阶段一 · 主 agent 不遗余力研究写厚      产物 data/library/notes/<番>.md
阶段二 · 对抗 agent 不遗余力找漏洞      产物 data/library/notes/<番>-对抗审查报告.md
阶段三 · 主 agent 汇总终审裁决回写      修正回写 <番>.md，裁决存笔记「已知更正记录」节
```

**三步产物齐 + 终审裁决已回写，才算这部番的笔记完成**——缺一步，「六条数字」里笔记那条
不许算齐，不许出片。对抗 agent 用 Task 子代理开（子代理天然零上下文），不需要人来开。
三个阶段的执行细节在下面三节。

**剧情理解的源不对——这条踩了两次才踩明白。** 第一次（2026-08-08）：agent 凭对系列剧情的
通识印象写 re 篇分集速查，一问才发现没读一行字幕；第二次（2026-08-09）：改成「从字幕原文
提取」后仍然出错——东京喰种 S01 表逐集读字幕核对时发现 E03/E04/E05/E09 四集有真错误，
OVA 把 Pinto 当成旧多的故事（实际主角是月山），S03 把拍卖会弧记错集数。
**教训合起来是：剧情理解的源不对。**

- **「凭训练记忆写」是错的**——agent 的动漫知识只撑得起抽象概括，撑不起可指认的事件。
- **「从字幕反推剧情」同样是错的**——字幕只有对话，没有画面、动作、叙事者，因果和情感全在
  台词之外。agent 从无上下文的台词里读不出「谁做了什么、为什么」，只会读到半截、读错、
  读出一堆空白。

所以剧情理解的**主源是网上现成的人类写的详细剧情资料**：百度百科分集剧情、维基百科剧情、
萌娘百科、B站番剧分集简介、豆瓣、bangumi。写分集速查前，先把这些源抓下来通读、交叉核对，
再落笔。

**字幕的双重身份要分清（2026-08-13 罪恶王冠大修后立的规则）：** 字幕在「理解剧情」上不够
（没有画面），但在「核实剧情」上是最硬的一手——逐行台词、时间码、说话人、事件先后顺序
全部在里面。**笔记里每条关键台词带行级时间码（指到台词所在行，不是场景起点，见判据 [S12](STANDARD.md#S12)），
对抗审查的第一层（剧情重建 diff）和第二层（逐条核销）全靠字幕这条地面真相。**

**源的可达性每次都要实测并记进笔记来源表。** 反爬是常态，不是意外：百度百科 403
（2026-08-13 实测完全不可达）、Fandom 403 但真实浏览器可开、萌娘需 JS 渲染、Anime Evo
已改版旧 URL 全部 404、tvsou 搜索页可用但条目难定位。拿不到的源如实记「不可达」，
**不许把「查不到」当「没有」**；可达但被反爬挡的按「源抓不到 ≠ 放弃」处理（见下）。

- 笔记头部**注明用了哪些来源**（URL 或站点名），来源之间冲突的标出来。
- 字幕/台词索引**只做三件事**：引台词原文（逐字）、记时间码、核说话人——全都回 `.ass` 或抽帧。
- **版本坑**：网上资料常把漫画版和动画版混着写，改编幅度大的（√A 是动画原创）要选「动画版」
  的源；拿不准的，以手上这部动画的实际内容为准并标注。

这条对任何番、任何 agent 都成立，不因为换了会话或者换了模型就不用管。

#### 阶段一 · 主 agent 不遗余力研究写厚

人物志/剧情回顾这类以「剧情事实」为承重的期数，agent 是**照着笔记写稿**的：写稿 agent 不
回看原片，它看到的世界就是笔记里写的世界。笔记薄 = 每集只有一句话速查，agent 不知道
「前情是什么、谁做了什么、为什么」——它就只能用「听起来合理的因果」填空（楪祈人物志·二
的错误 2/3/4 都是这么造出来的）。**写厚的标准：每集至少能回答「这集之前发生了什么导致现在
这样、这集里谁对谁做了什么、结果是什么」**，不是「这集大概讲了什么」。人物志还会用到
「前情」（上一集结尾发生了什么、为什么角色是这个状态），这些在笔记里必须有，否则写稿
agent 直接跳进场景，观众不知道前情（楪祈人物志·二错误 3 正是缺前情）。

**写厚不是「多写几句话」，是六条硬门槛，缺一条笔记不许进阶段二：**

1. **必须强迫开 subagent 研究**——写笔记这一步不准由写稿 agent 顺带完成，必须派独立
   subagent 专门做剧情考据（它吃「谁做了什么」这类不可凭记忆的断言，逐个开子任务查证，
   查不到的当场标「未经证实」）。顺带写 = 凭印象写，本节开头踩的两次教训已经证明必然出错。
2. **必须查阅多个独立网站**——主源是网上人类写的详细剧情资料（百度百科分集剧情、维基、
   萌娘、B站分集简介、豆瓣、bangumi），**每集至少两个来源交叉**，来源之间冲突的标出来
   （WORKFLOW「剧情理解走网上现成资料」节的规则照用）。一个源说、其他源都沉默的事，不能
   当确定事实写。
3. **必须剧情严格自洽**——笔记的因果链不能断：上一集结尾的状态和下一集开头对得上，角色
   为什么是这个处境、为什么这么做，前后能咬合。自洽检查是笔记写完后的必跑项，不靠「读着
   通顺」判断，靠「抽一集问'这集之前是什么导致了这个局面'，笔记答得出」。
4. **必须深度、逻辑严密**——不是每集一句话带过，是人物志要用到的「前情」「动机」「因果」
   全部写到：谁因什么做了什么、结果如何、这结果又成为下一段的起因。逻辑链上任何一环靠
   「大概」「应该」撑着，这一环就算未证实，回到第 2 条查。
5. **必须带可证伪的引用坐标**——每条关键台词带**行级时间码**（判据 [S12](STANDARD.md#S12)）、说话人与场景
   语境；源间说法不一致处单独列「分歧」存档，各源说法与裁决都写下来；单源断言标
   「仅 X 源」。没有引用坐标的笔记无法被对抗审查核销，等于免检。
6. **必须场景级钉时间码**（2026-08-27 加，ADR-0008 后锚点是排片唯一依据）：
   分集速查的**每个场景**带起止时间码。时间结构不用人看片拖——先跑
   `python -m pipeline.timeline <番>` 出时间网格（对白块/无台词块交替，边界已吸附
   镜头切点，产物在 `data/library/timeline/`），再把网搜来的场景序列对上去：
   ① 有台词的场景用一句标志台词 `subindex search` 定位；② 无台词场景对照网格的
   无台词块 + 抽一帧确认内容；③ 都钉不上标「未定位」，不许含糊带过。
   网格是零语义的纯时间结构（合并/切开只看台词间隔），**场景语义标注是 agent 的活，
   不许拿网格块的内容提示列当剧情依据**——从字幕反推剧情是老错路。

**笔记结构模板**（2026-08-13 罪恶王冠实测版，新番照此写，缺节即缺门槛）：
剧情来源与方法（来源表必须含**可达性实测**）→ 版本边界（漫画/小说/OVA 隔离声明）→
片源可用性 → 角色在场索引 → 角色名来源（字幕实证写法）→ 角色小传（完整弧光 + 声优）→
次要角色（含死亡节点）→ 世界观设定与术语 → 时间线年表 → 分集速查（场景级 + 行级时间码 +
分歧存档）→ 验证过的台词锚点 → 已知更正记录 → 存疑点 → BGM 候选池。

这六条和对抗性审查是同一件事的两半：写厚解决「没料」，对抗解决「料错」。
**产物 `<番>.md` 落盘后，进入阶段二。**

#### 阶段二 · 对抗 agent 不遗余力找漏洞（零上下文独立重查）

笔记是 agent 写的，agent 写笔记和写稿犯的是同一个毛病——凭印象/二手转述落笔，然后当作
事实喂给下一个 agent。**「人扫一眼兜底」兜不住**：人只会扫到错的密度，扫不出具体哪句错。
楪祈人物志·二里「祈在学校拦下供奉院殴打她」这句错误就写在笔记原文里（写稿 agent 照抄了
笔记的错误）。

**关键认识：让「同一个 agent 换个立场检查」没用。** agent 一旦看过笔记，就被笔记的因果
框架带了进去——它会顺着笔记的叙述找「顺不顺」，找不出「笔记和事实的分歧」。对抗必须
来自**没被笔记污染过的独立推导**。这个机制赌的是**两次独立推导撞在同一处错误的概率
极低**：一个 agent 凭印象编错可能，两个没交换过信息的 agent 在同一个断言上编出同一个错，
才是小概率。这就是对抗的意义——不是「检查」，是「另起炉灶再盖一栋，然后看两栋哪边歪」。

**执行版（2026-08-13 罪恶王冠实测定型，三层结构）：**

1. **零上下文怎么开**：主 agent 用 Task 工具开子代理——子代理天然零上下文，只拿到审计
   prompt 与方法，拿不到主 agent 的上下文与研究过程。**不必由人来开**，整条「研究 →
   审计 → 终审」全部是 agent 劳动，人类零耗时，不碰 ≤10 分钟止损线。
2. **第一层 · 剧情级重建 diff**：对抗 agent **先不读笔记**，只靠字幕逐行通读（22 集约 1.2 万行
   台词，全读）独立重建每集的事件序列 + 因果链，再与笔记逐集 diff。猎杀四类：**编造**
   （笔记有、字幕与全网源都无）、**遗漏**（剧情有、笔记无）、**因果错误**（方向反、
   张冠李戴、跳步）、**顺序/归属错误**（集数、先后）。跨集主线因果链（伏笔链）逐条独立
   拉一遍对照。
3. **第二层 · 引用级逐条核销**：笔记里每个时间码、每条带引号的台词，对抗 agent 亲自打开
   字幕定位到那一行、前后读 5-10 行，确认存在 + 逐字一致（含简繁）+ 说话人 + 语境。
   **时间码行级对准是判据（[S12](STANDARD.md#S12)）**。这一步是体力活，可以再分片外包给 subagent，
   主对抗 agent 抽样验收。
4. **第三层 · 元层抽查**：笔记里「某源如此说」的断言本身也要验（实测抓到「256=4⁴ 出自
   TV Tropes」查无出处、「GHQ 前台（英文维基）」查无原文）；「仅 X 源」标注的诚实性是
   审查项；网络源的独立性要分级（Fandom 抄英维、中维转日维，家族内互证只算一个源）。
5. **错误分类清单**（报告照此归类，即审计 prompt 的猎杀模板）：编造 / 遗漏 / 因果错误 /
   顺序错 / 集数归属错 / 数字错 / 时间码错 / 台词引文不实 / 说话人误归 / 来源标注失实 /
   推断当事实。严重度分致命（会误导成片）/ 高 / 中 / 低。
6. **报告格式硬要求**（缺一条打回重审）：
   - **覆盖率声明**（P0 x/22 集、时间码 x/y 条——没做完如实写，诚实失败优于凑合交付）
   - **随机抽样通过清单**（实测 45 条）——只报错不报过的报告是选择偏差，读者无法校准
     整体可信度（判据 [S11](STANDARD.md#S11)）
   - 每条错误给：笔记原文+行号 / 独立核实结果+证据 / 类型 / 严重度 / 建议修改（具体新表述）
   - 遗漏单独列清单（补写参考，不算错误）
   - 报告落盘 `data/library/notes/<番>-对抗审查报告.md`

**防污染纪律**（写进审计 prompt 的固定条款）：
- 审计 agent 不读同源中间产物（研究稿、写作分片），只读：审计对象 + 字幕 + 网络源
- 验证顺序强制：先查源、后看笔记
- 审计对象只当「待证伪的断言清单」，不当参考资料
- 笔记的每个时间码零信任，必须亲自定位核实

#### 阶段三 · 主 agent 汇总终审裁决回写

**终审裁决（审计之后的必跑环节，缺了这三步流水线就没闭环）**：报告回来后主 agent 逐条
裁决——采纳（改笔记）/ 驳回（**必须写理由**）/ 存疑（写还差什么证据）；修正回写笔记；
裁决过程存档进笔记的「已知更正记录」（包括驳回项与理由）；审查报告本身永久留档。
**没有终审的审计等于白审**：问题发现了不改，下次还是错的。实测：报告自身的断言也可能错
（终审把审计报告一条「E20 春夏台词」的集数错纠正回 E19），所以终审不是走过场，裁决前
每条都要拿一手证据再验一遍。**裁决完回写，三步闭环，这部番的笔记才算完成。**

#### 「未经证实不进正文」只有在写厚之后才可执行

**这条原则不是新发明，它一开始就在——而笔记薄的时候，它正是让笔记薄下去的帮凶。**
笔记薄 → agent 什么都不敢写 → 全部标「未经证实」→ 稿子没料 → 于是它要么硬凑违规、
要么笔记永远停在薄状态。这是一个自我锁死的循环。

所以**顺序不能反**：写厚在前，「未经证实不进正文」在后。写厚把「未经证实」的池子压到
极小（绝大多数断言有来源），这时「不进正文」才拦得住该拦的；没有写厚，它拦住的不是
错误，是唯一可用的料——相当于给薄笔记的每一句都判死刑。

对撞后的处理：
- 无法从来源裁决的断言：**要么删、要么标「未经证实」**，不许当事实写进正文
- 对抗 agent 独立推导里没有、但笔记里有的断言 → 笔记的「无来源断言」，标出来审查
- 通过对抗性审查的断言，在笔记里给一条**来源行**（字幕索引命中的行 / 哪一集哪一秒 / 哪个 URL）

**省人时（人类时间不是无限的）**：标了「未经证实」的料默认不进正文，**不搞逐条目视
兜底**——不存在「对抗查不到就让人挨条看」。人只在一种情况下花时间：稿子写到某一段，非那条
未经证实的料不可时，才做**一次单点确认**（如本期花绳、决战动作），其余未经证实的料直接绕开。
对抗审查省人的度量 = 审稿期 02.5 检查量：对抗漏得越多，人审得越累。对抗审查没把 02.5 的
负担压下来，就是没生效，回去查机制。

这一步是防「笔记把错误传给写稿」的关键闸门：错误只有一次机会被拦住，就是写笔记这一步。

**源抓不到 ≠ 放弃：WebFetch 失败时开子代理用真实浏览器重试。** 反爬是常态，不是意外；
事故复盘见 [`docs/notes/workflow-notes.md`](notes/workflow-notes.md#2-源抓不到--放弃)。

### 入库顺序不能换

```bash
# 1. 先验片源完整（下载器显示 100% 不等于文件完整）
python -m pipeline.ingest intact data/library/raw/<番>/*/*.mkv

# 2. 整季入库：逐集对轴校验 → 过了才建索引 → 登记片源路径
python -m pipeline.ingest phase0 data/library/raw/<番>/<该季目录>/*.mkv --anime <番> --season 1
```

**片源残缺时对轴校验会拿零填充的音频去比，结果无意义。** 所以完整性必须先验。

`phase0` 逐集打印结果，任一集对轴不过就跳过它并说明原因——**不许静默降级**。
它同时把片源路径登记进 `sources.json`，渲染阶段靠它找文件。

字幕来源有硬规则（只允许三种，且第三种必须过 `verify`），见 CLAUDE.md「字幕来源」。
简版：**永不用第三方字幕文件配第三方视频文件**。跨版本的差异是中间插入与删除，
不是恒定偏移，加 offset 修不好；而帧级精确截取是整条渲染链路的前提。

### 选音色（约 2 分钟）

参考干声放 `data/voice/reference/`，5–8 条、每条 8–10 秒、连续说话不要留大段静音。
同一句话逐条试音：

```bash
TEXT="随便一句两三秒的话，最好带个长句和一个短判断"
for f in data/voice/reference/*.wav; do
  python -m pipeline.tts probe "$TEXT" --ref "$f" --out "data/voice/probe/$(basename "$f")"
done
```

**听三样，按重要性排序：**

1. **语速** —— 同一句话在不同参考音下差得很多（实测 4.99s 到 8.23s，差 65%）。
   它直接决定成片长度，而时长与播放量负相关，是三样里唯一有数据支撑的。
2. **稳不稳** —— 有没有电音、忽快忽慢、句尾发飘。
3. **音色** —— 排最后。听的是「这个声音能不能撑 2–4 分钟口播」，
   不是「像不像原参考音」。

> **单句试音不能预测整篇语速。** 实测两条参考音在试音句上差 5%（6.52s vs 6.22s），
> 跑完整篇却反过来差 12%（122.5s vs 139.5s）。选音色可以听单句，
> 但要估成片长度**必须看 `manifest.json` 的总时长**。

选中之后改 `config/voice.json` 的 `ref_audio` 一个字段（换引擎是另一档事：改 `engine`/`model`
两个字段，见 ADR-0006）。
字数带也跟着音色变：`config/project.json` 的 `script.cpm` 要重测——
实测同一音色在不同文风下差过 24%；换引擎后语速特性改变，同样要重测。

**多语种试音（Qwen3-TTS 引擎，2026-08-15 起）：**
旁白夹英日歌名时，试音句要包含一段中英日混读（如「第一首片头曲 My Dearest 响起的时候，
没有人会忘记エウテルペ的旋律」），三样判据之外再听**三种语言念对没有**。

> **参考干声音量不能太小。** 峰值低于约 -20 dBFS 时模型提取不到说话人特征，
> 输出是像嚎叫的杂音（2026-08-15 实测，-26 dBFS 参考音全坏，重录到 -5 dBFS 才正常）。

## 周批量 · 选题

**人：约 5 分钟/周，摊到每期 ≈ 1.5 分钟**（这一步还没脚本化，手写 `01-topic.md`）

`01-topic.md` 必须带齐四项：

```markdown
番:   <番名>
类型: 杂谈            # 五种：人物志 / 剧情回顾 / 杂谈 / 盘点 / 共鸣。骨架由它决定
模式: 驳论            # 只对杂谈必需：驳论 = 通行说法不对；立论 = 作品里有说不通的地方；吐槽 = 图一乐
张力: 弹幕里最常见的一句话是——大老师又自爆了。   # 只对杂谈·驳论/立论必需
锚点: S2E07 / S2E10 / S3E04
```

> **类型先定，骨架从题材里长。** 五种题材五种骨架（人物志/剧情回顾/杂谈/盘点/共鸣），
> 每种的开场、推进、结尾都不一样，见 `skills/write-script` 第 4 节——不许拿一种骨架套所有题材。
>
> **`模式` 与 `张力` 只对杂谈必需。** 张力是杂谈（驳论/立论）里唯一真正的编辑判断，
> 必须在这一步定死并经人批准，不能留到写稿阶段由 agent 自行发明（写稿只校验、不更换）。
> **人物志/剧情回顾/共鸣不设张力**——它的「观点」就是人物/故事本身，由素材决定；
> 在选题阶段硬造一个论点再回头挑经历，是哗众取宠（2026-08-09 人物志踩过）。
> 盘点可选写张力（把「标准」写下来）。

可选第五项，只在这期需要偏离默认篇幅时才写：

```markdown
时长目标: 7-8分钟      # 不填就是默认 2–4 分钟。人物志/剧情回顾/共鸣等需要更多篇幅的体裁才写这项
```

`check_script.py`（第 02 步）与 `qc.py`（第 07 步）都读这个字段，写了就统一改按它判定，
不写就是默认带——两处判据永远来自同一个字段，不会出现「稿子按新标准写、质检按旧标准判」。
**默认带 870–1300 字 / 2–4 分钟是账号实测数据**（CLAUDE.md「内容参数」），只对短打杂谈类
选题成立；写这个字段等于承认这一期不打算套那份数据，是一次性的、要在会话里跟 agent
说清原因的决定，不是新的默认值。

一次勾 3–5 个进 backlog，之后一周从 backlog 取，不再想选题。

## 每期 · 九步

### 01 取选题

从 backlog 取一条，建目录 `data/episodes/YYYY-MM-DD-<番>-<主题>/`，写入 `01-topic.md`。

### 01.5 结构前置 · 按题材启用

`01.5-beats.md` 不是每期必有的状态文件：

| 类型 | 处理 | 前置产物 |
|---|---|---|
| 人物志 | 按期决定，使用时只锁经历弧线 | 可选 `01.5-beats.md` |
| 剧情回顾 | 按期决定，使用时只锁因果链 | 可选 `01.5-beats.md` |
| 杂谈 | 不用 beats，核心判断写在选题 | `01-topic.md` |
| 盘点 | 不用 beats，排序标准写在选题 | `01-topic.md` |
| 共鸣 | 不用 beats，情绪主线写在选题 | `01-topic.md` |

人物志或剧情回顾启用时，节拍表只回答三件事：经历弧线是否完整、因果是否相邻咬合、
每个承重落点是否有来源。它不是逐段台词清单，也不设料单数量配额。

杂谈、盘点、共鸣直接进入 02。它们的结构由题材骨架和 `01-topic.md` 的核心判断、
标准或情绪主线约束；机器写稿过程中允许自然调整段落，不需要先填一张会把正文拆成
材料列表的表。

### 02 写稿 · Agent 约 3 分钟

**产物约定（2026-08-14 加）：机器写的是 `02-script.draft.md`，人改的是
`02-script.md`。** 02.5 人审直接在 `02-script.md` 上改，改完当场提取
diff（见 02.5 一节）——这份 diff 才是「账号声音」的标注数据。
`02-script.draft.md` 是中间缓存，定稿后问过就删（CLAUDE.md 第八节清理表）。

调 `write-script` skill。若本期启用了节拍表，先读并遵守它；否则以 `01-topic.md`、
题材骨架、上一期过审稿和来源核验结果为结构依据：

1. **读锚点与范本**：动笔前必读上一期**过审终稿**（上一期目录的 `02-script.md`，
    不是它的 `.draft` 版）——不是为了避雷同，而是为了贴近
   是为了贴近这个账号已经过关的声音；同时读 skill 指向的范本全文
   （reference.md、bangumi/知乎链接等，当文档读，不摘短语）
2. 查证正文计划使用的剧情事实（笔记优先，无笔记则上网查，**不凭记忆**）
3. **捡料**：料单先于正文，承重料写得出出处，非承重料存在；不设数量配额，不把料单写成段落清单
4. **按题材骨架写正文**：`类型` 决定骨架用词与语体（杂谈再看 `模式` 与 `张力`）；没有节拍表的题材允许在写作中自然调整结构
5. **先超写到 1.6 倍，再删回目标字数**（默认 870–1300 字，`01-topic.md` 写了
   `时长目标` 就换算成那个带；写了 `缩段不注水: 是` 则字数下限打 8 折、
   上界不动——这段真的没料就缩短，不许注水凑数，见 `check_script.py`
   `shrink_no_padding()`）
6. 切成 8–20 段，每段配 `查询` 与 `备选`

> **「读锚点」与「捡料」这两条数字化程度最高的规则，曾经催生机器味、雷同和机械效仿。**
> 规则描述什么，模型就容易表演什么；配额化的捡料会变成材料清单。现在只保留来源核验
> 和上一期过审稿的声音锚点，结构前置按题材启用，不再把一张表强加给所有稿件。

写完自动跑机检，**不过就自己改，改到过为止**：

```bash
python -m pipeline.check_script data/episodes/<本期>/02-script.md
```

机检覆盖：字数、时长、单句上限、**气口段上限、句长起伏、长句下限与短句配额**、
论文连接词、括号、引号、阿拉伯数字、模糊指代、**跨期套话**、**论据是否报菜名**、
剧情锚点数、查询是否重复、查询是否误写成画面构图。主观项机器判不了，脚本按
`01-topic.md` 的 `类型` 给出对应的提示（杂谈看张力/公道话，人物志看有没有给角色安论点，
剧情回顾看因果链……），明确提示留给人看——**主观项提示按题材来，不是每期都念杂谈那一套**。

**机检全过不代表能交。** 自检拆成两遍且顺序不能反：**先保真**（台词原文、说话人、
季集号、数字——去味改写最容易破坏的就是这些），**再去味**。

> **`查询` 是机器接口，不是备注。** 它被原样送进字幕索引检索，
> 所以要写成**台词语义**：「角色承认自己一直在逃避」有效，
> 「中景，逆光，樱花飘落」必然落空——字幕里没有构图信息。

> **锚点看画面集号，正文不背剧情。** 机检的「剧情锚点」按每段画面块的
> `集:` 字段数判定（ADR-0004），**不从正文找「第X集」字样**——正文要不要点明
> 集数、剧情对不对、文字像不像人，是 02.5 人审的活，机检逼正文写集数 =
> 让机器决定内容（2026-08-12 改，删掉了 `anime.anchor_words` 具名词表机制）。

产物 `02-script.draft.md`，agent 原样拷贝一份成 `02-script.md`（02.5 起两者
才分道，`--no-index diff` 量的正是这份分道）。

### 02.5 人审改稿 · **人约 3–5 分钟**（2026-08-05 补，此前漏了）

机检全过不等于能进 03——**机检只证伪，不能证明**（05 那条「主观项机器判不了」同样适用于这里）。
人读一遍全文，重点看两样：

- **这一期的编辑判断立不立得住**——杂谈看张力与公道话像不像反方；人物志/剧情回顾/共鸣看
  是不是按题材骨架在走、有没有为了「有观点」硬造论点。这些是 agent 自己判断不了的主观项，
  `check_script` 跑完也会明确提示「主观项仍需人看」，不是留白，是必须有人接住。
- **承重引用的说话人**——agent 应该已经抽帧/查字幕核对过，但人过一眼成本很低，
  漏判的代价是弹幕当场拆穿（已踩过一次：01-topic.md 标「已核」的 S3E12 锚点实际说话人是雪乃不是结衣）。

不满意就直接改 `02-script.md`，改完重跑 `check_script` 确认机检仍过，再进 02.8。
这一步不出新产物，改的是 02 的产物本身。

**diff 对存档（2026-08-14 加）**：改完当场跑

```bash
git diff --no-index --stat 02-script.draft.md 02-script.md > 02-diff.patch
```

（落在期目录）。机器写了什么、人把它改成了什么，这对 patch 就是「账号声音」
的标注数据；攒够 ≥4 对之后再写提取/风格分析脚本，现在手跑这一条命令就是
全部所需（YAGNI）。02.5 结束时 agent 报一句 diff 规模（增/删行数、改动段数），
给 B2（`docs/issues/README.md` 的人时超限问题）的耗时计时提供数据。

### 02.8 零上下文对抗审查（agent 劳动，人零耗时，2026-08-14 加）

复用「番剧笔记」三步流水线（写厚门槛 → 零上下文对撞 → 终审裁决回写，见本文档
「番剧笔记」节），对象从番剧笔记换成 `02-script.md`。**人不在这一步出现。**

审查 agent **零上下文**（CLAUDE.md 判据 11）：不看料单、不看选题、不看节拍表，
只拿稿件本身 + 字幕索引 + 番剧笔记。逐条核销：

1. 每个叙事断言（谁在哪做了什么）→ 追笔记来源行；追不到 = 报告条目
2. 每句引文 → `subindex search` 逐字比对 + 集号核对
3. 每处「某某说」→ 时间码定位 + 抽帧确认说话人
4. **每段 `锚点:` 时间码 → 回笔记查该时间码附近的场景描述，与本段剧情断言对撞**
   （ADR-0008 后锚点是排片的唯一依据，错锚点直接带错画面且不露怯——
   N24「审讯室实为警车后座」就是这类错）
5. 含混表述（「好像」「似乎」承载剧情断言时）→ 列出要求写稿侧消歧或删除

**报告必须含随机抽样通过清单**（判据 11：只报错不报过的报告是选择偏差，
无法校准整体可信度）；报告落 `data/episodes/<本期>/02-adversarial.md`，
写稿会话逐条终审裁决（采纳/驳回，驳回写理由）记进同一文件，修正回写
`02-script.md`。

**审查管事实不管审美**：机器味、节奏、好不好听不在对抗范围——02.8 拦「假」，
02.5 拦「坏」，两步分工不重叠。

### 03 配音 · Agent 约 5–10 分钟（机器时间）

```bash
python -m pipeline.tts data/episodes/<本期>
```

逐段 TTS，**保留段落边界**（不要整篇一次生成，后面对不齐）。
每段音频的时长用 `ffprobe` 复核后写进 `03-audio/manifest.json`——
这个时长是下一步排画面的唯一依据，**不采信模型自报**。

每段生成后 Whisper **回读**一遍与原文比对，抓漏读 / 重复 / 跑飞；
不过就换种子重生成，三次仍不过就整体退出，不留坏音频。判据与踩过的坑见 ADR-0002，
引擎换 Qwen3-TTS 后的选型与克隆路径见 ADR-0006。

> **ASR 盲区豁免（2026-08-16 改判据）**：三个不同种子生成的音频 Whisper 全部
> 严重失真（CER 远超门槛）而时长达标时，判为 ASR 对音色的盲区而非 TTS 念错
> （[S4](STANDARD.md#S4) 跳过样本不定罪），保留音频标 `qc_skip`，成片交人前必须人耳确认。
> 判据就是「3 次全不达标 + 时长达标」，**不要求回读文本两两相似**——段落 5.1
> 实测：日语参考音色下 Whisper 对中文的失真在「假名乱码」与「近音中文」间
> 摇摆，三次回读内容互不相似（CER 60/60/30%）而音频实际念对，旧判据卡死整期。
> 跑飞由时长闸拦（漏读/重复会改变时长）+ 人耳确认兜底。

> **voice.json 的 `titles` 时长值随换番/换音色重测。** 值是该歌名单独念一遍的
> 实测秒数（`python -m pipeline.tts probe "歌名"`），供时长估算替代 cpm——
> 不重测就沿用旧值，误差由 DUR_BAND 0.5–2.0 的带宽兜底；值为 `null` 表示
> 未实测，跑期时会 WARN 提示可能触发时长门禁。
>
> **含英日歌名的段落，回读 CER 可能虚高。** Qwen3 的拼音比对里英日假名按字符逐字保留，
> Whisper 回读会听岔（エウテルペ→Eutelope），CER 可能超 20% 门槛而音频完全正确。
> 歌名区段要做豁免，不要给整段放松阈值（ADR-0006 遗留项，踩到时处理）。

中断可直接重跑，已过的段落跳过；改了稿再跑只重做改动的段落，`--force` 强制全做。
**严禁无差别全篇重跑**：重跑必须且只能以「单段」为粒度进行，优先保留已合格段落，只删掉并重做有问题的段落（`rm seg-NN.wav` 触发增量合成）。全篇重跑不仅浪费机器时间，还会导致各段音频时长发生不可控的微小漂移。
**换音色也是增量感知**（2026-08-16 起）：manifest 记录 engine/model/ref_audio 与读音表指纹，
config 变了旧 wav 不复用、自动重做对应段——此前只比对稿件文本，换音色后忘带
`--force` 会出一期混两种音色的成片且零警告。若仅修改个别生僻字读音，应同步更新 manifest 指纹并仅删除目标段落，保持其余段落复用。

> **回读比对前会先归一化，而归一化可能把缺陷一起抹掉。**
> 有一次 TTS 把中文引号念成了字（「谁更该"赢"」→「谁更该非赢匪」），
> 回读判 **PASS**——因为参考文本被归一化剥掉了引号，多念出来的两个字只算两处插入，
> CER 7% 远在门槛下。修法是合成前用 `tts.speakable` 剥掉纯书面符号，
> 逗号句号破折号一律保留（它们控制停顿）。
>
> 这一例是**靠耳朵听出来的**，没有任何机器检查报警。所以：
> **成片交人之前至少听一遍开头和最长的那一段。**

产物 `03-audio/seg-NN.wav` + `manifest.json`。

### 03.5 配音顺听与单段重跑 · **人约 2–3 分钟**（2026-08-20 加）

**自回归多语种 TTS（如 Qwen3-TTS）的稳定性不如单语种模型。** Whisper 回读只能卡住
「漏读、重复、跑飞」等字面错误，**听不出电音、语调诡异、近音滑腔、吞字和情绪突变**。
如果在第 05 或 06 步才发现配音不好听要重跑，重跑后音频时长必定微调变动，
会导致 04 排片与切片全部推翻重来。**先顺听把音频定死，后续才能一路畅通。**

**核心原则：绝对优先单段增量重跑，严禁无差别推翻全篇。** 只有出问题的段落需要重新合成，
其余合格段落必须保留复用。

#### 1. 快速顺听（无需第三方工具，Agent 自动调用）

跑完 03 后，Agent 自动在终端执行顺序连播给人类顺听（macOS 原生 `afplay`）：

```bash
for f in data/episodes/<本期>/03-audio/seg-*.wav; do
  echo "▶ 正在播放: $(basename "$f")"
  afplay "$f"
done
```

#### 2. 单段快速重跑（增量重跑，不浪费其他段）

`pipeline.tts` 原生支持跳过已有合格音频。如果听出第 N 段有问题（比如 `seg-04` 语气怪）：

```bash
# 1. 删掉有问题的单段音频
rm data/episodes/<本期>/03-audio/seg-04.wav

# 2. 重新执行 tts（会自动跳过其他合格段落，只重跑并复核缺失段）
python -m pipeline.tts data/episodes/<本期>
```

人工顺听确认全部段落自然、无明显电音与吞字后，再进入第 04 步。

### 04 素材检索 · Agent 约 1 分钟

```bash
python -m pipeline.clips data/episodes/<本期>
```

每段的 `查询` 送进 `subindex.search` 取 Top-24，然后**全局贪心分派**：
把所有 (段, 画面, 分数) 三元组摊平按分数降序占坑，同一处画面整期只用一次。
不按段落顺序分——那是先到先得，会让后面真正引用某句台词的段落抢不到那句话的画面。

每段按**音频真实时长**（manifest，不是字数估算）填满，单个片段 ≥ 2.5s（太碎会闪）。

> **字数估算与实际语速的偏差每段几百毫秒，二十段攒下来就是几秒**，
> 而且是渐进错位，越到后面画面与口播差得越远，**全程不报错**。
> 这是「顺序不可交换」的全部理由。

**分镜可以声明走哪个通道**（ADR-0008 / ADR-0003）：

| 分镜写法 | 通道 | 排序依据 |
|---|---|---|
| `锚点: S01E01 17:50[-18:20]` | **剧情锚点直通**（一等公民，ADR-0008）：起点吸附含锚点的镜头切点，不检索 | 无分数——确定性时间码 |
| `锚点: 无（理由）` + `查询` | 台词检索（氛围补位） | 台词分数，门槛 0.45 |
| `人物: 雪乃` | 台词检索 + **角色在场过滤**（过滤为空则退回不过滤的结果） | 台词分数，门槛 0.45 |
| `场景: 黄昏的天台空镜` | **画面语义检索**，不看台词 | ✗ **当前不可用**：探针没过，写了会当场报错（见下） |

**锚点优先于一切检索**（2026-08-27，ADR-0008，已实现）：02 写稿时料单与引用核对
已经锁定分钟级剧情时间码，排片把它们直通镜头表；双塔检索只服务 `锚点: 无` 的氛围段。
锚点段不占检索配额，且先于检索段占位——检索段的同一处画面判定自然绕着它们走。
两段锚点撞车不自动挪，标 `anchor_overlap` 交 05 处理。

**一段只走一个通道**：不并跑、不取最高、不加权，两个都写当场报错。
台词的 0.7 和画面的 0.7 不是同一个量，长得像纯属巧合。
分派画面时的跨段冲突也不比分数，按**显式的通道优先级**解：台词段先挑，
理由是它们要的是「那句话发生的那一刻」，具体且不可替换。

`人物` 修的是一类具体错配：台词检索命中的是「谁说了这句话」，
而镜头往往就在**说话人**身上——某段配音原文是一个人名，检索拿到 0.750 高分，
可那个镜头拍的是喊这个名字的人。

单段落空时走**查询阶梯**：`查询` → `备选` → 该段 `配音` 原文，逐级重试，
门槛 `0.45` 全程不动——**加大的是找的力度，不是放低的标准**。
画面通道爬自己的两级（`场景` → `备选`），**不许因为画面通道不及格就改走台词通道**，
那等于用换通道来降标准。

**阶梯只救不比。** 上一级够格就到此为止，绝不因为下一级分数更高而换掉。
实测 21 段里配音原文在 11 段上分数最高，但取它会把已经对的段落弄坏：
一段的查询是逐字引语（0.855），换成配音原文（0.559）会换来一个不相干的镜头。

> **分数高不等于画面对。** 分数量的是「旁白文本与字幕文本的语义相似度」，
> 而我们要的是「这个镜头是否呈现旁白在讲的那一刻」。两者只在查询写成台词语义时才重合。
> 有一段配音全文就是一个人名，配音原文拿到 0.750 高分——因为剧里有人喊了这个名字，
> **而那个镜头拍的是喊话的人，不是她**。
>
> 同一条教训在这个项目里出现过四次：**一个量能用来卡门槛，不代表它能用来排序。** 见 [S2](STANDARD.md#S2)。

产物 `04-clips.json`。

### 05 审时间码 · **人 5 分钟**

**这是整条流水线里唯一「不过就不能往下走」的强制人工关卡**（02.5 是建议性的改稿关口，
跳过也能技术上继续跑；05 卡的是 `--approve` 这个显式动作，不点就渲不了）。

```bash
python -m pipeline.review data/episodes/<本期>          # 出 04-review.html
open data/episodes/<本期>/04-review.html
python -m pipeline.review data/episodes/<本期> --approve
```

一页 HTML，每段并排三样：**这段口播在说什么 · 画面长什么样 · 那一刻字幕原文是什么**。
每个片段抽三帧（进点 / 中间 / 出点）——只看中间帧会漏掉「前半段是对的人、
后半段镜头切走了」，而那正是要抓的错。`no_match` 的段落标红顶到眼前。

要抓的是**台词对了但画面不对**：索引建在字幕上，命中的是「谁说了什么」，
但那句话可能是画外音，镜头在拍别的。机器判不了，只有眼睛能抓。

不对就报段号，改排片重出。

`no_match` 的段落**渲染会硬失败，不自动降级**。那一步的判断只有人能做：
这一段留白合不合适、换哪段素材顶上、还是干脆改稿。机器自动塞一段空镜看着省事，
实际是把「画文不符」藏起来。**留白远优于画文不符。**

> **落空的绝大多数原因是查询写错了，不是素材不够。** 先回去看那条 `查询`
> 是不是在向字幕索引要画面构图。实测：片尾查询写成「角色转身走出教室」落空，
> 改成台词式「时间差不多了 我该走了」后 0.446 → 0.747。

产物 `04-clips.approved.json`。**`--approve` 必须是显式动作**——
让 `clips.py` 自动写 approved 是最省事的做法，也正是这一关曾经形同虚设的原因：
有一期两个文件字节完全相同，画面是检索直出、没过人眼就渲了，错配等成片看完才发现。

**05 也是段级不变量的强制关卡（B4）**：人在这一步直接改 `04-clips.json` 的
start/dur 时，机器生成时保证的「Σclip.dur == 配音时长」不会自动重新成立——
`--approve` 会先校验这条不变量，不对齐就拒绝拷贝成 approved 版，`render` 还有
第二道闸防绕过。**改画面只改 start/source，dur 不手改**，改完跑：

```bash
python -m pipeline.clips <本期> --refit
```

把每段 dur 重排到满足不变量，漂移由该段最后一个片段吸收。**警告：人改过之后
重跑 `python -m pipeline.clips <本期>`（不带 `--refit`）会重新检索，覆盖掉人工
修改的排片结果**——`--refit` 只读写 `04-clips.json`，不碰检索，这是它和不带
参数直接重跑的本质区别。`--refit` 改的是人审（`--approve`）之后的产物，
重写前先把原文件备份成 `04-clips.json.prerefit.bak`（单份覆写，不累积）——
写一半崩溃时「人改过什么样」还能从备份找回；确认新版没问题后备份可删。

### 06 渲染 · Agent 约 1.5 分钟（40 片段 / 3 分钟成片实测 77s）

```bash
python -m pipeline.render data/episodes/<本期>
```

按时间码切片 → 统一中间格式 → 拼接 → 混 BGM → 烧字幕 → 响度归一，一趟出片。

**两道截取守卫强制执行，缺一不可：**

1. **切之前**校验 `seek + duration <= 源时长`
2. **切之后**复核实际时长与请求值之差 ≤ 1 帧

> ffmpeg 在片段超出源片末尾时**静默截断且不报错**，检索命中集尾时必然踩到，
> 一旦踩到整条音画全线错位而无任何提示。这是已复现的产线杀手，守卫不能省。
>
> **「1 帧」要按源片实际帧率现算，不许写死。** 番剧片源常见 23.976 / 24 / 29.97 三种，
> 按 30fps 的 0.034s 去卡会把 23.976fps（一帧 0.0417s）的合格切片判成不合格。
> 容差从 `ffprobe` 读到的 `r_frame_rate` 算。

**BGM 一期一到两首，人耳现选**（2026-08-08 起；此前是 Phase 0 锁死一部番的固定曲目）：
配音（03）出来之后人听一遍，把选中的曲名填进这期 `01-topic.md`：

```markdown
BGM正文: Grau
BGM结尾: Schöpfer      # 不填就整期只用正文那一首，不强制两首都选
```

`render.py` 读这两个字段找 `config/bgm.json` 里对应的曲目；没填就退回该番在
`config/bgm.json` 里的 `use` 默认值（多数番这个字段是空的，也就渲不出 BGM，
这是允许的状态，不报错——BGM 缺失不该拦掉渲染，那是「拿不到能证伪的信息时不定罪」
的同一个道理）。曲库本身（`bgm scan`/`extract`/`measure` 攒出来的候选池）还是
Phase 0 建一次，变的只是「选哪首」这个判断从机器挪回了人。

正文垫劇伴，最后 15–20 秒换 OP/ED 伴奏，等功率交叉 3 秒。
换曲点卡段落边界，不卡固定秒数。每首按 `config/bgm.json` 里的**实测响度**归一到
-26 LUFS 再送侧链闪避。

> **固定音量系数是错的控制量。** 实测劇伴 -14.4…-18.1 LUFS，OP/ED 单曲伴奏
> -7.1…-13.2 LUFS，**极差 11 dB**——单曲是按打榜标准压过的，原声碟不是。
> 初版那个 `volume=0.35` 是对着 -16.9 那首调出来的，换一首 BGM 会凭空大 9.8 dB
> 直接压过口播，**而且不报错**，只会某一期突然特别吵。
> 所以曲目表里没有 `lufs` 的曲子直接拒绝使用。

产物 `05-final.mp4`。

### 07 质检 · 机器约 40 秒（11 项，不过非零退出）

```bash
python -m pipeline.qc data/episodes/<本期>
```

- 成片时长落在目标带（默认 2–4 分钟，`01-topic.md` 写了 `时长目标` 就按那个带判）
- 音画时长误差 < 0.5s；成片与排片一致
- 响度 EBU R128 目标 −16 LUFS；无 true peak > −1 dBTP
- 无 > 0.5s 纯黑；无 > 2s 静音段
- 字幕：无空段、不超宽、每卡一行、不超高

> **字幕那四项查的是实际折行结果，不是「原文长度 ÷ 每行容量」。**
> 初版就是后者，等于假设折行一定会发生；而 **libass 对无空格的中文根本不折行**，
> 于是 91 字的一段渲成一整行、两头切出画面，这条检查照样判 PASS。
> **检查项一旦测的不是真实产物，通过就毫无意义。**

产物 `06-check.log`。

### 08 封面与标题 · Agent 约 1 分钟（几百帧 → 9 张，约 65s）

```bash
python -m pipeline.cover data/episodes/<本期>                   # 出池子 + 联系表
python -m pipeline.cover data/episodes/<本期> --pick 107,110,20  # 定 9 张
open data/episodes/<本期>/07-cover/index.html
```

**这一步不新增人工环节**，选封面和选标题并进第 09 步，点一张图、点一条标题合计半分钟。

#### 封面：机器把几百帧筛到 9 张，不负责挑那一张

「富有张力、吸引眼球」是审美判断，机器判不了，**不要假装能判**。

候选帧从三处取：

1. `04-clips.approved.json` 里实际用上的片段——每 0.5 秒抽一帧
2. 番剧笔记里本期锚点对应的名场面时间码——**agent 从台词索引检索、人扫过一眼确认**的时刻
3. **`01-topic.md` 的 `封面集` 通篇每 12 秒抽一帧**，跳过 OP/ED

> **第 3 路是被打脸打出来的。** 初版只有前两路，理由写在代码里：「只用片中出现过的
> 画面，否则是标题党」。结果九张候选里**没有一张主角占主位**——三张背影侧脸，
> 六张根本没有他，而这一期从头到尾讲的就是他。
>
> 根因是**池子本身系统性地偏**：前两路的帧都来自字幕检索命中的时刻，
> 而稿子引用的台词大多是**别人说给主角听的**，镜头自然在说话人身上。
> 筛选救不了这个——池子里就没有想要的东西。
>
> 「否则是标题党」这条也用过头了：给一期讲主角的视频配主角的正脸是名副其实，
> 真正算标题党的是拿一场不相干的戏去暗示别的内容。
>
> 所以 `封面集` 与 `锚点` 是**两个字段**：封面池不必局限于稿子引用过的集。
>
> **2026-08-03 补上了真正的解法**：视觉索引建好之后，
> `01-topic.md` 写 `封面人物: 一色彩羽`（或 `--character`）即可让候选池只留
> 检测到这个人的帧。上面那个「九张里没有一张主角」的偏置就是它修的。

机器只做四件事，逐条都有明确判据：

| 做什么 | 判据 |
|---|---|
| 剔掉转场帧、运动模糊 | 拉普拉斯方差 < 60——没有清晰边缘 |
| 剔掉黑场、过曝 | 平均亮度落在 40–215 之外 |
| （可选）剔掉没有本期主角的帧 | 视觉索引的角色在场判定，**硬过滤，为空则失败** |
| **同一个镜头只留一张** | 同集内相隔 < 6 秒 = 同一镜头；另加 dHash 抓不同时刻复现的同一画面 |
| 按位置铺开取样 | 2 个坑留给名场面，其余按段落号均分，每档取最清晰的一张 |

> **去重是最要紧的一道。** 按 0.5 秒抽帧，一个 4 秒的镜头出 8 张几乎一样的图。
> 初版只用感知哈希，结果九个候选里四个是同一场戏几秒之内的四张。
> **dHash 对「同镜头内角色微动」不敏感**——人物挪一点、口型变一下就能差出十几位；
> 放宽阈值又会误合并真正不同的镜头。镜头是时间上的连续区间，按时间判才对。

#### 候选之间没有排名，这是刻意的

试过两版打分，**两版都把正确答案压掉了**：

| 打分 | 结果 |
|---|---|
| 清晰度<sup>0.5</sup> × (0.5+饱和度) | 把一场关键对视压到第 5——它背景是淡色的 |
| 纯清晰度 | 选出运动服店的货架、图书室的书架，**主角一个都没有** |

第二版暴露了根因：**拉普拉斯方差测的是「画面里有多少细节」，不是「画面有多好」。**
杂乱背景细节最多，按它排等于专挑最杂乱的画面，与封面要的「主体突出」正好相反。
**清晰度是准入门槛，不是排序依据，两者不能混用。**

换掉它的不是更好的打分函数——饱和度、中心细节、对比度都是自己发明的判据，
没有数据支撑。正确做法是取一份有代表性的样本交给人判。

#### 分工是三层，不是两层

「谁在画面上、占不占主位」是**认人**，机器判不了（标准人脸模型对二次元无效，
要专门的 anime cascade），但 **agent 能看图**：

| 层 | 谁 | 做什么 | 判据 |
|---|---|---|---|
| 1 | 机器 | 剔黑场/过曝/糊帧、去重、编号 | 有明确阈值 |
| 2 | **agent** | 看联系表，挑出符合本期主题的（谁在画面上、占不占主位） | 认人 + 读内容 |
| 3 | 人 | 从 9 张里定一张 | 审美 |

第 2 层的接口是**联系表**——`sheet-*.jpg`，6×5 一张、带编号，一张顶 30 次单张读取，
纯粹为省 token。agent 看完报编号给 `--pick`。

不加 `--pick` 时退到机械铺开取样，仍然出得了 9 张——**agent 不在场时流程不断**，
只是选出来的不一定切题（空镜会混进候选，人自己跳过）。

规格用 1920×1080 原帧，各平台自己会裁。

> `07-titles.md` **已填表就不再覆盖**。封面常要重跑几次调取样，
> 而标题和封面在同一个命令里出——曾经这么把写好的标题冲掉过一次。

#### 标题：5 条候选，路子写明

**金句式，不要论文式。** 判据是**这句话能不能脱离视频单独发出去**。
播放最高的那条是一句能单独成立的判断；垫底的那条是一串并列名词加副标题，像论文题。
（自己账号的实例见 `CLAUDE.local.md`。）

标题的原料是稿件的**第 2 节（亮判断）与第 8 节（结论）**——
那两句本来就是全篇最锋利的判断，不用另起炉灶。

5 条而不是 3 条，每条注明走的是哪个路子（下判断 / 反问 / 复述再打 / 剧情钩子 / 金句），
好让人横向比而不是逐条读。同时给简介一段与标签若干。

**人类合计 ≈ 13–15 分钟**，机器约 7 分钟（可后台跑）。2026-08-05 加了 02.5 之后
**已经超过 CLAUDE.md 那条「每期人类投入 ≤ 10 分钟」的止损线**——这一条要么把 02.5
的实测耗时降下来（比如只审不改的情况应该远低于 5 分钟），要么正式承认止损线要改。
先跑几期实测，不要凭这里的估计数字下结论。

> **这个 9.5 分钟至今没有端到端验过。** 第一期是边搭边做的，第二期在 04 步之前
> 就花掉远超预算的人工（拆题、改稿、核对说话人）——那部分花在选题反复上，
> 不是流水线的问题，但账还是没验成。选题一次定死的那期跑完再回来改这张表。

连续 3 期人类耗时超预算 → **停止产出，回头修流水线**。
超预算是系统缺陷，不是加班的理由。

## 已知局限 · 待做

### 画面语义通道（第 2 层）探针没过，**已决定不建**（2026-08-04）

第 1 层（画面里有谁）2026-08-03 已建成。**第 2 层（画面是什么，Chinese-CLIP）
探针跑完了，结论是不建**，完整证据见 ADR-0003「待实测」第 4 条。

检索本身不差（10 条查询里 7 条 Top-3 有真命中），**但门槛立不住**——
三种定法全试过全失败，根因是 CLIP 的余弦没有绝对含义：它能在一条查询内部排高低，
答不了「这算不算命中」。最扎眼的一个数：反例「太空中的宇宙飞船」
在 CLIP 原生 softmax 下拿到 P=0.896，高过「学校走廊」的 0.689。

**这不是「效果不够好」，是判据不成立。** 门槛定低则不相干的镜头判及格、
成片画文不符且不报错，而本文写死了「留白远优于画文不符」。

所以：`场景` 字段会因为缺 `no_match` 而当场报错，**这是终态不是过渡态**；
氛围段落继续留给人在第 05 步处理。`vindex status` 把画面语义报成「未启用」而不计入对账——
一道永远失败的门禁，人会学会忽略它。

代码与探针全部保留：换动漫域的图文模型、或改由第 3 层 VLM 判断，都要重新过探针，
**不许「先上了再看效果」**。
