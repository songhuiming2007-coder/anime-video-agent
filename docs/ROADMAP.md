# ROADMAP：开发规划展望

日期：2026-07-30
状态：**展望，不是承诺**

## 这份文档管什么

三份规划类文档的分工，别放错地方：

| 文档 | 记什么 |
|---|---|
| `CLAUDE.md` | 工程约定。任何人拿这个仓库都适用的规则 |
| `docs/adr/` | 难以回头的**单个决策**，以及它的证据 |
| **本文件** | **顺序和闸门**：先做什么、什么条件下才允许做下一件 |

**这里写的是顺序，不是承诺的时间。** 没有任何一个阶段带日期，因为这是每周几小时的
实验项目，排期只会变成谎。真正约束进度的是闸门，不是日历。

### 阶段 1：Windows 上跑通九步

**做什么**

- 把 ASR 从 mlx 上解绑成可替换后端（`asr.py` 只有两个对外函数，三个调用点）
- TTS 同理。IndexTTS-1.5 上游本来就是 PyTorch，`mlx-audio` 只是移植
- 修掉冒出来的平台假设（字体已经是配置项，`preflight.sh` 是 bash）
- 三平台 CI + 共享 fixture，见下

**完成判据**

> 协作者在 Windows 上，用他自己的素材跑完九步，**11 项质检全过，出一条能发的片。**

不用解释、没有争论空间，和现有门禁同一套标准。

**为什么排第一**

不只是让人上手。**它同时是阶段 4 的地基**：现在 ASR 只是「无字幕时的兜底」，
因为动漫片源都带内封 ASS 字幕；换成影视、游戏、纪录片，大部分素材没有可用字幕，
**ASR 从兜底变成主路径**。同一块工作，这里是移植，那里是必需品。

而且不先证明第二台机器能跑，后面所有泛化都是空谈。

**配套：怎么保证「几乎同样」不漂移**

「几乎」是分叉的入口。两个机制：

1. **三平台 CI —— 已建**（`.github/workflows/test.yml`）。每次 push 与 PR 在
   ubuntu / macos / windows 上跑纯函数测试。**每次 push 就有一台 Windows，不用买。**
   边界：runner 没有 CUDA / MPS，模型推理与端到端出片验不了；A 层全覆盖，
   含「依赖能否全新装上」——`numpy<2.5` 那个坑正是这个形状
2. **共享 fixture —— 待建**。片源不外传，计划用可合法共享的公开素材做对齐基准
   （Blender 开源电影，CC-BY；*Sintel* 有稳定主角、有官方多语字幕，两层索引都能测），
   仓库只提交 URL + 校验和 + 参数 + 期望输出。**比什么、期望输出长什么样，
   要等视觉索引有雏形才定得下来，所以在本阶段边做边定。**

在 fixture 建起来之前，只有 A 层的对齐是机器保的，B / C 层靠人对数字——
这是当前状态，不是终点。

### 阶段 2：API 接入

**做什么**

把 coding agent 现在干的三件事——写稿、写检索查询、写标题——改成直接调 API。

这不是新设计，是把 CLAUDE.md「文案由 Agent 全权生成」那节已经预留的 seam 实现掉：
`config/script-mode = auto | from-core`，原文写着「`from-core` 模式的接口先预留、不实现」。

**完成判据**

- 不装 coding agent 也能跑完九步
- **同一选题跑两次，稿件可复现**（固定模型、固定 prompt）

**为什么提前到这里，而不是放到最后**

三个理由，任一条都够：

1. **它解协作者的依赖。** README 写着「coding agent 是前置要求，不是可选项」。
   写稿和排片查询都要它，他那条 Windows 流水线不自包含
2. **写稿第一次变得可回归测试。** 现在同一个选题两次跑出来的稿不一样，
   没法写测试，也没法判断改了 prompt 之后是变好还是变坏
3. **它是同一个模式的第三次。** ASR 后端、TTS 后端、写稿后端——
   三处都是「把平台或供应商的绑定藏到接口后面」。三次用同一套做法，
   这本身就是一条能讲清楚的架构叙事

### 阶段 3：视觉索引

设计已定，见 [ADR-0003](adr/0003-visual-index-as-filter.md)。这里只记顺序相关的事。

**做什么**：第 1 层（画面里有谁）+ 第 2 层（画面是什么）。第 3 层的启动条件在 ADR 里。

**分工：探针共享，实现分头。**

实现可以两边各写——ADR 已经把设计定死了，两人是在实现规格而不是在设计。
**但探针不行。** WD-Tagger 准确率、CLIP 在动漫上的命中率、相似人设可分性，
这些产出的是**判据**。同一个探针在两台机器、两套素材上跑会得到两个数，
而且没法判断哪个对。**判据只能被发现一次。**

做法：探针一人跑，两人一起看结论，结果写回 ADR-0003 的「待实测」那节。

**完成判据**：封面候选含主角的比例、排片错配率，两项都要有可测的改善。
具体数字待第一次探针之后定——现在写死是编的。

### ══ 闸门 A：把 ≤10 分钟的账结掉 ══

**在动泛化之前，连续跑够 3–5 期，每期由 agent 在会话内掐表记录人类耗时。**

理由不是拖时间。「动漫领域到这基本就到头了」这句话里，**到头的是流水线，不是素材**——
选题池还有 7 个题，春物那几小时 Phase 0 投入还没摊薄。如果视觉索引一完就转去泛化，
会同时发生三件事：

- Phase 0 投入白花
- 项目的核心主张（人类每期 ≤10 分钟）**从未被验证过**
- CLAUDE.md 那条止损线（连续 3 期超预算 → 停产修流水线）**没有数据可以触发**，
  等于形同虚设

一条「能泛化但没人知道它省不省时间」的流水线，泛化了也不知道泛化的是什么。

**闸门开启条件**：3–5 期实际耗时已记录，且结论明确——达标，或不达标且知道卡在哪一步。

### 阶段 5：`ava run` 单命令编排

**这件事比看起来小。** `pyproject.toml` 的 `[project.scripts]` 已经有十个入口
（`ava-ingest` … `ava-bgm`），缺的只是把九步串起来。而因为状态模型是
「产物即状态，看目录里有哪些文件就知道跑到哪一步」，串联就是一个跳过已完成步骤的循环。

**不是编排框架，是一百来行。** 随时可以插进任何阶段之间，不占关键路径。

### 阶段 6：GUI

**这是唯一一件性质不同的事**，两个问题不回答就不要动手。

**一、给谁用？**

给自己用的话，第 05 步已经有 `review.py` 生成的缩略图 + 单页 HTML，那本来就是界面，够用。
给不写代码的人用，项目性质就从「我跑的流水线」变成「别人装的软件」：
打包、安装器、跨平台、报错要说人话、有人来问问题。每一项都不难，加起来是无底洞。

**二、审阅型还是编辑型？**

CLAUDE.md 有一条硬的：「不要往流程里加回任何需要人工操作 GUI 的环节」。
那条针对的是剪映那种**编辑型** GUI，不是 `review.py` 那种**审阅型**页面。

- 九步的外壳 + 现有审阅页 → 不违反
- 能拖时间轴、调画面 → 正面撞上，且人类时间预算会被吃掉

**这条边界现在就定死，不要等做的时候凭感觉。**

## 这份规划建立在哪些未验证的假设上

写出来是为了将来推翻时知道推翻的是什么：

1. **人类每期 ≤10 分钟可达。** 闸门 B 就是验这个
2. **解说视频的骨架通用**，因垂类而异的只有「素材怎么被检索、稿子怎么算合格、
   成片怎么算能发」三件事（HELP.md 的核心假设，未验证）
3. **视觉索引能修掉封面和排片的错配。** ADR-0003 的前提。**封面已验证**
   （`cover --character 雪乃` 9/9 含她，基线 0/9）；排片错配率待一期真用上 `人物` 的稿子
4. ~~**CLIP 系模型在动漫帧上可用。**~~ **已证伪**（2026-08-04）：探针跑完，
   检索能排序但**门槛立不住**，第 2 层不建。域偏移这个风险点押中了。
   证据见 ADR-0003 待实测 #4
5. **两人平行开发不会分叉。** 靠 CI + 共享 fixture 兜，机制未建

## 什么会让这份规划作废

- **连续 3 期超 10 分钟** → 停止产出，回头修流水线（CLAUDE.md 硬约束）。
  规划让位，闸门 B 变成停止线
- **协作者退出** → 阶段 1 的 Windows 侧无人维护。届时决定：CI 保住 A 层不退化，
  或整块标记为不支持。**不要留一个没人跑的半吊子平台分支假装它还活着**
- **主线（转码 / 找实习）需要时间** → 本项目优先级低于它，这是写在
  `CLAUDE.local.md` 里的。停就停，提前说一声

> 建设期止损线（3 周、每周 ≤6 小时、到期未跑通端到端）**已经满足**——
> 两期成片跑通，止损条件解除。现在唯一活着的止损线是上面那条 10 分钟。
