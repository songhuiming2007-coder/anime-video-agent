# 写稿

产出一篇口播稿与逐段分镜标注。口播稿是**念出来**的，不是给人读的——写完出声念一遍，这是最终判据。

字数带：`01-topic.md` 写了 `时长目标` 就按它换算（分钟 × `script.cpm`），没写就是默认
870–1300 字；真没料就写 `缩段不注水: 是`，下限打 8 折（上界不动，不许凑数注水）。
**默认带是短打杂谈类的实测数据，人物志/剧情回顾/共鸣天然要更多篇幅，必须写 `时长目标`。**

## 元规矩

**一、这份文件管防差不管造好**——结构是否前置取决于题材：人物志 / 剧情回顾可以使用
01.5，杂谈 / 盘点 / 共鸣不创建 beats，这里剩下的是语言判断，好靠自己琢磨。
**二、题材决定骨架**（第 4 节），没写「类型」先定。
**三、判据和机检同时改**——数字和文字打架数字赢，动判据同步动 `config/project.json`
（对照数据见 [BASELINE.md](BASELINE.md)）。
**四、这份文件里有三类内容，分量不同**：
- **机器约束**：`check_script` 真正在卡的项（段落数、句长、气口、锚点格式、音乐段语法、纪录片物证表）。以机检输出为准，本文件只说明它们为什么存在。
- **事实纪律**：不编造、事实有出处（第 1、2 节，第 9 节第一遍）。这是硬的，但靠查证和工具执行，不靠措辞加重。
- **文风**：怎么讲、什么语气、什么节奏。这里只给原则，具体怎么写由写稿的人判断。

**本文件的语气不是示范。** 稿子的语体每期按 `01-topic.md` 的 `语体:`（可选）与人的要求定——荒诞期就写得荒诞，散文诗期就写成散文诗。照第 3 节「声音锚点」去贴近过审终稿，不要照这份说明书的口吻说话。

| 同目录 | 什么时候读 |
|---|---|
| `SKILL.local.md` | **若本地存在，必读**。只写本机的补充（私有题材与本机约定）；与本文件冲突处以它为准 |
| `VOICE.local.md` | **动笔前必读**，不存在时读空模板 `VOICE.md` 并提示用户去填 |
| [SHOTLIST.md](SHOTLIST.md) | 标分镜时，`查询` 是机器接口不是备注 |
| [BASELINE.md](BASELINE.md) | 要改节奏阈值时 |

机器上还装了通用写作 skill `human-writing`，冲突时以本文件为准，理由见文末。

## 0. 先定这一期的题材

读 `01-topic.md` 的「类型」。没有就停下来报告，退回选题。

通用六种（不是穷尽——更多个性化题材与骨架可以写进 `SKILL.local.md`）：

| 题材 | 一句话本质 | 张力在哪 | 结尾 |
|---|---|---|---|
| 人物志 | 一个人的一生 | 他真实的经历与人性，不编论点 | 平实收尾，可预告下期 |
| 剧情回顾 | 把一条线讲清楚 | 故事本身的转折与代价 | 回环落点，或一句判断，或悬念 |
| 杂谈 | 对一部作品发表观点 | 驳论=通行说法vs事实；立论=被低估/说不通的地方；吐槽=无 | 驳论落具体东西；立论一个判断不装权威；吐槽一句自嘲 |
| 盘点 | 按一条标准过几个对象 | 标准本身 | 回环，或升华，或退场 |
| 共鸣 | 把戳人的故事讲出来 | 角色真实经历里让人心疼的东西 | 回收意象，或台词收束，或行为细节 |
| 纪录片 | 现实中的人和事 | 物证与解读（事实落在物证上，解读交给意象） | 片尾长镜头余韵，或对结局的平实交代 |

按题材跳到第 4 节对应小节，把骨架和范本看一遍，然后回来走第 1–3 步。

## 1. 先把剧情查准

**开写前逐段读 `data/library/notes/<番>.md`（写厚版笔记，含分集剧情 + 来源行），
这是剧情事实的唯一主源**，不凭记忆、不靠 prompt 里带的梗概。读不到笔记就停下报告。

正文里要落的每条剧情断言核对来源（字幕/画面回 `.ass` 或抽帧确认；网上的回原帖）。
**笔记标「未经证实」的断言不许当承重材料**——换一条有来源的，或标「待 02.5 确认」。
「某某说」之前必须抽帧确认说话人——字幕 `Name` 字段字幕组基本不填，光靠检索定位
只知道时间点，说话人得看画面：

```bash
python -m pipeline.subindex search "别再那样自我牺牲了" -k 3   # 定位在哪一集第几秒
ffmpeg -ss <秒> -i <该集 mkv> -frames:v 1 -vf scale=480:-1 /tmp/who.jpg   # 抽帧看谁在说
```

画面和稿子不一致时，先怀疑稿子。

企划 / 纪录片期讲的是现实里的事（采访、发售、榜单、成员变动）：这些事实用 `fact_add` 记进事实库（D99），
稿里写到的现实事实都要能在事实库里找到；找不到出处的不写，或标「待核」交人。

## 2. 事实入脑，不搞形式料单

**开写前吃透写厚笔记与真实台词。** 明确本期承重的 3–5 个核心剧情转折或具象细节（如某句关键台词、某次对峙动作、具体的生活窘境）。
不要求在稿件头部填形式化的「承重料 / 非承重料清单」——事实与细节在行文里自然交待，不为了凑「非承重配额」而生硬报菜名。

## 3. 声音锚点

**动笔前读上一期过审终稿**（上一期目录的 `02-script.md`，不是 `.draft` 版）。
不为避雷同——是为了贴近
这个账号已经过关的声音：**上一期的稿子是被用户改到能用的。像它那样说话，别像
这份文件说话。** 想清楚谁在说、为什么现在说、手里有什么能托住这篇（答案不进稿件）。

## 4. 各题材骨架

> 骨架从**真实优秀文本**拆出来，不是必须照抄的分步模板，只在形状和题材严重不匹配时回来对照原文。

### 4.1 人物志
**范本：`reference.md` 真实文案（罗十五，两期董香）。** 一个人的一生，讲经历
不证明论点。从第一印象或时间线起点入手；**按经历顺序讲，讲完一段贴着一幕评
一段**，点评不服务全篇统一判断；挣扎写实——具体动作+具体数字比抒情概括更让
人信；段落不追求每段收口；**没有模式、没有张力字段**，不为「有观点」硬造
论点再回头挑经历，张力来自真实经历与人性，找不到不硬找；结尾平实，可预告下期。
- **经历之间因果咬合**（2026-10-08 补，D48）：每段的事件要么由上一段直接引出，要么开头一句交代起因；
  推动主角经历的常是别人的行动，交代那个人的动机，一句即可（谁为什么来、为什么动手、为什么出现在这里）。
  按经历顺序讲不等于把经历并排——董香二期 22 段里有 6 段被人指出「不知道为什么」，全是这一条。

### 4.2 剧情回顾
**范本：bangumi《命运石之门0》第8集跳线原因（blog/352834）、《记忆管理局》
分集回顾（blog/378265）、《来自新世界》日记节选（blog/361133）；口播参照
阿斗归来了。** 把一条故事线（事件/关系/线索，不是整部作品）讲清楚。
- **人物动机推因果**：以故事推动角色，因果相邻咬合（A导致B，B引发C），不用「然后然后」；
- **设定就地解释**：遇到复杂规则一句话说清本质，不留理解断层；
- **自然收拢**：故事讲透、代价点明即自然收束，可落在回环落点、一个判断或悬念，不搞报幕式总结。

### 4.3 杂谈
**范本：bangumi「论反本质的真物」（blog/311213）、「Oregaku 关于春物的杂谈」
（blog/361121）、「洞穴中的人及试图拉他们出洞的人」（blog/315100）。**
先定子型（`模式` 字段）。
- **立论**：讲通作品里被低估、被误解或说不通的地方。证据紧扣原著真实剧情与台词，坦诚标出推测与作品真缺点，给判断不装全知权威；可以从一个被忽视的微观细节直接起笔，不必在第 1 段先立稻草人；
- **驳论**：直击论证过程的核心漏洞（回答「不这样会怎样」），对反方立场有人性理解，不搞扁平脸谱化批判，不为了辩证而在固定段落机械插入「公道话」；
- **吐槽**：不吃张力，喷完点到为止，收在梗或自嘲上，不上价值升华。
三型共通：段落之间是因果递进，不是材料并排。

### 4.4 盘点
**范本：知乎「眯眯眼都是怪物」（zhihu.com/p/357839891）、bangumi「构成我的
九部动画」（blog/369922）、「2024四月新番观感报告」（blog/344226）；口播参照
凉风「阅片无数」。** 按一条标准过几个对象，标准本身就是观点。
- **标准有区分度**：标准要真能把对象分开，并带来认知落差；
- **去模板化**：不按「定性句+荒谬证据+金句」三件套填空；篇幅随素材厚度自然长短，重在每个对象最不可替代的记忆点；
- **落点在观众生活**：论证贴着观众的真实经验与直觉走，不报菜名。

### 4.5 共鸣
**范本：bangumi「你的真心究竟在何处？」（blog/327001）、「致凋亡季节中的你」
CLANNAD（blog/375742）、知乎「哆啦A梦·大雄奶奶」（zhihu.com/question/635431889）；
口播参照凉风「这是一个关于火影的故事」、抖音「意难平/破防」流。** 把戳人的
真实故事讲出来，目的是打动不是分析。
- **拒绝表演情绪**：不生造「先防御后失守」的套路，让角色的具体动作、眼神与处境自己说话；
- **不归纳道理、不点题**：把孤独写出来，别说「他很孤独」；把绝望写出来，别总结「这正如生活」；
- **细节收束**：收在具体动作、未完的台词或象征物上，把叹息留给观众。

### 4.6 纪录片（企划史 / 音乐史 / 行业人物史）
**范本：B站《EGOIST 传奇企划志》、NHK 人物纪录片、BBC 音乐纪实。** 讲现实中的人和事：
先用物证把事实立住，再讲对它的理解；不写成百科年表。

- **物证与解读**：没有物证撑着的抒情站不住，没有解读的物证只是罗列。
- **物证卡片表（机检）**：动笔前先有 `01-hero-shots.md`，列 5–8 组核心物证（H1–H8：关键转折点、
  对应的素材号 `SPxx`、核心画面与事实）。纪录片题材缺这份文件、或全篇 SP 物证锚点少于 3 处，`check_script` 判失败。
- **画面怎么配，看句子承载的是什么**（不给段落贴「报道段 / 抒情段」标签，两种句子常在同一段里）：
  1. 句子讲具体的年份、选拔考题、合同期限、榜单数据、场馆，或描述画面里某个人的具体动作：
     锚到物证（`SPxx mm:ss` 或原番时间码），画面里要真有这个东西，不凭想象写画面；
  2. 句子在解读、留白、讲时代，不报数据、不指某件具体的事：可以不写硬锚点，写意象检索词
     （如 `查询: 昏暗舞台上的孤独投影微光`），交给语义检索（bge-m3）从全池调空舞台、微光、人群这类空镜。
- **缺物证时**：讲到关键事实而素材池里没有对应画面，停下来按 8.5 补，补到了回填锚点再接着写；
  不用无关画面顶替（v1 出过「讲三次元合同放打斗画面」的错配）。8.5 所有题材通用，纪录片在它之上
  多两条机检：物证卡片表在位、全篇 ≥3 处 SP 锚点。

## 5. 语言：念得出来

**写完出声念一遍，这是最终判据。** 底线只有三条——**代词找得到人**（「他」出现
时上一个说出口的人名必须是这个「他」）、**专名第一次说全**（之后固定一种叫法）、
**一段一个数字**（只留必须记住的那个）；其余判据放在第 9 节自检清单，写的时候不必想。

## 6. 直奔核心，宁短勿水

**不要先超写 1.6 倍再删回。** 强制超写只会逼模型注水、反复说同义句。
- **直击矛盾**：围绕本期 3–5 个核心事实与生活冲突展开，不铺垫无关的宏大背景；
- **点到即止**：有话则长，意尽则止；没料就用 `缩段不注水: 是`，不为凑字数注水；
- **精简原则**：写完只删三种东西：复述上一句的解释句、空洞的形容词程度词、假装深刻的概括总结。保留真实的具象细节。

## 7. 不重样

本期开场动作/推进方式/口头禅三项与上期都要换。模型没有跨会话记忆，不主动去读就必然收敛到同一个默认形状——
**雷同不是巧合，是没人回头看过。**

## 8. 标分镜

按视听逻辑把稿子切成若干段，每段配一条明确的画面需求。**动手前读 SHOTLIST.md。**

### 8.1 段落怎么切
- **一个事实配一个画面**：段落是配音切片和排片切刀的单位。一段讲一件事、配一个明确的画面
  （一张物证、一段写实空镜、一个动画镜头）。不要把两件不同时间、不同因果的事放进同一段。
- **段长跟着画面走**：一件事要连着换几个画面（锚点多），就拆成几段短的；一个画面讲得完，就不必硬拆。
- **机检在卡的**（以 `check_script` 输出为准）：段落数 8 到上限（上限 = 时长上界 ÷ 8 秒，不低于 `script.max_segs`；默认带约 37 段，写了 `时长目标` 按目标算）；
  整句不超过 `script.max_sentence`（90）字；逗号之间的气口段不超过 `script.max_breath`（30）字——这才是一口气念不念得完的单位。
- **切段不等于分节**：段落只是排片和配音的桩位。念出来要是一整篇连贯的讲述，后一段接着前一段的因果，
  不要每段开头摆一句小标题式的定性句。

### 8.2 素材类别：别每段都用动画正片
写稿时把所有素材类型都考虑进来：
1. **A 类 · 动漫正片**：剧情还原、人物经历、试听段的高潮画面；
2. **B 类 · 官方 MV 与 NCOP/NCED**：音乐本身的画面；
3. **C 类 · Live 与动捕等现场影像**：舞台上的虚拟形象与幕后真人的对照；
4. **D 类 · 现实档案物证**：官方公告与宣传物、CD 与画集扫图、榜单与报道页面、采访照片，以及街道、车站、录音室这类写实空镜；
5. **E 类 · 外部真实素材（所有题材都能用）**：原理示意图、受力图、数据图表、实物与生活照片、
   设定集 / 画册扫描。正文讲到原片里拍不出来的东西（压强、一公斤有多重、某个数字的对比）时用它，
   和动漫正片平起平坐，不是纪录片专属。怎么补见 8.5。

讲现实史实（发售、榜单、签约、选拔、采访内容）时，用 D 类物证或写实空镜；手上没有就按 8.5 补，不用无关画面顶替。

### 8.3 音乐段与片尾余韵
- **前景音乐试听块（## 音乐段 Mx）**：在全片的关键段落留出原声大音量段，旁白停止，配上对应的画面；试听结束后同一音轨自动下潜 18dB 变为弱音 BGM 托起后续解说（`过渡: 降为 BGM`），或淡出。放几个、每个多长看这一期本身，不套数量（人 2026-10-14）；
- **编排顺序**：普通期的 BGM 在配音之后由人点名，你照写；企划 / 试听型期音乐与文案一起设计：文案有了先定试听段、试看段，再铺满 BGM，之后反复调，怎么排由人主导；
- **试看 / 原声片段（音画同源，ADR-0013）**：想让观众直接看一段原片、听原片自己的声音（名场面对白、Live 现场、
  MV 片段）时用它。画面和声音切自同一源片的同一时间段，旁白停、BGM 静音，片段放完从下一段落接着讲。
  在稿件里**插在哪两个段落之间，成片里就放在哪**：
  ```markdown
  ## 音乐段 M3 · 更衣室试看

  源片原声: `伪恋 S01E07` 17:11.00-17:41.50
  状态: 前景试听，旁白停止
  音画同源: 是
  过渡: 淡出
  画面: 同源
  ```
  - `源片原声:` 写 `` `[番名] SxxEyy` `` 或 `` `<企划> SPxx` ``（反引号必须有），后面是起止时间；
    起止点用 `search_notes`（`source="subs"`）在字幕里定准到台词行，不凭记忆估。
  - `音画同源: 是` 与 `源片原声:` 必须成对；`画面:` 只能写 `同源`；`过渡:` 只认 `淡出`。写错 `check_script` 当场报。
  - **番剧集的试看自动配原片中文字幕**（D86）：渲染从该集字幕索引取窗口内的台词按原时间上屏。
    `check_script` 的「试看字幕」项会列出窗口里有几句；0 句多半是窗口写错，纯画面就写 `原声字幕: 关`。
    截一段 OP / ED 原曲不想要歌词字幕，也写 `原声字幕: 关`。SP 素材（Live / MV）不配字幕。
  - **稿件里一旦有任何 `## 音乐段`，BGM 就只认稿件里的块，01 的 `BGM:` 列表不生效**（D89）。只插一个试看段的期，
    要把 BGM 写成背景铺底块，片头一块、要换曲的地方再一块；试看期间 BGM 自动暂停，放完接着播：
    ```markdown
    ## 音乐段 M0 · 片头铺底

    音乐: `曲名` 完整版 00:00
    状态: 背景铺底
    ```
    漏写时 `check_script` 的「BGM 出处」会判 FAIL，并按 01 的列表给出可以照抄的铺底块。
- **片尾余韵（Epic Outro）**：在文案最后一段写明 `音乐: `曲名` 继续播放至完整版结束`，配音停后音乐不掐断、不淡出，自然播满全曲（留出 1–5 分钟纯音乐）。

### 8.4 通道与分镜语法
不读也别踩的一条：`查询` 匹配的是**台词语义**不是画面构图——索引建在字幕上，
写 `中景，逆光，樱花飘落` 必然检索不到。
**台词是查询/备选的检索素材，不是配音必引内容**——正文引不引由写稿按语体定，不强制；
正文不引台词、查询照写台词，排片照样成立。

```markdown
## 段落 3

配音：他算准了说什么最快能让人讨厌他。

画面：
  锚点: S01E08 21:14                ← 笔记里的剧情时间码，排片直通（ADR-0008）
  查询: 角色承认自己是故意惹人厌的      ← 锚点段可省；无锚点段必填
  备选: 我从一开始就打算这么做
```

每段必写 `锚点`（没有就写 `锚点: 无（理由）`，机检拦留空）——锚点是排片的
一等公民，检索只服务无锚点的氛围段。细则见 SHOTLIST.md「锚点」节。

### 8.5 缺画面就补（所有题材通用）
写到一句话、原片里没有能对上的画面（受力图、数据图、实物对比、生活场景），**不许拿角色镜头硬凑**，
也不许写成「这段先空着」。停下来补：

1. **登记缺口**：`write_episode_file` 写本期 `02-asset-requests.json`（数组，一段一条：`段`、`要什么画面`、
   `原片为何给不了`、`状态`——待找 / 已提议 / 已入池 SPxx / 找不到）。补完回来改状态，人和后面的回合都靠它知道还缺什么。
2. **找图**：按 `skills/acquire-assets/SKILL.md` 搜。`web_fetch` / `crawl` 的返回里有 `images`（页面图片直链），
   拿它写候选（type `scan`），走 `acquire_propose`（登记并核对，返回机器表给人看；人点名后 `acquire fetch`，D100）。**不许自己下载。**
   候选的 `why` 写明「补段 N 的缺口：讲的是什么、原片为什么给不了」，人在提议卡上一眼能判。
   图要原图：短边 <1600 门禁直接拒（放大到 1080p 会糊）。
3. **入池**：先 `acquire gate` 过门禁，再按期的归属选池（2026-10-20 人定，D129）。图片登记时自动转成 12 秒 1080p 缓推视频。
   - **属于企划的卷**：一律 `acquire register <文件> --pool <企划名>` 进企划池，只用一次的图也一样。
     企划各卷讲同一段历史，哪张图后面的卷还会回扣，登记时判断不了；补丁池里的素材只有本期能锚。
     登记完就能写锚点，打标入库可以之后再做。
   - **不属于企划的期**：`acquire register <文件> --to-patch <期目录>` → `ingest_patch --anchor-only`。
     `--anchor-only` 只切镜头、登记，不打标、不开云端，几秒就能用。
4. **写锚点**：企划池写 `锚点: <企划名> SPxx 0:00`；补丁池写 `锚点: <补丁池名> SP01 0:00`，
   补丁池名以 `04-patch/pool.json` 的 `pool` 字段为准，`ingest_patch` 跑完会打印出来。
   一段要连放两三张图，用逗号写多个锚点（蒙太奇，按书写顺序平分时长）：
   `锚点: <池名> SP01 0:00, <池名> SP02 0:00`。
5. **机检**：`check_script` 会核对池里有没有这个号、时间码在不在片长内；补丁池名写错它会告诉你真名。

一段只走一个画面通道：同一段里不要既写图表锚点又写台词 `查询`。想「先图表、再实物、再切回动漫」，
就拆成三段，各配各的画面。

## 9. 自检：两遍回读，分开做

先跑机检 `python -m pipeline.check_script data/episodes/<本期>/02-script.md`。
**机检全过不代表能交。** 分两遍自己过，不要混着做。

### 第一遍：保真

去味改写最容易破坏的就是事实，逐条回原片或笔记复核：

- [ ] 正文引用的台词原文——一个字都不能改，包括语气词（正文没引就不用查）
- [ ] 说话人——每一处「某某说」都抽帧确认过
- [ ] 季/集号、专有名词、人名；数字，以及数字修饰的对象
- [ ] **剧情断言逐条核对笔记的来源行**，「未经证实」的一句都没进正文当承重材料
- [ ] 没有编造的第一人称经历（`data/personal.md` 没有就整步跳过）

### 第二遍：去味

只有第一遍全过了才做：

- [ ] 出声念了一遍没断气、没别扭句，文字有自然的呼吸感，不刻意堆金句
- [ ] 清掉模型腔与商业黑话（「不仅是……更是……」、「这正如我们的人生」、「赋能」、「闭环」、「底层逻辑」）
- [ ] 听众不能往回翻：代词指代清晰、专名首次说全、大白话不掉书袋
- [ ] 哪一块没想通直接说了，全篇一处不打太极；读过上一期过审终稿，开场与切入角度不照搬旧套路

以及内容层面的（按题材取）：

- [ ] 人物志：按经历顺序讲/点评贴着当下一幕/没给角色安生硬论点/每个转折观众都知道为什么发生
- [ ] 剧情回顾：一条主线+因果咬合不是流水账/人物动机讲清了/自然收束
- [ ] 杂谈：立论证据落在具体剧情与台词/驳论针对逻辑漏洞而非扁平扣帽子/不搞机械公道话
- [ ] 盘点：标准有区分度/篇幅随素材自然展开/不报菜名
- [ ] 共鸣：没有归纳空泛道理/用具象动作细节呈现痛感/不强行上价值总结
- [ ] 纪录片：`01-hero-shots.md` 物证表在位，全篇至少 3 处 SP 物证锚点；讲事实的句子都有物证，缺的已按 8.5 补，没有拿别的画面顶替
- [ ] 结尾落对了地方（见第 4 节）

## 和 human-writing 的关系

`human-writing` 面向知乎/公众号长文，不面向口播稿。冲突处**以本文件为准**：
它禁破折号/冒号，这里不禁（破折号是本人特征，冒号是机器接口）；它禁「不是X而是Y」，
这里只限 ≤2 次。值得借的已并进本文件（第 3 节声音锚点、第一稿直接带着人写）。
别拿它的 `check_prose.py` 检 `02-script.md`——稿件机检只有 `pipeline.check_script`。

## 边界

**政治议题不写**（runbook 01.2「政治」行：不进自动管道，自动生成的政论稿过审风险高，走人工通道）。
**写不出来就说**：题材没定、剧情查不实、素材不足以支撑——直接报告卡在哪一步，
不要降低标准硬凑一篇。
