# 声音样本（模板）

**这份文件要你自己填。** 仓库里的这一份是空模板——它定义了写稿 skill 需要哪些栏目，
但里面的样本必须来自**你自己的既有文稿**，否则写出来的稿子是通用 AI 腔。

> 填好的版本放 `VOICE.local.md`（已在 `.gitignore`）。写稿 skill 优先读它，
> 没有才退回本文件。理由很实际：**声音样本必然包含真实经历和个人身份**，
> 那类内容不该进公开仓库，而工程约定该进。

## 怎么提炼

1. **找 5–10 篇自己写的、你自己看着还行的东西**。博客、长评、朋友圈长文、吐槽帖都算。
   越有攻击性、越不像作业的越好——中性文体提炼不出可辨识的声音。
2. **不要总结成形容词。**「犀利」「幽默」「接地气」这类词对 agent 毫无用处，
   它们不可执行。要摘的是**可复制的句式**和**原句**。
3. 每条特征都配一句自己写过的原话。**原话是唯一的锚**；没有原话支撑的特征
   都是你以为自己是那样写的。
4. 最后单独写一节「移植到本题材时改什么」——原文风大概不是为动漫内容写的。

## 必填栏目

### 核心机制（2–4 条）

不是修辞，是**篇章级的动作**：每篇都会做、别人一眼能认出来的那种。三个常见的：

| 机制 | 是什么 | 判据 |
|---|---|---|
| **靶子** | 开场摆出一个流行观点，明确站到它对面 | 靶子必须是读者真听过的说法，不能是稻草人 |
| **公道话** | 在自己立场内部主动加一段对自己不利的具体反例，然后守住原判断 | 「凡事都有两面性」这种空转不算，它没引入新信息 |
| **点名** | 判断后面永远跟具体对象，不说「某些人」「有的作品」 | 随便挑一个判断，后面能不能找到具名对象 |

每条下面贴 1–2 句自己的原话。

### 语言层面（4–8 条）

只写**能照着做的**。示例格式（内容换成你自己的）：

```markdown
**句子长短悬殊。** 长句铺完，接一个四五个字的判断。

> （你自己写过的一句长句）
> （紧跟的那个短判断）
```

值得单独检查的几项：

- **要不要掉书袋**——如果原文里一个学术词都没有，就明确写「不许出现学术词」，
  并给出你平时用什么词替代（这一条最容易被 agent 违反）
- **反问的密度**——数一下自己原文里每千字几个反问句，写下这个数
- **说话的痕迹**——「行」「对，你没听错」这类标记，逐条抄下来，它们让文字有人在场
- **人称**——「我」出现频率、直呼「你」还是「大家」、用不用「咱」
- **破折号 / 括号**——哪个你常用。**括号念不出来**，口播稿里要禁掉

### 抽象落地的方式

抽象词（孤独、成长、异化）后面你习惯怎么落到画面。贴一句自己的原话作范本。

### 移植改动表

| 特征 | 移植 |
|---|---|
| （原文风的某条特征） | **保留** / **去掉**，一句话说明为什么 |

至少要判断这几条：粗口与攻击性、居高临下的指导姿态、平台专属梗——
论战文的姿态搬到内省型内容上通常要换成「并肩的困惑」。

## 别做的两件事

**别写成风格指南。** 「简洁有力、富有感染力」写一百条也没用。这份文件的价值全在原话上。

**别编造经历。** 自我暴露是很强的论据，但只能用真事。编出来的经历因为完全贴合论点，
反而比真话更顺滑、更假——它是最难被发现的假。真实经历放 `data/personal.md`
（不进 git），写稿 skill 第 2 步会去读它，没有就整步跳过。
